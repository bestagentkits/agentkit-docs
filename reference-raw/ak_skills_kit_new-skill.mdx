## ak skills kit new-skill

Add a brand-new skill, authored in a personal kit

### Synopsis

Declares the skill @local/&lt;slug&gt; with alias &lt;slug&gt; in the skills: list of the personal kit local/&lt;kit&gt; and writes its tree to AGENTKIT_HOME/kits/personal/&lt;kit&gt;/skills/&lt;slug&gt;. The skill is a package of the personal kit itself, not a fork: it has no foundation base, a rebase never touches it, and `ak skills improve <slug>` evolves its tree in place. Without --from-dir a minimal SKILL.md is scaffolded; with --from-dir the directory is copied after the same checks as a personal kit tree (no links or special files, the skill tree limits, SKILL.md required) and its SKILL.md name is set to &lt;slug&gt;. A tree that carries a secret or an absolute local path is refused. The slug must be kit ID characters without the reserved ak- prefix and must not collide with an identity or alias the kit already provides. The personal kit must exist (`ak skills kit init`). Nothing is projected: run `ak skills kit apply <kit>` next. SkillX cannot publish such a skill yet (`ak skills kit publish` refuses with kit.local_skill_unsupported).

Effects:
  With --dry-run, read-only. Otherwise, under the kit lifecycle lock and after store recovery, writes AGENTKIT_HOME/kits/personal/&lt;kit&gt;/personal-kit.yaml and the new skill directory in one journaled transaction that requires the skill directory to be absent and the manifest unchanged since it was read. Never projects or applies. Requires the skill store on (after `ak update --ssot`, or AGENTKIT_SKILL_STORE=1 or features.skill_store: true).

Exit status:
  0   success, or nothing to change
  1   command failure, such as a path too long or a recovery that is required
  2   the skill store disabled, invalid flags or arguments, or a malformed manifest or proposal
  4   another AgentKit operation holds the kit lifecycle lock
  5   personal kit, foundation, version, skill or previous revision not found (removing a kit that is not applied changes nothing and exits 0)
  6   review required, stale plan token, rebase conflict, alias collision (including a legacy kit alias), or an unowned or modified path
  7   the new tree carries a secret or an absolute local path (personal_kit.payload_refused), or a link in a target path

```
ak skills kit new-skill <kit> <slug> [flags]
```

### Examples

```
  ak skills kit new-skill mine my-tool
  ak skills kit new-skill mine my-tool --description "Use when ..." --dry-run --json
  ak skills kit new-skill mine my-tool --from-dir ./drafts/my-tool
```
