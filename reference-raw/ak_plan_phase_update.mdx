## ak plan phase update

Create or update a phase record for a plan

### Synopsis

What it does:
  Update the index-owned bookkeeping of phase &lt;n&gt; of plan &lt;plan-id&gt;: notes, evidence, acceptance, and the GitHub comment id. Title, status, and content are owned by the phase file — status via its checkboxes — so they are edited in the file (or via `ak plan check`/`uncheck`) and picked up by `ak plan reindex`, not set here.

Who it's for:
  Both: manual phase bookkeeping and scripted --json automation.

When to use it:
  (unspecified)

Examples:
  ak plan phase update my-project/260722-1200 2 --notes "blocked on review" --json
  ak plan phase update my-project/260722-1200 1 --evidence "benchmarked, see #1120"

What changes on disk:
  Writes the index-owned phase columns (and FTS index) in the local plan store. Never writes phase files.

Output modes:
  pretty   default on TTY (colors, ASCII markers)
  plain    auto when stdout piped or --no-interactive
  json     --json (single-object envelope, NDJSON-safe)

Exit codes:
  0  success
  1  runtime error
  2  invalid flags
  3  user-cancel (SIGINT, prompt-cancel)
  1  plan not found or plan store I/O error
  2  invalid arguments, or a file-owned flag (--title/--status/--content)

```
ak plan phase update <plan-id> <n> [flags]
```
