## ak secrets approvals approve

Allow a pending request from another device

### Synopsis

Allow the pending request &lt;id&gt; (or a unique prefix of it) with a decision signed by this device. Without --ttl the requesting device may release the secret once; with --ttl it may release it for that long (at least 1m, at most what the request accepts, 24h by default). The command refuses to run when an agent is among its parent processes. An id that starts with "-" goes after "--", as in "ak secrets approvals approve -- -r_nM".

Effects:
  Signs one decision with this device's key and sends it to the vault server. The first answer wins; a request already answered, withdrawn or expired is refused with 3.

Exit status:
  0   success
  1   the vault server does not serve remote approvals, or an unexpected failure
  2   invalid invocation, an ambiguous id prefix, or the store moved since enable
  3   no pending request has that id (answered, withdrawn or expired)
  5   local storage failure
  6   this device may not answer (a machine device or a reader), or an agent ran approve
  10  sync is not enabled on this device
  11  the vault server is unavailable or busy; retry
  13  integrity alarm; sync halted
  14  not logged in, or this device was removed

```
ak secrets approvals approve <id> [flags]
```

### Examples

```
  ak secrets approvals approve 3f2a
  ak secrets approvals approve 3f2a --ttl 2h --json
```
