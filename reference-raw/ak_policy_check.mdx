## ak policy check

Ask the policy what it says about one operation

### Synopsis

Answer what the project's policy says about writing one path, running one command, or landing one diff. Every answer carries the rules that produced it and where they came from. A document whose rules disagree is refused rather than resolved by guesswork.

Effects:
  Read-only. Evaluates the policy; changes nothing.

Exit status:
  0   success
  1   the policy document is missing or unreadable
  2   invalid arguments
  3   a rule blocks this operation
  4   the engine refused to answer: the document conflicts or the matching rules disagree

```
ak policy check [-- command args...] [flags]
```

### Examples

```
  ak policy check --path internal/gen/api.pb.go
  ak policy check -- npm install
  ak policy check --changed docs/a.md --changed README.md --ran lint --json
```

### Options

```
      --changed stringArray   Changed path in the diff being landed (repeatable)
      --dir string            Project directory holding .agentkit/policy.yaml (default ".")
  -h, --help                  help for check
      --json                  Emit machine-readable JSON (implies --no-interactive)
      --no-bypass             Ignore AGENTKIT_POLICY_BYPASS, so a rule that would have fired is reported as firing
      --no-interactive        Disable interactive prompts (CI-safe)
      --path string           File path an edit would touch
  -q, --quiet                 Suppress non-error output on stderr
      --ran stringArray       Check the caller has already run (repeatable)
  -V, --verbose               Extra diagnostic output on stderr (loses to --quiet)
  -y, --yes                   Assume yes for all prompts
```
