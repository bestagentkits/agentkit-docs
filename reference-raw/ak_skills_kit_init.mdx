## ak skills kit init

Create a personal kit that extends one kit version

### Synopsis

Creates the personal kit local/&lt;name&gt; under AGENTKIT_HOME/kits/personal/&lt;name&gt; with a personal-kit.yaml that extends exactly one kit version and declares no overlay or fork. The kit version must resolve offline from the kits directory or the cached installed build. An existing directory of that name is refused, whatever it holds; nothing is overwritten. --extends &lt;kit&gt; picks the kit.yaml version the kits directory holds, else the one installed with `ak kit init <kit> --global`; &lt;kit&gt;@installed prefers the installed one; &lt;kit&gt;@&lt;version&gt; pins one exactly. Add overlays and forks by editing the manifest, then preview with `ak skills kit inspect <name>`.

Effects:
  With --dry-run, read-only. Otherwise, under the kit lifecycle lock and after store recovery, writes AGENTKIT_HOME/kits/personal/&lt;name&gt;/personal-kit.yaml in one journaled transaction that requires it to be absent. Never projects or applies. Requires the skill store on (after `ak update --ssot`, or AGENTKIT_SKILL_STORE=1 or features.skill_store: true).

Exit status:
  0   success, or nothing to change
  1   command failure, such as a path too long or a recovery that is required
  2   the skill store disabled, invalid flags or arguments, or a malformed manifest or proposal
  4   another AgentKit operation holds the kit lifecycle lock
  5   personal kit, foundation, version, skill or previous revision not found (removing a kit that is not applied changes nothing and exits 0)
  6   review required, stale plan token, rebase conflict, alias collision (including a legacy kit alias), or an unowned or modified path
  7   revoked foundation, a link in a target path, or a digest mismatch

```
ak skills kit init <name> --extends <kit>[@<version>] [flags]
```

### Examples

```
  ak skills kit init mine --extends engineer --dry-run
  ak skills kit init mine --extends engineer@installed
  ak skills kit init mine --extends engineer@<version> --kits-dir ./kits --json
```

### Options

```
      --dry-run           Print the manifest; write nothing
      --extends string    Kit to extend as <kit>, <kit>@installed or <kit>@<version>
  -h, --help              help for init
      --json              Emit machine-readable JSON (implies --no-interactive)
      --kits-dir string   Foundation kits directory (default: $AGENTKIT_KITS_DIR, else ./kits, else the cached installed build of the extended kit)
      --no-interactive    Disable interactive prompts (CI-safe)
  -q, --quiet             Suppress non-error output on stderr
  -V, --verbose           Extra diagnostic output on stderr (loses to --quiet)
  -y, --yes               Assume yes for all prompts
```
