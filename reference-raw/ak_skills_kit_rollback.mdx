## ak skills kit rollback

Project a personal kit's previous revision again

### Synopsis

Re-activates the previous revision the scope's skill lock records for the personal kit, from the skill store, through the same transaction as apply; it needs no network and no foundation kits. It projects into the running revision's runtimes (plus --runtime). Being offline, it does not re-check whether a foundation version was revoked since; ak doctor reports yanked and revoked releases. The running revision becomes the previous one, so a second rollback returns to it.

Effects:
  Applies without prompting unless the plan needs review; --dry-run prints the plan, its review findings and plan token, and writes nothing. In one journaled transaction under the kit lifecycle lock it writes the composed trees into the skill store under AGENTKIT_HOME, the projected files into each runtime's native skills root (mode 0644, never executable), and the scope's skill lock and receipts, owned by personal:&lt;name&gt;. Never rewrites the personal kit or the foundation kits, and never runs a script. Running sessions may see the new files as soon as the transaction commits. Needs the skill store on (after `ak update --ssot`, or AGENTKIT_SKILL_STORE=1).

Exit status:
  0   success, or nothing to change
  1   command failure, such as a path too long or a recovery that is required
  2   the skill store disabled, invalid flags or arguments, or a malformed manifest or proposal
  4   another AgentKit operation holds the kit lifecycle lock
  5   personal kit, foundation, version, skill or previous revision not found (removing a kit that is not applied changes nothing and exits 0)
  6   review required, stale plan token, rebase conflict, alias collision (including a legacy kit alias), or an unowned or modified path
  7   revoked foundation, a link in a target path, or a digest mismatch

```
ak skills kit rollback <name> [flags]
```

### Examples

```
  ak skills kit rollback mine --dry-run
  ak skills kit rollback mine --scope global --json
```

### Options

```
      --dry-run           Print the plan, its review findings and plan token; write nothing
  -h, --help              help for rollback
      --json              Emit machine-readable JSON (implies --no-interactive)
      --no-interactive    Disable interactive prompts (CI-safe)
  -q, --quiet             Suppress non-error output on stderr
      --runtime strings   Runtimes: claude-code, codex (repeatable; the running revision's runtimes are always included)
      --scope string      Lock and skills root scope: project (default) or global (default "project")
  -V, --verbose           Extra diagnostic output on stderr (loses to --quiet)
  -y, --yes               Assume yes for all prompts
```
