## ak skills kit sync

Project one exact SkillX revision of a personal kit

### Synopsis

Projects exactly the SkillX revision the personal kit's link records (the last publish or sync), or the one --kit, --revision and --digest name. The revision document must hash to the pinned digest, and every skill is rebuilt from its pinned base and overlay and checked against its composition digest, so the same revision projects byte-identical trees on every machine. A newer revision is never followed. Review findings and plan tokens work as in ak skills kit apply. When SkillX is offline and the scope already runs the pinned revision, the sync keeps it with an offline warning and exits 0; otherwise nothing changes. Like apply, a revision that pins a foundation older than the running one is refused (personal_kit.pin_behind); --allow-downgrade replays it with a warning and a review finding (review.foundation_downgrade) that the plan token approves.

Effects:
  Reads the lock and revision document of one exact SkillX revision with the configured SkillX API key, and its bases from the foundation kits directory or, when it lacks them, from SkillX releases (verified, staged in a temporary directory that is removed). Then, like ak skills kit apply, in one journaled transaction under the kit lifecycle lock it writes the composed trees into the skill store, the projected files into each runtime's native skills root (mode 0644, never executable), the scope's skill lock and receipts, owned by personal:&lt;name&gt;, and AGENTKIT_HOME/state/personal-kits/&lt;name&gt;/skillx.json. Never uploads, never follows a newer revision, never rewrites the personal kit, and never runs a script. --dry-run prints the plan and writes nothing. Needs SkillX on (after `ak update --ssot`, or AGENTKIT_SKILLX=1) and the skill store on (after `ak update --ssot`, or AGENTKIT_SKILL_STORE=1).

Exit status:
  0   synced, nothing to change, or SkillX offline while the scope already runs the pinned revision
  1   command failure: SkillX offline, the API key missing, scoped or expired, or a recovery that is required
  2   SkillX, the overlay flag or the skill store disabled, --locked missing, or an invalid pin, flag or argument
  4   another AgentKit operation holds the kit lifecycle lock
  5   SkillX kit, revision, foundation, version or skill not found
  6   review required, stale plan token, a foundation downgrade without --allow-downgrade, alias collision, or an unowned or modified path
  7   the revision document does not match its pin, carries an unsafe path or key, a revoked foundation, or a link in a target path

```
ak skills kit sync <name> --locked [--kit @<handle>/<name> --revision <id> --digest sha256:<hex>] [flags]
```

### Examples

```
  ak skills kit sync mine --locked --dry-run
  ak skills kit sync mine --locked
  ak skills kit sync mine --locked --kit @alice/mine --revision pkr_... --digest sha256:... --json
  ak skills kit sync mine --locked --allow-downgrade --dry-run
```

### Options

```
      --allow-downgrade   Replay a revision that pins a foundation older than the running one (needs review)
      --digest string     Revision digest the document must hash to (default: the linked one)
      --dry-run           Print the plan, its review findings and plan token; write nothing
  -h, --help              help for sync
      --json              Emit machine-readable JSON (implies --no-interactive)
      --kit string        SkillX personal kit @<handle>/<name> (default: the linked one)
      --kits-dir string   Foundation kits directory (default: $AGENTKIT_KITS_DIR or ./kits)
      --locked            Project only the exact pinned revision (required)
      --no-interactive    Disable interactive prompts (CI-safe)
      --plan string       Plan token from --dry-run; required when the plan needs review
  -q, --quiet             Suppress non-error output on stderr
      --revision string   SkillX revision id to project (default: the linked one)
      --runtime strings   Runtimes: claude-code, codex (repeatable; the running revision's runtimes are always included)
      --scope string      Lock and skills root scope: project (default) or global (default "project")
  -V, --verbose           Extra diagnostic output on stderr (loses to --quiet)
  -y, --yes               Assume yes for all prompts
```
