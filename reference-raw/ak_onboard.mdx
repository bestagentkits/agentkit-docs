## ak onboard

First-run conductor: setup, login, then install a kit

### Synopsis

First-run conductor: setup → sign in (email OTP or API key) → install a kit in this folder. Finished steps are skipped, so an existing AgentKit user only installs a missing kit. A published -beta CLI installs beta kits unless --channel is set. Any folder except $HOME is a project (git optional). From $HOME, pick global install or cd into a folder. On a TTY this uses the same select/input chrome as `ak setup` (arrow keys, Esc to cancel). Does not replace `ak setup` for later config edits. Scripted mode needs an existing session.

Effects:
  May write ~/.agentkit/config.yaml, CLI session, and project or global kit files. Does not change bare `ak` help.

Exit status:
  0   known-good for this invocation
  1   runtime or authentication failure
  2   incomplete: need TTY login, --target, or a project directory
  3   user cancelled

```
ak onboard [flags]
```

### Examples

```
  ak onboard
  ak onboard --kit engineer --target claude-code
  ak onboard --global --yes
```

### Options

```
      --channel string       Persist and use stable or beta. A published -beta CLI installs beta kits unless this flag is set
      --email string         Email for TTY OTP login when no CLI session exists
  -g, --global               Install the kit at user/global scope
  -h, --help                 help for onboard
      --json                 Emit machine-readable JSON (implies --no-interactive)
      --kit string           Kit to install (default: kit.default, else engineer)
      --no-interactive       Disable interactive prompts (CI-safe)
      --project-dir string   Project directory (must not be the user home unless --global)
  -q, --quiet                Suppress non-error output on stderr
      --target string        Runtime target (required when adapters.enabled is none in non-interactive mode)
  -V, --verbose              Extra diagnostic output on stderr (loses to --quiet)
  -y, --yes                  Assume yes for all prompts
```
