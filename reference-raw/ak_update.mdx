## ak update

Preview or apply AgentKit-owned project refreshes

### Synopsis

Update AgentKit: on an interactive TTY, bare `ak update` runs a step-by-step wizard (CLI signed self-update → global/user kits → project kits). With --yes (or after an interactive accept) it updates or re-executes the ak binary first when needed, then refreshes kit content. Use `ak self-update --yes` for a binary-only operation. Each step defaults to N; pass --yes to accept every step, or pin scope with --global / [project-dir].

Project scope: for each tracked file, `ak update` checks whether the user has modified it since install. Clean files are overwritten; user-modified files are skipped (unless --force). A pre-update project snapshot is always taken before mutation.

Scripted / non-TTY callers without --yes stay preview-only (exit 3, offline-safe). Pass --global (-g) to refresh only AgentKit-owned user/global kit installs (preserve-only; no --force). Claude Code user-plugin-only installs are reported, not silently refreshed — use `ak kit refresh <kit> --global --switch-to-plugin`.

Runtime selection: --target (alias --runtime) picks which agent runtime(s) to update (claude-code, codex, cursor, grok), comma-separated for several at once. At --global it filters which installed runtimes refresh — unset means all discovered runtimes; a runtime you ask for but have not installed globally is reported as skipped, not an error. At project scope exactly one runtime is materialized, so a multi-value spec there is rejected. --target and --runtime are the same flag; set only one.

Effects:
  TTY wizard applies only the steps you accept (or all steps with --yes). Scripted project updates preview by default; apply with --yes. With --yes (and after an interactive accept), the command updates or re-executes the ak binary first when needed, then refreshes kit content. CLI hard-gate runs before kit mutation (manager-owned / Windows-pending / restart-required abort). Kit failures continue with an honest summary and a support bundle under ~/.agentkit/support/. Global refresh is preserve-only: --force never overwrites user-modified files; it only authorizes archiving legacy ClaudeKit Codex skills so the refresh can proceed. Use `ak self-update --yes` for a binary-only operation.

Exit status:
  0   success
  1   runtime error, CLI hard-gate, partial kit failure, or interrupt after mutation
  2   invalid flags (including --target with --runtime set differently, an unknown runtime, or a multi-value --target at project scope); with --global: a project directory argument, an empty refreshable set, or a plugin-only result
  3   preview only — neither --yes nor an interactive confirmation was given

```
ak update [project-dir] [flags]
```

### Examples

```
  ak update
  ak update --yes
  ak update ./myproj
  ak update --show-diff
```
