## ak secrets bundle create

Seal the selected secrets into an encrypted CI bundle

### Synopsis

Read each --secret REF from this device's vault and seal exactly those values, each under the environment variable VAR, to the CI key's public recipient. Selection is an explicit allowlist: there is no export-all, and the bundle never carries grants, membership, device keys, recovery material, the ref names or any metadata. --profile names the trust boundary (for example ci-production); `run --bundle` refuses a bundle whose profile is not the one it was told to expect. Use one bundle and one key per boundary. Possession of the bundle and its key permits reading every value in it. The vault may ask for its passphrase here, on this trusted device; nothing in CI does.

Effects:
  Reads the selected secrets and writes the 0600 bundle file (replacing an existing one at --output).

Exit status:
  0   the bundle was written
  2   invalid flags, profile, recipient or selection
  3   a selected secret does not exist
  5   the vault could not be read or the file could not be written

```
ak secrets bundle create --profile NAME --encrypt-for AGE_RECIPIENT --secret VAR=REF [--secret VAR=REF ...] --output FILE [flags]
```

### Examples

```
  ak secrets bundle create --profile ci-production --encrypt-for age1... --secret DEPLOY_TOKEN=${REF} --output ci-production.akv
  ak secrets bundle create --profile ci-staging --encrypt-for age1... --secret A=${REF_A} --secret B=${REF_B} --output ci-staging.akv
```
