## ak secrets alias

Point an env var name at one of several stored secrets

### Synopsis

An alias maps an environment-variable name to a stored ref, so one logical key (CLAUDE_API_KEY) can follow whichever account's secret (CLAUDE_API_KEY_1, CLAUDE_API_KEY_2) you pick, switched with one command. A $&#123;secret:NAME&#125; reference the inject hook resolves, and the REF of `ak secrets run --env VAR=REF`, follow an alias when no secret of that name is stored. A stored ref always wins over an alias of the same name, and an alias is followed one hop: a target that is itself an alias, or that has no stored value, is refused as a missing secret.

An alias grants nothing. The grant, approval and audit checks run against the ref the alias points at, never the alias name, so grant the target (`ak secrets grant CLAUDE_API_KEY_1 ...`); the audit row records the alias as alias:&lt;NAME&gt;. Switching an alias to a secret the agent holds no grant on files a request for that secret.

Aliases hold names only, never a value, and live in ~/.agentkit/secrets/aliases.json on this device. They are not synced: the vault sync carries the values, and which account a machine uses stays that machine's choice.

### Examples

```
  ak secrets alias set CLAUDE_API_KEY CLAUDE_API_KEY_1   # pick account 1
  ak secrets alias set CLAUDE_API_KEY CLAUDE_API_KEY_2   # switch to account 2
  ak secrets alias list --json
  ak secrets alias unset CLAUDE_API_KEY
```
