## ak migrate prefs

Migrate legacy ClaudeKit preferences into AgentKit config.yaml

### Synopsis

What it does:
  Read legacy ClaudeKit `.ck.json` preferences and merge their values into the AgentKit config: the user-level file under the AgentKit home, and the project file under .agentkit/ when the current directory has one. Values already set in AgentKit win, so the migration is safe to re-run. This migrates preferences only — `ak migrate` without a subcommand moves kit content and installs.

Who it's for:
  Anyone whose settings still live in .ck.json, including after the kits were migrated.

When to use it:
  Once, after moving to AgentKit, or whenever `ak doctor` reports a residual .ck.json.

Examples:
  ak migrate prefs                       # preview the migration
  ak migrate prefs --dry-run=false --yes # apply it
  ak migrate prefs --json                # machine-readable report

What changes on disk:
  Read-only with --dry-run (default). Without --dry-run, merges values into config.yaml only after --yes; the legacy file is left untouched.

Output modes:
  pretty   default on TTY (colors, ASCII markers)
  plain    auto when stdout piped or --no-interactive
  json     --json (single-object envelope, NDJSON-safe)

Exit codes:
  0  success
  1  runtime error
  2  invalid flags
  3  user-cancel (SIGINT, prompt-cancel)

```
ak migrate prefs [flags]
```

### Options

```
      --dry-run          Preview the preference migration without writing any files (default true)
      --from string      Source to migrate from (currently supports "ck" for ClaudeKit) (default "ck")
  -h, --help             help for prefs
      --json             Emit machine-readable JSON (implies --no-interactive)
      --no-interactive   Disable interactive prompts (CI-safe)
  -q, --quiet            Suppress non-error output on stderr
  -V, --verbose          Extra diagnostic output on stderr (loses to --quiet)
  -y, --yes              Assume yes for all prompts
```
