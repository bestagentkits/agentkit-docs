## ak secrets run

Run one program with secrets in its environment, under exec grants

### Synopsis

Run one program with secrets delivered only in the environment variables --env names. Each VAR=REF pair needs an exec grant (`ak secrets grant REF --exec PROGRAM --env VAR`) for the calling agent on exactly this program: its path with every symlink resolved and its content hash. A program found elsewhere on PATH, or changed since the grant, matches no grant, and each uncovered scope is filed for the operator to answer with `ak secrets approve`, as resolve files one. An ordinary grant never releases here, and an exec grant never releases to resolve. A REF with no stored value that names an alias (see `ak secrets alias`) follows it one hop, and the exec grant is checked against the alias's target, never the alias name. Every scope is checked, and the program re-hashed, before any value is read, so a run a grant check refuses spends no allow-once. If the program still cannot start after its values were released, the ledger records that it never started.

The program is started directly, never through a shell, so nothing in its arguments is expanded. Shells and launchers are refused. Its environment is rebuilt: a few variables copied from this one (HOME, USER, LANG, TERM, TMPDIR and their kind), a fixed PATH of the system directories (led, for a `#!/usr/bin/env NAME` script, by the directory NAME was found in), and the granted variables; nothing else, proxies and runtime options included. A program that runs a helper installed outside the system directories must name it by path. Its output is relayed with every granted value struck out; the last few bytes are held back (fewer than the longest form of a value, which for an escaped form can exceed the value) until the program writes more or exits.

Ctrl-C reaches the program from the terminal, and SIGTERM and SIGHUP are passed on to it; ak waits for it to exit and never kills it. Its exit status is this command's. ak's own failures always print an error starting `secrets run:` on stderr; the program's status is passed on with nothing added, though the program itself can print anything. Its output goes to pipes, not a terminal.

This bounds which program gets a value, not what the program does with it. The program can still send it anywhere, write it to a file or pass it to a child of its own; an interpreter runs whatever script it is given; a program such as curl, wget or gh can be told by its arguments to send a variable anywhere or to run another program; and any process of the same user can read the program's environment while it runs. Grant exec scopes to programs you would hand the value to yourself.

Effects:
  Reads the vault, the alias file and the grant file, writes one audit row per variable, and starts the program. Files a request in the approval inbox when no exec grant covers a variable. Never prints a value.

Exit status:
  0   the program exited 0; any other status it exits with is passed on (128 plus the signal number if a signal ended it)
  2   invalid flags, no program after --, or a refused program or variable
  3   no secret by that ref
  5   the vault, alias file, grant file or audit ledger could not be used, or the program could not start
  6   a block refuses the caller, its identity cannot be named, or the program changed after it was checked
  7   the file backend's vault needs a passphrase and this run has no terminal
  8   no exec grant covers a variable; a request is waiting for `ak secrets approve`
  9   the caller raised too many approval requests and is in its cool-down
  15  a synced vault policy refuses this release, or whether one governs it cannot be answered; the JSON error's sync.reason names why

```
ak secrets run --env VAR=REF [--env VAR=REF ...] -- <program> [args...] [flags]
```

### Examples

```
  ak secrets run --env STRIPE_API_KEY=${REF} -- stripe customers list
  ak secrets run --env GH_TOKEN=${REF} --purpose release -- gh release list
```

### Options

```
      --backend string         Storage backend: keychain (default), file (age-encrypted vault), or memory (dev/test; values and its index are throwaway)
      --env stringArray        VAR=REF: deliver secret REF in environment variable VAR (repeatable)
  -h, --help                   help for run
      --json                   Emit machine-readable JSON (implies --no-interactive)
      --no-interactive         Disable interactive prompts (CI-safe)
      --project string         Project slot; defaults to the AK project containing the current directory
      --purpose string         Purpose label the grant must match literally
  -q, --quiet                  Suppress non-error output on stderr
      --session string         Session id tying this run to the agent run that asked for it
      --unlock-with-recovery   Open the file backend's vault with a recovery private key and set a new passphrase
  -V, --verbose                Extra diagnostic output on stderr (loses to --quiet)
  -y, --yes                    Assume yes for all prompts
```
