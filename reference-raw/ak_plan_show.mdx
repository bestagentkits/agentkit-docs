## ak plan show

Show a single plan and its phases from the local plan store

### Synopsis

What it does:
  Print full detail for one plan: plan.md's full body, every phase, and each phase file's body. Files-first — reads the folder directly, then best-effort-overlays index-owned fields (state, issue_number, linked_pr, current_phase, per-phase rev/notes/evidence/acceptance/comment_id) from the local plan store when it opens. Accepts either the plan folder basename (e.g. 260722-1200-my-plan) or the indexed &lt;slug&gt;/&lt;timestamp&gt; form. With no id, resolves the current-plan pointer (set by `ak plan create`/`ak plan use`), which lives in .git and is readable even under a sandboxed $HOME.

Who it's for:
  Both: quick lookups and scripted --json inspection.

When to use it:
  (unspecified)

Examples:
  ak plan show
  ak plan show 260722-1200-my-plan
  ak plan show my-project/260722-1200 --json

What changes on disk:
  Read-only on the repo; refreshes the index if stale.

Output modes:
  pretty   default on TTY (colors, ASCII markers)
  plain    auto when stdout piped or --no-interactive
  json     --json (single-object envelope, NDJSON-safe)

Exit codes:
  0  success
  1  runtime error
  2  invalid flags
  3  user-cancel (SIGINT, prompt-cancel)
  1  plan not found, no plan matches the current context, or plan store I/O error

```
ak plan show [id] [flags]
```
