## ak backups create

Create a consistent operational.db snapshot via VACUUM INTO

### Synopsis

What it does:
  Produces a database-aware snapshot of the durable operational core using SQLite VACUUM INTO. Live DB/WAL/SHM files are never raw-copied. Content shards are omitted unless --include-content.

Who it's for:
  Operators capturing recoverable operational state before maintenance.

When to use it:
  Before risky upgrades/recovery drills; not a substitute for runtime source backups.

Examples:
  ak backups create --json
  ak backups create --include-content --json

What changes on disk:
  Writes a staged operational.db under a temp directory and reports checksum/schema metadata. Does not mutate runtime-owned sources.

Output modes:
  pretty   default on TTY (colors, ASCII markers)
  plain    auto when stdout piped or --no-interactive
  json     --json (single-object envelope, NDJSON-safe)

Exit codes:
  0  success
  1  runtime error
  2  invalid flags
  3  user-cancel (SIGINT, prompt-cancel)

```
ak backups create [flags]
```
