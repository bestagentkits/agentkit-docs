## ak init

Initialize an AgentKit project

### Synopsis

Idempotently initialize or update an existing project directory. Tracks managed files under project .agentkit/, kits/, and .claude/ subtrees. Interactive prompts are bypassed with --yes or --no-interactive.

Effects:
  Creates or updates &lt;dir&gt;/.agentkit/ownership.json. Captures pre-init snapshot.

Exit status:
  0   success
  1   directory does not exist or I/O failure
  2   invalid flags or arguments
  6   drifted files detected without --force

```
ak init [dir] [flags]
```

### Examples

```
  ak init
  ak init ./myproj
  ak init --dry-run
  ak init --force
```

### Options

```
      --docs-dir string     Custom docs directory, persisted to .agentkit/config.yaml paths.docs (avoids colliding with an existing docs/ folder)
      --dry-run             Preview what would happen without writing any files
      --force               Proceed even when AK-owned files have been user-modified (drift)
  -h, --help                help for init
      --json                Emit machine-readable JSON (implies --no-interactive)
      --no-backup           Skip the pre-install snapshot (power users only — data loss risk)
      --no-interactive      Disable interactive prompts (CI-safe)
      --plans-dir string    Custom plans directory, persisted to .agentkit/config.yaml paths.plans. A relative value is honored by skills, ak plan, journals, and the dashboard; an absolute value is honored by the config and skills only
      --project-id string   Override the project name stored in the manifest (default: directory basename)
  -q, --quiet               Suppress non-error output on stderr
  -V, --verbose             Extra diagnostic output on stderr (loses to --quiet)
  -y, --yes                 Assume yes for all prompts
```
