Without --set prints the stored visibility of the package. With --set reads it, then changes it from that value (a compare-and-set: a change made meanwhile is never overwritten); setting the current value changes nothing. When the package changed meanwhile its visibility is read once more: if it is already the requested one the command succeeds with changed: false, otherwise it is a conflict (exit 6) naming the visibility found. Narrowing (to private, or public to unlisted) takes effect on the next read. Widening (to unlisted or public) needs your approval in a signed-in SkillX session, so with a token SkillX refuses it and the error points to https://skillx.sh/dashboard.

**Effects:** Reads the package's release list; with --set also changes its visibility on SkillX. Sends the request with the SkillX credential: the agentkit.best link (`ak skills link`) while one exists, otherwise SKILLX_TOKEN. Writes nothing locally and never prompts. Needs SkillX on (after `ak update --ssot`, or AGENTKIT_SKILLX=1 or features.skillx: true).

### Usage

```bash
ak skills visibility <@publisher/slug> [--set private|unlisted|public] [flags]
```

Global flags, output modes, and the base exit codes (`0`–`2`) are shared by every command — see [CLI conventions](../cli-conventions). The sections below list only what is specific to this command.

### Flags

| Flag | Description |
| --- | --- |
| `--set string` | New visibility: private, unlisted or public |

### Exit codes

| Code | Meaning |
| --- | --- |
| `1` | command failure: SkillX offline, the credential missing or refused, or an untrusted answer (a change may have been applied; check with ak skills visibility) |
| `2` | SkillX disabled, invalid flags or arguments, a skill directory that is not a valid skill tree, or a request SkillX refused as invalid |
| `5` | package or release not found, or release publishing not enabled on SkillX |
| `6` | conflict with the package's current state: visibility mismatch, version exists, publish to a deleted package, a release that is not published, a concurrent change that left another state, or the restore window passed |
| `7` | SkillX refused the change: approval needed on the dashboard, not the package owner, publisher suspended, or deleted by an administrator |
