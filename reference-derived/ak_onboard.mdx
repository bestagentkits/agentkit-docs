**First-run conductor:** setup → sign in (email OTP or API key) → install a kit in this folder. Finished steps are skipped, so an existing AgentKit user only installs a missing kit. A published -beta CLI installs beta kits unless --channel is set. Any folder except $HOME is a project (git optional). From $HOME, cd into a project repo and rerun (or pass --project-dir / --global). On a TTY, confirm kit and runtime before install (defaults from config; --kit/--target skip that prompt). An occupied runtime asks to overwrite kit collision paths; --yes never becomes --force. On a TTY this uses the same select/input chrome as `ak setup` (arrow keys, Esc to cancel). Does not replace `ak setup` for later config edits. Scripted mode needs an existing session and a project directory or --global.

**Effects:** May write ~/.agentkit/config.yaml, CLI session, and project or global kit files. Does not change bare `ak` help.

### Usage

```bash
ak onboard [flags]
```

Global flags, output modes, and the base exit codes (`0`–`2`) are shared by every command — see [CLI conventions](../cli-conventions). The sections below list only what is specific to this command.

### Flags

| Flag | Description |
| --- | --- |
| `--channel string` | Persist and use stable or beta. A published -beta CLI installs beta kits unless this flag is set |
| `--email string` | Email for TTY OTP login when no CLI session exists |
| `-g, --global` | Install the kit at user/global scope |
| `--kit string` | Kit to install (default: kit.default, else engineer) |
| `--project-dir string` | Project directory (must not be the user home unless --global) |
| `--target string` | Runtime target (required when adapters.enabled is none in non-interactive mode) |

### Exit codes

| Code | Meaning |
| --- | --- |
| `0` | known-good for this invocation |
| `1` | runtime or authentication failure |
| `2` | incomplete: need TTY login, --target, or a project directory / --project-dir / --global |
| `3` | user cancelled |
