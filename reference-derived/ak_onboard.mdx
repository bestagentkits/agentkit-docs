**One first-run wizard:** setup, sign-in (email OTP or API key), then kit install. On a TTY this uses the same select/input chrome as `ak setup` (arrow keys, Esc to cancel). From $HOME, pick global install or cancel and `cd` into a repo. Does not replace `ak setup` for later config edits. Scripted mode needs an existing session. Does not install kit content itself — calls the kit install service.

**Effects:** May write ~/.agentkit/config.yaml, CLI session, and project or global kit files. Does not change bare `ak` help.

### Usage

```bash
ak onboard [flags]
```

Global flags, output modes, and the base exit codes (`0`–`2`) are shared by every command — see [CLI conventions](../cli-conventions). The sections below list only what is specific to this command.

### Flags

| Flag | Description |
| --- | --- |
| `--channel string` | Persist and use stable or beta for kits and binary updates |
| `--email string` | Email for TTY OTP login when no CLI session exists |
| `-g, --global` | Install the kit at user/global scope |
| `--kit string` | Kit to install (default: kit.default, else engineer) |
| `--project-dir string` | Project directory (must not be the user home unless --global) |
| `--target string` | Runtime target (required when adapters.enabled is none in non-interactive mode) |

### Exit codes

| Code | Meaning |
| --- | --- |
| `0` | known-good for this invocation |
| `1` | runtime or authentication failure |
| `2` | incomplete: need TTY login, --target, or a project directory |
| `3` | user cancelled |
