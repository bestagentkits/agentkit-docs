Calls the vault's secrets_run tool. The relay device runs PROGRAM only when an exec grant it holds for this client covers every VAR=REF pair; it never prompts. Otherwise it files a request in its approval inbox and this command exits 8: approve it on that device with `ak secrets approve`, then run this again. Approve every scope a task needs before the task starts. PROGRAM, its arguments and --project are resolved on the relay device, not here. Output is that device's, with released values redacted; the exit status is the program's.

**Effects:** Renews the sign-in when needed (AGENTKIT_HOME/state/vault-remote.json). Runs nothing locally.

### Usage

```bash
ak secrets remote run --env VAR=REF... -- PROGRAM [ARGS...] [flags]
```

Global flags, output modes, and the base exit codes (`0`–`2`) are shared by every command — see [CLI conventions](../cli-conventions). The sections below list only what is specific to this command.

### Flags

| Flag | Description |
| --- | --- |
| `--env stringArray` | VAR=REF: give secret REF to the program as VAR (repeatable, 1 to 16) |
| `--issuer string` | Authorization server origin (default https://agentkit.best, or AGENTKIT_OAUTH_ISSUER) |
| `--project string` | Registered project on the relay device to run in |
| `--timeout int` | Seconds the device lets the program run (1 to 110) |
| `--vault-id string` | Vault to use when the online devices hold several |
| `--vault-origin string` | Vault origin (default https://vault.agentkit.best) |

### Exit codes

| Code | Meaning |
| --- | --- |
| `0` | the program exited 0; any other status it exits with is passed on |
| `2` | invalid flags or arguments, or the vault found them invalid |
| `3` | the relay device has no secret by that ref |
| `5` | no sign-in, no relay device online, or the vault could not serve the run |
| `6` | the relay device refused the run |
| `8` | no exec grant covers the run; a request waits for `ak secrets approve` on the relay device |
| `9` | too many calls; retry later |
