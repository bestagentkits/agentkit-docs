Check the user and project config files against the schema this binary embeds, reporting the line of each problem. A key spelled the pre-1.0 way still resolves, so it is reported as a warning rather than an error.

**Who it's for:** Anyone hand-editing a config, and CI jobs that keep a committed project config honest.

**When to use it:** Run it after editing config.yaml, or when a setting is not taking effect.

**What changes on disk:** Reads the config files. Writes nothing.

### Usage

```bash
ak config prefs validate [flags]
```

### Examples

```bash
ak config prefs validate                        # the user and project configs
ak config prefs validate --file ./config.yaml   # one file
ak config prefs validate --json                 # a report with a severity and line per finding
```

Global flags, output modes, and the standard exit codes (`0`–`3`) are shared by every command — see [CLI conventions](../cli-conventions). The sections below list only what is specific to this command.

### Flags

| Flag | Description |
| --- | --- |
| `--file string` | validate one file instead of the user and project configs |
