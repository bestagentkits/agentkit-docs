Replace &lt;ref&gt;'s stored value with a new one, read the same way as `ak secrets set`: --value=- (stdin), --value-file=&lt;path&gt;, or an interactive, non-echoing prompt — never --value=&lt;literal&gt;. Unlike set, rotate requires ref to already exist: it always overwrites (like set --force), so confirming existence first catches a typo'd ref instead of silently creating a new secret under the wrong name. Use it when a credential's value changed, expired, or is being rotated as a precaution.

**Effects:** Overwrites the value in the active backend and updates the ref's metadata (rotatedAt) in ~/.agentkit/secrets/index.json.

### Usage

```bash
ak secrets rotate <ref> [flags]
```

Global flags, output modes, and the base exit codes (`0`–`2`) are shared by every command — see [CLI conventions](../cli-conventions). The sections below list only what is specific to this command.

### Flags

| Flag | Description |
| --- | --- |
| `--backend string` | Storage backend: keychain (default), file (age-encrypted vault), or memory (dev/test; values and its index are throwaway) |
| `--unlock-with-recovery` | Open the file backend's vault with a recovery private key and set a new passphrase |
| `--value string` | Secret value source: '-' reads from stdin. A literal value is rejected — use --value=- or --value-file |
| `--value-file string` | Path to a file containing the secret value |

### Exit codes

| Code | Meaning |
| --- | --- |
| `3` | ref has no stored value (rotate never creates one) |
| `5` | backend or index failure |
