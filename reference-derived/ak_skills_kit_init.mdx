Creates the personal kit local/&lt;name&gt; under AGENTKIT_HOME/kits/personal/&lt;name&gt; with a personal-kit.yaml that extends exactly one kit version and declares no overlay or fork. The kit version must resolve offline from --kits-dir. An existing directory of that name is refused, whatever it holds; nothing is overwritten. Add overlays and forks by editing the manifest, then preview with `ak skills kit inspect <name>`.

**Effects:** With --dry-run, read-only. Otherwise, under the kit lifecycle lock and after store recovery, writes AGENTKIT_HOME/kits/personal/&lt;name&gt;/personal-kit.yaml in one journaled transaction that requires it to be absent. Never projects or applies. Requires the skill store on (after `ak update --ssot`, or AGENTKIT_SKILL_STORE=1).

### Usage

```bash
ak skills kit init <name> --extends <kit>@<version> [flags]
```

Global flags, output modes, and the base exit codes (`0`–`2`) are shared by every command — see [CLI conventions](../cli-conventions). The sections below list only what is specific to this command.

### Flags

| Flag | Description |
| --- | --- |
| `--dry-run` | Print the manifest; write nothing |
| `--extends string` | Kit version to extend as &lt;kit>@&lt;version> |
| `--kits-dir string` | Foundation kits directory (default: $AGENTKIT_KITS_DIR or ./kits) |

### Exit codes

| Code | Meaning |
| --- | --- |
| `0` | success, or nothing to change |
| `1` | command failure, such as a path too long or a recovery that is required |
| `2` | the skill store disabled, invalid flags or arguments, or a malformed manifest or proposal |
| `4` | another AgentKit operation holds the kit lifecycle lock |
| `5` | personal kit, foundation, version, skill or previous revision not found (removing a kit that is not applied changes nothing and exits 0) |
| `6` | review required, stale plan token, rebase conflict, alias collision (including a legacy kit alias), or an unowned or modified path |
| `7` | revoked foundation, a link in a target path, or a digest mismatch |
