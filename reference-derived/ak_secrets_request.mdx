Ask for access to one secret before using it. An agent that has found a credential with `ak secrets search` and `ak secrets describe` names it here, and the request waits in the same inbox a refused resolve files into, for the operator to answer with `ak secrets approve`. A request never releases or reads a value, never writes a grant, and never spends an allow-once; only the operator's answer grants anything.

The caller is identified the way `ak secrets resolve` identifies it, by walking the parent-process chain to a recognized agent and hashing its binary; a request from no identified agent is refused. Nothing in a secret's profile is read to decide a request, and no grant is ever inherited from one: a request for a scope is answered by a grant on exactly that scope.

--exec with --env asks for an exec scope: the value delivered only in that environment variable of the program --exec names, pinned by its resolved path and content hash. Shells, launchers and variables that steer a loader, a runtime or a network endpoint are refused. Repeated requests for one scope are one inbox entry, and a caller that asks too often is refused until its cool-down passes.

**Effects:** Reads the secrets index and the grant file. When no grant covers the scope, files it in the approval inbox and writes one row to the secrets audit ledger; a blocked scope writes a block row. Never reads or prints a value.

### Usage

```bash
ak secrets request <ref> [flags]
```

Global flags, output modes, and the base exit codes (`0`–`2`) are shared by every command — see [CLI conventions](../cli-conventions). The sections below list only what is specific to this command.

### Flags

| Flag | Description |
| --- | --- |
| `--backend string` | Storage backend: keychain (default), file (age-encrypted vault), or memory (dev/test; values and its index are throwaway) |
| `--env string` | Environment variable the program receives the secret in (needs --exec) |
| `--exec string` | Program the secret is requested for, by name on PATH or by path; makes this an exec scope (needs --env) |
| `--project string` | Project slot; defaults to the AK project containing the current directory |
| `--purpose string` | Why the secret is needed; shown to the operator and matched literally by the grant |
| `--session string` | Session id tying this request to the agent run that made it |
| `--unlock-with-recovery` | Open the file backend's vault with a recovery private key and set a new passphrase |

### Exit codes

| Code | Meaning |
| --- | --- |
| `0` | the request is waiting for the operator, or a grant already covers it |
| `2` | invalid flags, purpose, ref, exec program or env name |
| `3` | no secret by that ref |
| `5` | the index, grant file, inbox or audit ledger could not be used |
| `6` | a block refuses the caller, or its identity cannot be named |
| `9` | the caller asked too often and is in its cool-down |
| `15` | a synced vault policy refuses this release, or whether one governs it cannot be answered; the JSON error's sync.reason names why |
