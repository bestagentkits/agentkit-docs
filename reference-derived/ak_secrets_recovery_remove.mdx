Drop a recovery recipient by fingerprint and re-encrypt the vault without it. This cuts that key out of every future write. It does not reach a copy of the vault someone already kept: anything encrypted to the key before the removal stays readable with it forever, so treat a leaked key as a reason to rotate the secrets themselves. Fingerprints are matched in full, never by prefix. Removing the last recovery recipient is refused — it would leave the passphrase as the only way in.

**Effects:** Opens the vault with the current passphrase and rewrites vault.age encrypted to the reduced recipient set.

### Usage

```bash
ak secrets recovery remove <fingerprint> [flags]
```

Global flags, output modes, and the base exit codes (`0`–`2`) are shared by every command — see [CLI conventions](../cli-conventions). The sections below list only what is specific to this command.

### Exit codes

| Code | Meaning |
| --- | --- |
| `2` | that recipient is the last one left |
| `3` | no vault at that path, or no recipient with that fingerprint |
| `5` | the vault could not be rewritten |
