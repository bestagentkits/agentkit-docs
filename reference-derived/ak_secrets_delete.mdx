Permanently delete &lt;ref&gt;'s value from the active backend and remove its entry from the index. Deleting a ref that does not exist is an error, not a no-op — delete is not idempotent, so scripts can detect a stale/duplicate delete. Use it when a credential is rotated out of use, revoked, or no longer needed.

**Effects:** Removes the value from the active backend and the ref's entry from ~/.agentkit/secrets/index.json. Irreversible.

### Usage

```bash
ak secrets delete <ref> [flags]
```

Global flags, output modes, and the base exit codes (`0`–`2`) are shared by every command — see [CLI conventions](../cli-conventions). The sections below list only what is specific to this command.

### Flags

| Flag | Description |
| --- | --- |
| `--backend string` | Storage backend: keychain (default), file (age-encrypted vault), or memory (dev/test; values and its index are throwaway) |
| `--unlock-with-recovery` | Open the file backend's vault with a recovery private key and set a new passphrase |

### Exit codes

| Code | Meaning |
| --- | --- |
| `3` | ref has no stored value |
| `5` | backend or index failure |
