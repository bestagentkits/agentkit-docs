Load the policy document and report every pair of rules that disagree about an input both describe, and every compiled rule whose source instruction has changed. A conflicting document enforces nothing, so this is the check that belongs in CI: it turns a typo into a red build instead of a silent enforcement gap in someone's session.

**Effects:** Read-only. Reads the policy document and the instruction files it names.

### Usage

```bash
ak policy validate [flags]
```

Global flags, output modes, and the base exit codes (`0`–`2`) are shared by every command — see [CLI conventions](../cli-conventions). The sections below list only what is specific to this command.

### Flags

| Flag | Description |
| --- | --- |
| `--dir string` | Project directory holding .agentkit/policy.yaml (default ".") |
| `--fail-on-stale` | Also fail when a compiled rule's source instruction has changed |

### Exit codes

| Code | Meaning |
| --- | --- |
| `1` | the policy document is missing or unreadable |
| `2` | invalid arguments |
| `4` | rules in the document disagree, so nothing in it is enforced |
