Restores every personal kit file the apply of the candidate wrote or removed, from the rollback record the apply wrote first. It runs only while each of those files still holds what the apply wrote: a file edited since is evolve.apply_conflict and nothing is changed, so an edit is never lost. It does not change a runtime projection; re-run ak skills kit apply afterwards if the kit was applied.

**Effects:** With --dry-run, read-only. Otherwise, under the kit lifecycle lock: snapshots the personal kit when a file is rewritten, restores the files in one journaled transaction and sets the candidate's apply slot to rolled_back. Requires AGENTKIT_SKILL_STORE=1. Runs no script, model or network call.

### Usage

```bash
ak skills evolution rollback <candidateId> [flags]
```

Global flags, output modes, and the base exit codes (`0`–`2`) are shared by every command — see [CLI conventions](../cli-conventions). The sections below list only what is specific to this command.

### Flags

| Flag | Description |
| --- | --- |
| `--dry-run` | Preview the rollback; write nothing |

### Exit codes

| Code | Meaning |
| --- | --- |
| `0` | success, including a preview |
| `1` | the candidate store, the personal kit or the skill store could not be read or written, or a record failed verification (store.corrupt) |
| `2` | invalid flags or arguments, or an apply without the approval it needs (evolve.approval_required) |
| `4` | another AgentKit operation holds the kit lifecycle lock (evolve.store_busy) |
| `5` | no recorded candidate matches, or the skill's base cannot be resolved (evolve.base_unresolved) |
| `6` | the base moved since the candidate was recorded (evolve.base_changed), the evaluation refuses the apply (evolve.apply_refused), or the personal kit does not hold what the apply or rollback expects (evolve.apply_conflict) |
| `7` | redaction or the content gate could not be prepared (evolve.redaction_failed) |
