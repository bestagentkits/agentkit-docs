Restores the SkillX kit the personal kit's link records (or --kit) after an unpublish, here or on the SkillX dashboard, within 30 days; a kit that is live already is reported as such. A kit an administrator deleted can only be restored by the administrator. SkillX accepts these calls only from the kit's owner with an unscoped SkillX API key (ak secrets SKILLX_TOKEN), which is used for them even while `ak skills link` links SkillX; the agentkit.best link alone is refused with a hint, and the SkillX creator dashboard does the same.

**Effects:** Restores a soft-deleted SkillX personal kit with one POST /api/v1/kits/@&lt;handle&gt;/&lt;name&gt;/restore, within 30 days of the unpublish. When the link record names the kit and nothing else changed it, the record is moved to the restored generation through the skill store journal. Never prompts. Needs SkillX on.

### Usage

```bash
ak skills kit restore <name> [--kit @<handle>/<name>] [flags]
```

Global flags, output modes, and the base exit codes (`0`–`2`) are shared by every command — see [CLI conventions](../cli-conventions). The sections below list only what is specific to this command.

### Flags

| Flag | Description |
| --- | --- |
| `--kit string` | SkillX personal kit @&lt;handle>/&lt;name> (default: the linked one) |

### Exit codes

| Code | Meaning |
| --- | --- |
| `0` | done, already done, or a dry run |
| `1` | command failure: SkillX offline, or no unscoped SkillX API key (the agentkit.best link alone is refused) |
| `2` | SkillX or the overlay flag disabled, invalid flags, or no linked kit and no --kit |
| `5` | the SkillX kit was not found for this credential, or its 30-day restore window has passed |
| `7` | refused by SkillX: the publisher is not owned, or an administrator deleted the kit |
| `10` | personal kits are not enabled for your account yet (SkillX answered kit.api_disabled) |
