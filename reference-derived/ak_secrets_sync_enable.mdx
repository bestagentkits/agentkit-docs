Create a synced vault from this device's secrets. You choose a vault password and receive a recovery key; keep both offline. Losing both, with no enrolled device left, makes the vault unrecoverable. Use `ak secrets devices add` instead if the account already syncs elsewhere. Needs an email sign-in (`ak login`), or an API-key sign-in whose key has vault sync turned on, and the keychain or file backend. An API-key sign-in creates the vault without a recovery bundle, password or kit, and warns on stderr (and in `warnings` with --json) until an email sign-in seals one with `ak secrets sync rotate-recovery`. --resume continues an enable that stopped, or turns sync back on after `ak secrets sync disable`. --accept-sealed lets this device apply the sealed writes a remote MCP client queued on the vault server (each one is written as this device's own signed record and audited); on a device that already syncs it only changes that setting, and --accept-sealed=false turns it off. A compromised vault server cannot read these writes but can forge one, so an agent may not turn --accept-sealed on; run it in a terminal you opened yourself. The setting is this device's own; an older AgentKit cannot read a config with it on, so turn it off before installing one here. An older AgentKit also refuses this version's sync state; see the secrets guide before going back.

**Effects:** Generates this device's keys and a vault key, stores them in the keystore, writes sync state under AgentKit home, uploads the encrypted vault, and shows the recovery kit once on the terminal (stderr), or writes it only to --recovery-kit-out with mode 0600.

### Usage

```bash
ak secrets sync enable [flags]
```

Global flags, output modes, and the base exit codes (`0`–`2`) are shared by every command — see [CLI conventions](../cli-conventions). The sections below list only what is specific to this command.

### Flags

| Flag | Description |
| --- | --- |
| `--accept-sealed` | Apply sealed writes queued by remote MCP clients on this device's sync cycles |
| `--backend string` | Storage backend: keychain (default), file (age-encrypted vault), or memory (dev/test; values and its index are throwaway) |
| `--password-file string` | Read the vault password from this file, or - for stdin (default: prompt twice on the terminal) |
| `--recovery-kit-out string` | Write the recovery kit only to this new file (mode 0600), not the terminal; required with --json or without a terminal |
| `--resume` | Continue a stopped enable, or re-enable after disable |
| `--unlock-with-recovery` | Open the file backend's vault with a recovery private key and set a new passphrase |

### Exit codes

| Code | Meaning |
| --- | --- |
| `1` | the server refused (quota, unsupported protocol) |
| `2` | invalid invocation: no kit destination, short password, memory backend, or the store moved |
| `4` | sync is already enabled (and no --accept-sealed change was asked), a partial enable needs --resume, or the kit file exists |
| `5` | local storage failure |
| `6` | refused: an AI agent is turning --accept-sealed on |
| `7` | the file-backend passphrase is unavailable |
| `10` | --resume with nothing to resume |
| `11` | the vault server is unavailable or busy; retry |
| `12` | enabled, but something needs attention |
| `13` | integrity alarm; sync halted |
| `14` | not logged in, or the session cannot mint vault tokens |
