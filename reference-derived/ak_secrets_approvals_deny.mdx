Deny the pending request &lt;id&gt; (or a unique prefix of it) with a decision signed by this device. The requesting device refuses the release and does not ask again until the request expires. An id that starts with "-" goes after "--", as in "ak secrets approvals deny -- -r_nM".

**Effects:** Signs one decision with this device's key and sends it to the vault server. The first answer wins; a request already answered, withdrawn or expired is refused with 3.

### Usage

```bash
ak secrets approvals deny <id> [flags]
```

Global flags, output modes, and the base exit codes (`0`–`2`) are shared by every command — see [CLI conventions](../cli-conventions). The sections below list only what is specific to this command.

### Flags

| Flag | Description |
| --- | --- |
| `--backend string` | Storage backend: keychain (default), file (age-encrypted vault), or memory (dev/test; values and its index are throwaway) |
| `--unlock-with-recovery` | Open the file backend's vault with a recovery private key and set a new passphrase |

### Exit codes

| Code | Meaning |
| --- | --- |
| `1` | the vault server does not serve remote approvals, or an unexpected failure |
| `2` | invalid invocation, an ambiguous id prefix, or the store moved since enable |
| `3` | no pending request has that id (answered, withdrawn or expired) |
| `5` | local storage failure |
| `6` | this device may not answer (a machine device or a reader), or an agent ran approve |
| `10` | sync is not enabled on this device |
| `11` | the vault server is unavailable or busy; retry |
| `13` | integrity alarm; sync halted |
| `14` | not logged in, or this device was removed |
