# Plan: Hook preference management guide

## Outcome

A Beta-channel guide (EN+VI) that documents `ak config prefs set|unset|resolve|validate`
for `hooks.<name>` soft preferences: what a preference changes, the exact command
forms, user vs project scope with examples, validation/limits, and
recovery/troubleshooting — discoverable from the hooks and configuration docs.

## Constraints / non-goals

- Beta-only. `content/docs/stable/**` is machine-generated by
  `scripts/promote-docs.mjs`; never hand-edit it (AGENTS.md). This guide lands
  in Beta and reaches Stable through the normal promotion pipeline (out of
  scope for this issue).
- Never hand-edit `reference-derived/` or the generated
  `content/docs/beta/reference/cli/config/prefs/*` pages — they are the
  released CLI reference this guide must stay consistent with, not duplicate.
- Command syntax, flags, validation rules, and exit codes must match the
  existing generated reference pages (`config/prefs/{index,set,unset,resolve,validate}.en.mdx`),
  already read in full — do not invent flags.
- Keep prose channel-neutral (no "beta"/"stable" wording), per AGENTS.md.
- `Hook` stays untranslated in Vietnamese prose (product-taxonomy rule in AGENTS.md).

## Acceptance criteria (from issue #111)

- [ ] Guide linked from configuration and/or hooks navigation surfaces.
- [ ] Copyable user-scope and project-scope enable/disable examples.
- [ ] Documents `set`, `unset`, validation behavior, and effective-preference
      verification (`resolve`), matching the released CLI reference.
- [ ] Distinguishes soft preference control from uninstalling/deleting hooks.
- [ ] Documents restoring default/inherited behavior and troubleshooting.
- [ ] Stable/Beta content and CLI reference remain consistent (Beta-only edit;
      no stable hand-edit; no generated-dir edit).
