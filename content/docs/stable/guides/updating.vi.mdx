`ak` tự cập nhật từ kênh phát hành đã ký. Mỗi lần cập nhật đều xác minh metadata
phát hành và artifact đích trước khi thay thế binary đang chạy.

## Kiểm tra trước

Hãy truyền `--channel stable` một cách tường minh — kênh trống mặc định là beta:

```bash
ak self-update --check --channel stable           # có bản mới hơn không?
ak changelog --since-current --channel stable     # đổi gì kể từ phiên bản của tôi?
ak self-update --changelog --channel stable       # in thay đổi đã xác minh trực tiếp
```

## Áp dụng

Việc apply thủ công trên CLI cần `--yes`:

```bash
ak self-update --channel stable --yes
```

## Cài bằng trình quản lý gói

Nếu `ak` xác định được binary đang chạy thuộc về một trình quản lý gói (Homebrew,
Scoop), thì cả check lẫn apply đều sẽ báo **managed install** và in ra lệnh gốc
của trình quản lý đó thay vì thay tệp:

```bash
brew upgrade ak      # Homebrew
scoop update ak      # Scoop
```

<Callout type="info">
  Chỉ cài sẵn trình quản lý trên máy thôi là chưa đủ — executable đang được
  resolve phải nằm trong prefix của chính trình quản lý đó thì `ak` mới coi là
  managed.
</Callout>

## Rollback

Để quay về một bản phát hành **binary** trước đó, hãy cài lại đúng phiên bản đó.
Quá trình self-update binary không tạo bản ghi `ak backups`:

```bash
curl -fsSL https://agentkit.best/install.sh | AK_CHANNEL=stable AK_VERSION=<previous-tag> sh
```

`ak backups restore` chỉ khôi phục snapshot **state dự án/vòng đời** (ví dụ sau
`ak update` hoặc sau khi gỡ kit), chứ không phải binary đã cài:

```bash
ak backups list
ak backups restore --latest
```

Hãy ghi lại kết quả `ak --version` và `ak doctor --json` nếu bạn đang báo cáo một
sự cố cập nhật.
