Pi giữ phần lõi tối giản. AgentKit bổ sung nội dung Kit vào môi trường Pi;
bạn có thể chọn thêm extension theo nhu cầu công việc. Các package dưới đây
là phần bổ sung tùy chọn, được cài và cấu hình riêng qua Pi.

Nếu chưa cài Kit, hãy bắt đầu với
[Cài đặt Kit](./installing-kits#dùng-pi-native).

## Chọn extension

Tên mỗi package dẫn đến tài liệu của tác giả, nơi có yêu cầu cài đặt và hướng
dẫn sử dụng hiện hành.

| Extension | Khả năng bổ sung | Khi nào nên dùng |
| --- | --- | --- |
| [@tintinweb/pi-subagents](https://github.com/tintinweb/pi-subagents) + [subagents-pi](https://github.com/luongnv89/pi-extensions/tree/main/extensions/subagents-pi) | Điều phối subagent qua tool `Agent` và FleetView, kèm panel hiển thị context đã dùng, TPS đầu ra, mức thinking và model. | Giao việc và theo dõi các subagent đang hoạt động trong Pi. |
| [statusline-pi](https://github.com/luongnv89/pi-extensions/tree/main/extensions/statusline-pi) | Footer gọn hiển thị trạng thái Git, context còn lại, model, tốc độ phản hồi và chi phí phiên ước tính. | Theo dõi phiên làm việc và project ngay trong Pi. |
| [advisor-pi](https://github.com/luongnv89/pi-extensions/tree/main/extensions/advisor-pi) | Tool `advisor` tham khảo một model khác dựa trên ngữ cảnh hội thoại. Model cố vấn không dùng tool hay sửa file. | Lấy ý kiến thứ hai về kế hoạch, rủi ro hoặc quyết định khó. |
| [pi-multix](https://github.com/bestagentkits/pi-multix) | Tạo ảnh, video, âm thanh, chuyển đổi tài liệu và xử lý media cục bộ qua multix. | Tạo hoặc xử lý media cùng với mã nguồn và nội dung. |
| [pi-lens](https://github.com/apmantza/pi-lens) | Phản hồi mã nguồn qua language server, linter, formatter, kiểm tra kiểu và phân tích cấu trúc. | Cung cấp chẩn đoán cho Pi trong quá trình đọc và sửa code. |
| [pi-web-access](https://github.com/nicobailon/pi-web-access) | Tìm kiếm web, trích xuất nội dung URL và các khả năng bổ sung với tài liệu, video. | Tra cứu tài liệu mới và đưa nguồn bên ngoài vào nhiệm vụ. |
| [pi-model-fallback](https://github.com/eiei114/pi-model-fallback) | Tự chuyển model khi lỗi provider khớp với quy tắc đã cấu hình. | Tiếp tục công việc bằng model dự phòng khi gặp giới hạn lượt gọi hoặc lỗi provider. |
| [pi-mcp-adapter](https://github.com/nicobailon/pi-mcp-adapter) | Truy cập MCP server, tìm tool theo nhu cầu và kết nối khi cần. | Kết nối Pi với công cụ và dịch vụ cung cấp qua MCP. |

Các extension trên tạo thành bộ công cụ cơ bản cho công việc lập trình hằng ngày
với Pi. Nếu muốn mở rộng thêm, bạn có thể tham khảo
[zuey-pi-setup](https://github.com/mrgoonie/zuey-pi-setup) để khám phá thêm
extension và cách kết hợp chúng trong một môi trường Pi hoàn chỉnh hơn.

## Cài qua Pi

Chỉ chạy lệnh cho những extension bạn muốn dùng:

```bash
pi install npm:@tintinweb/pi-subagents
pi install npm:subagents-pi
pi install npm:statusline-pi
pi install npm:advisor-pi
pi install npm:pi-multix
pi install npm:pi-lens
pi install npm:pi-web-access
pi install npm:pi-model-fallback
pi install npm:pi-mcp-adapter
```

Các lệnh này đăng ký package ở phạm vi người dùng của Pi. Thêm `-l` để cài
riêng cho project, ví dụ `pi install -l npm:statusline-pi`.
Khởi động lại Pi sau khi cài để tải các extension mới.

Dùng trình quản lý package của Pi để cập nhật và gỡ extension. Ví dụ:

```bash
pi list
pi update npm:statusline-pi
pi remove npm:statusline-pi
```

## Hoàn tất cấu hình

- **Subagent:** cài cả hai package. `@tintinweb/pi-subagents` đảm nhiệm tạo và
  điều phối subagent, cung cấp FleetView và tool `Agent`. `subagents-pi` là
  panel theo dõi đi kèm, không tự chạy subagent. Panel nằm dưới ô nhập và chỉ
  hiển thị agent đang chạy hoặc chờ; dùng `/subagents-pi` để bật hoặc tắt,
  `/subagents-pi-refresh` để cập nhật các chỉ số.
- **Statusline:** dùng `/statusline-pi` để bật hoặc tắt footer. Chỉ báo PR dùng
  GitHub CLI (`gh`) và được ẩn khi không có công cụ này.
- **Cố vấn:** dùng `/advisor-pi status` để xem cấu hình và
  `/advisor-pi model <provider>/<model>` để chọn model đã xác thực.
  Lượt tham khảo gửi ngữ cảnh hội thoại đến model đó và sử dụng quota hoặc tính phí tương ứng.
- **Media:** pi-multix có sẵn multix CLI. Tạo nội dung qua provider cần API key;
  xử lý media cục bộ cần `ffmpeg` hoặc ImageMagick.
  Yêu cầu Pi chạy `multix_check` để kiểm tra khả năng hiện có.
- **Phản hồi mã nguồn:** làm theo yêu cầu Node.js và hướng dẫn thiết lập ngôn ngữ
  hiện hành của pi-lens. Chẩn đoán khả dụng phụ thuộc vào các công cụ ngôn ngữ nó có thể dùng.
- **Web:** pi-web-access có hướng dẫn tìm kiếm không cần API key và các provider
  bổ sung với cơ chế xác thực riêng. Cấu hình provider bạn muốn sử dụng.
- **Model dự phòng:** cấu hình quy tắc khớp lỗi và model đích đã xác thực cho
  provider của bạn. Cài package không tự tạo chuỗi dự phòng cho mọi provider.
  Dùng `/model-fallback:status` để xem trạng thái.
- **MCP:** dùng `/mcp setup` để cấu hình hoặc nhập các server, rồi `/mcp` để xem
  chúng. Theo hướng dẫn cấu hình của adapter cho thông tin xác thực và tool của server.

Cập nhật Kit của AgentKit và cập nhật package của Pi là hai thao tác riêng.
Giữ cấu hình của từng extension theo hướng dẫn package đó; xem
[Cập nhật](./updating) cho bản thân AgentKit.
