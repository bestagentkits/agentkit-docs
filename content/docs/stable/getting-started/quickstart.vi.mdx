Quy trình tập trung này cài Engineer Kit ở chế độ native vào project hiện tại và
bắt đầu một tác vụ phần mềm trong runtime lập trình được hỗ trợ. Các lệnh bên
dưới minh họa Claude Code, Codex, Cursor, Grok Build và Pi.

## Trước khi bắt đầu

Hoàn thành [Cài đặt](./installation) và [Làm quen](./onboarding), hoặc xác minh ba
trạng thái bắt buộc ngay bây giờ:

```bash
ak --version
ak whoami
ak licenses
```

`ak whoami` phải hiển thị đúng tài khoản, còn Engineer Kit phải xuất hiện trong
`ak licenses`. Runtime đã chọn cũng phải được cài và đăng nhập. Các phép kiểm tra
này không in secret đã lưu của bạn. Kết quả chưa xác thực từ `ak whoami` vẫn trả
exit code `0`, vì vậy hãy kiểm tra trạng thái hiển thị thay vì chỉ dựa vào exit
code.

## Cài và chạy

<Steps>
  <Step>
    ### Mở một project

    Chuyển tới project nơi bạn có thể review và hoàn tác thay đổi. Các lệnh bên
    dưới dùng scope project và chế độ native của runtime.
  </Step>
  <Step>
    ### Cài Engineer Kit

    <Tabs items={['Claude Code', 'Codex', 'Cursor', 'Grok Build', 'Pi']}>
      <Tab value="Claude Code">

    ```bash
    ak kit init engineer --target claude-code --channel <channel>
    ```

      </Tab>
      <Tab value="Codex">

    ```bash
    ak kit init engineer --target codex --channel <channel>
    ```

      </Tab>
      <Tab value="Cursor">

    ```bash
    ak kit init engineer --target cursor --channel <channel>
    ```

      </Tab>
      <Tab value="Grok Build">

    ```bash
    ak kit init engineer --target grok --channel <channel>
    ```

      </Tab>
      <Tab value="Pi">

    ```bash
    ak kit init engineer --target pi --channel <channel>
    ```

      </Tab>
    </Tabs>

    Hãy thay `<channel>` bằng kênh phát hành đang chọn trên header tài liệu. Nếu
    bỏ `--channel`, CLI resolve kênh Kit `stable` và có thể trả
    `version_not_available` khi runtime package chỉ tồn tại ở kênh khác. Hãy
    review preview cùng cảnh báo trước khi tiếp tục.
  </Step>
  <Step>
    ### Nạp lại trợ lý

    Mở phiên mới trong runtime đã chọn từ cùng project để trợ lý phát hiện Skill đã
    cài.
  </Step>
  <Step>
    ### Gọi `ak:cook`

    <Tabs items={['Claude Code', 'Codex']}>
      <Tab value="Claude Code">

    ```text
    /ak:cook Add a health-check endpoint
    ```

      </Tab>
      <Tab value="Codex">

    ```text
    $ak:cook Add a health-check endpoint
    ```

      </Tab>
    </Tabs>

    Claude Code dùng `/ak:...`; Codex dùng `$ak:...`. Với Cursor, Grok Build và
    Pi, hãy xác minh surface discovery và invocation hiện tại của runtime sau
    khi cài. Pi expose các thư mục Skill portable `ak-<slug>` dưới `.pi/skills/`.
    Với Skill dispatch trực tiếp, `ak run` cũng hỗ trợ `--target omp` cho Oh My
    Pi. Tên Kit vẫn ở dạng thường trong lệnh CLI như `ak kit init engineer`.
  </Step>
</Steps>

## Kết quả mong đợi

Trợ lý nhận diện `ak:cook`, đọc tác vụ cùng context project hiện tại và bắt đầu
workflow của skill. Hãy review scope đề xuất và mọi thay đổi tệp như với công
việc lập trình khác. Quickstart hoàn tất khi skill đã khởi chạy thành công; kết
quả của tác vụ mẫu phụ thuộc vào project của bạn.

## Nếu skill không được nhận diện

1. Xác nhận phần tóm tắt cài đặt ghi `engineer` và đúng target bạn muốn.
2. Xác nhận bạn đang ở đúng project, scope và delivery mode đã dùng khi cài, đồng
   thời tập Skill đã chọn có `ak:cook`.
3. Xác nhận phiên bản và release channel của CLI cùng Kit đúng như bạn dự định.
4. Mở phiên trợ lý mới trong cùng project.
5. Chạy `ak doctor --exit-on-fail` và xử lý mọi kiểm tra runtime hoặc Kit được báo.
6. Nếu có xung đột quyền sở hữu khi cài, hãy dừng và kiểm tra; đừng lập tức thử
   lại với `--force`.

Nếu thao tác được quản lý đã in backup ID, hãy giữ ID tới khi xác minh xong
project. Kiểm tra thông tin và xem trước điểm khôi phục bằng
`ak backups show <backup-id>` cùng `ak recover <backup-id> --dry-run`; xem
[Phần khôi phục trong Làm quen](./onboarding#khôi-phục-và-lỗi-thường-gặp) để biết
lệnh áp dụng và giới hạn restore.

## Giữ CLI và Kit luôn cập nhật

Binary, nội dung thuộc quyền sở hữu AgentKit trong project và Kit đã cài vào
runtime là ba lớp riêng biệt. `ak self-update` thay đổi binary CLI; lệnh này
không làm mới file trong `.claude`, `.codex` hoặc đích runtime khác. `ak update`
xử lý nội dung project thuộc quyền sở hữu AgentKit, còn `ak kit refresh` phát lại
một tuyến cài Kit theo target, scope, delivery mode và tập Skill đã ghi nhận.

Dùng [Cập nhật AgentKit và Kit](../guides/updating) để chọn đúng lớp bạn muốn thay
đổi. Nếu file vẫn không đổi, hãy kiểm tra tuyến cài và bằng chứng quyền sở hữu
trước khi cài lại hoặc xóa nội dung runtime.
