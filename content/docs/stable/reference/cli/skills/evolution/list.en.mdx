---
title: ak skills evolution list
description: List every verified skill evolution candidate with its skill, classification, findings, and slot states.
---

Use `ak skills evolution list` to see which candidates
[`ak skills improve --candidate`](../cli/ak_skills_improve) recorded on this machine and
where each one stands.

## Usage

```bash
ak skills evolution list [--json]
```

The command accepts no positional arguments. It is read-only: it reads the
candidate records under `AGENTKIT_HOME/state/skill-evolve/candidates/`,
verifies each against its candidate ID, takes no lock, runs no script, model,
or network call, and skips the background update check.

## Output

Text prints one line per verified candidate: the ID, the skill identity, the
classification and confidence, the finding count, and the evaluation and apply
slot states. A record that fails verification is reported as `unverified <id>`
with a `store.corrupt` warning instead of being listed. An empty store prints
`no recorded candidates`.

JSON uses `kind=skills.evolution.list`:

```text
schema_version: 1
kind: skills.evolution.list
data.candidates[]: candidateId, skill, base, overlay, diff[], findings[],
                   blastRadius, classification, confidence, evaluation, apply
data.unverified[]
```

`classification` is `preference`, `systematic`, or `conflicting`;
`confidence` is `low`, `medium`, or `high`. The `evaluation` slot state is
`not_evaluated` or `evaluated`; the `apply` slot state is `not_applied`,
`applied`, or `rolled_back`.

## Exit behavior

| Exit | Meaning |
| --- | --- |
| `0` | Success, including an empty candidate store or one with unverified records. |
| `1` | The candidate store could not be read. |
| `2` | Invalid flags or arguments. |
