Dùng `ak:bootstrap` để đưa project mới từ outcome đã chấp nhận tới code chạy
được. Skill điều phối research, chọn stack, design, planning, implementation,
testing, review, documentation và onboarding thay vì chỉ tạo một scaffold khó
kiểm chứng.

## Chọn ak:bootstrap cho project mới

### Dùng ak:bootstrap khi

- Bạn bắt đầu project hoặc full-stack setup từ đầu.
- Bạn có thể nêu product outcome, constraint, non-goal và acceptance criteria
  quan sát được.
- Bạn muốn nối quyết định stack và design với implementation đã kiểm thử.
- Bạn chấp nhận mode đã chọn tạo project file, plan và documentation.

### Chọn workflow khác khi

- Bạn đang thay đổi project hiện có với scope đã rõ. Dùng `ak:cook`.
- Bạn vẫn cần so sánh product direction. Dùng `ak:brainstorm` trước.
- Bạn chỉ cần implementation plan. Dùng `ak:plan`.
- Bạn cần đưa code hiện có ra CLI hoặc MCP server. Dùng `ak:agentize`.

## Chuẩn bị project và runtime

Trước khi bắt đầu:

- Hoàn thành [Làm quen](../../../getting-started/onboarding) và xác nhận
  Engineer Kit đã được cài cho runtime cùng scope đang dùng.
- Mở directory sẽ sở hữu project mới.
- Quyết định có cho phép khởi tạo Git nếu directory chưa là repository không.
- Nêu constraint bắt buộc về stack, compatibility, security, delivery và
  licensing trước khi bắt đầu lựa chọn tự động.
- Không đưa credential vào request. Chỉ cung cấp sau qua setup flow được project
  chấp nhận.

| Runtime | Cách gọi | Ranh giới khả dụng |
| --- | --- | --- |
| Claude Code | `/ak:bootstrap ...` | Phân phối native là mặc định; phân phối plugin rõ ràng cũng được hỗ trợ. Workflow có thể dùng toàn bộ collaboration surface Claude được hỗ trợ. |
| Cursor | `/ak:bootstrap ...` | Slash invocation theo cách gọi Engineer Skill do người dùng xác minh. Capability về Agent, plan và approval phụ thuộc surface Cursor đang hoạt động. |
| Codex | `$ak:bootstrap ...` | Native Skill discovery được hỗ trợ. Phase delegated hoặc parallel cần session Codex hiện tại cung cấp multi-agent capability tương ứng. |

Xem [Runtime adapter](../../../concepts/runtime-adapters) trước khi cho rằng mọi
runtime có cùng orchestration control.

Nếu không truyền cờ, Skill dùng `--full`.

| Mode | Thay đổi điều gì | Hành vi phê duyệt |
| --- | --- | --- |
| `--full` | Chạy refinement yêu cầu, research, chọn stack, design tùy chọn, planning chi tiết và implementation interactive | Dừng tại mọi phase chính, gồm khởi tạo Git và duyệt plan |
| `--auto` | Tự động research và chọn stack, rồi dùng planning cùng implementation tự động | Giữ opening contract và design approval gate; bỏ các lần dừng thường lệ về sau |
| `--fast` | Kết hợp research, stack và design có giới hạn trước một fast plan | Giữ opening contract và review gate bình thường của `ak:cook` |
| `--parallel` | Tạo dependency graph và giao ownership implementation không chồng lấn | Giữ opening contract, design approval và review gate của `ak:cook --parallel` |

## Mô tả project rõ ràng

Một request hữu ích gồm:

- **Outcome:** Nêu người dùng có thể làm gì khi project chạy.
- **Constraints:** Nêu technology, platform, compatibility, security rule và
  delivery boundary bắt buộc.
- **Non-goals:** Loại trừ feature gần kề không nên vào implementation đầu tiên.
- **Acceptance criteria:** Đưa ra phép kiểm tra quan sát được cho main path,
  failure behavior và edge case quan trọng.
- **Authority boundary:** Nêu có cho phép Git initialization, dependency
  installation, external research, asset generation, commit, publication hoặc
  deployment không.

Với ví dụ incident response, hãy nêu thêm ai được xem incident, event nào vào
audit log, “private” có nghĩa gì và validation nào chứng minh release đầu dùng
được.

## Hiểu workflow

1. **Skill khóa project contract.** Skill ghi nhận hoặc dùng lại outcome,
   constraint, non-goal và acceptance criteria trước mọi setup work.
2. **Skill kiểm tra trạng thái Git.** Với `--full`, Skill hỏi trước khi khởi tạo
   Git. Với `--auto`, `--fast` và `--parallel`, workflow khởi tạo repository còn
   thiếu qua Git workflow.
3. **Skill research và chọn setup.** Độ sâu, parallelism và approval gate theo
   mode đã chọn.
4. **Skill tạo design evidence khi phù hợp.** Skill có thể tạo design guidance,
   wireframe, screenshot và generated asset qua design cùng media tool khả dụng.
5. **Skill tạo plan.** Skill gọi `ak:plan` với hành vi theo mode và giữ nguyên
   contract đã chấp nhận.
6. **Skill triển khai qua ak:cook.** Plan được chuyển cho `ak:cook`; testing và
   code review theo workflow đó thay vì các edit trực tiếp không được theo dõi.
7. **Skill hoàn tất project handoff.** Skill đánh giá documentation, cập nhật
   plan state, hướng dẫn onboarding và báo changed file, check, risk cùng next
   action.

## Giữ quyền phê duyệt và an toàn ở bạn

<Callout type="warn" title="Mode nhanh và tự động có thể đổi trạng thái repository">
  Khi chưa có Git, `--auto`, `--fast` và `--parallel` sẽ khởi tạo repository mà
  không có câu hỏi Git-init riêng như `--full`. Chọn `--full` hoặc tự khởi tạo
  repository khi quyết định đó cần review.
</Callout>

Automatic execution không cấp authority ngoài scope. External research, asset
generation, dependency installation, credential use, commit, push,
publication và deployment vẫn phụ thuộc tool khả dụng cùng scope bạn đã duyệt.
Git action cuối vẫn là câu hỏi riêng.

Parallel mode cần exclusive file ownership và dependency rõ ràng. Worker hoặc
worktree riêng giúp giảm edit collision; chúng không phải operating-system
sandbox và không làm conflicting change tự động an toàn để merge.

## Xác minh kết quả

Một lần chạy hoàn tất nên cung cấp:

- Project chạy được và khớp outcome cùng non-goal đã chấp nhận.
- Plan với phase state hiện tại và acceptance criteria.
- Quyết định stack cùng design được ghi trong documentation của project khi có
  ảnh hưởng lâu dài.
- Test thực và project check, với failure đã xử lý hoặc được báo rõ.
- Kết quả code review không che giấu critical finding.
- Bước onboarding cho phần configuration vẫn cần bạn thực hiện.
- Final report ngắn gọn với changed file, validation, remaining risk và câu hỏi
  chưa giải quyết.

Xem generated wireframe hoặc passing build là bằng chứng trung gian. Project chỉ
hoàn tất khi acceptance criteria, test, review và onboarding path thống nhất.

## Xử lý sự cố hoặc tiếp tục

| Triệu chứng | Bước tiếp theo an toàn |
| --- | --- |
| Skill hỏi về product trước setup | Cung cấp outcome, constraint, non-goal hoặc acceptance criterion còn thiếu. Mọi mode đều giữ opening gate này. |
| Stack được chọn không đúng | Dừng trước approval, thêm compatibility hoặc delivery constraint còn thiếu rồi chạy lại quyết định liên quan. |
| Parallel work chồng lấn | Dừng writer, tách file ownership hoặc chạy tuần tự phase phụ thuộc rồi xác minh integrated tree. |
| Design hoặc external tool không khả dụng | Giữ limitation hiển thị và chọn local alternative được hỗ trợ hoặc bỏ output tùy chọn bằng quyết định rõ ràng. |
| Test thất bại gần cuối | Giữ failure hiển thị và quay lại implementation hoặc debugging; không đánh dấu scaffold hoàn tất. |
| Runtime không nhận diện Skill | Xác nhận target cùng scope, mở runtime session mới, rồi làm theo [Runtime không tìm thấy Skill hoặc Agent](../../../troubleshooting/runtime-cannot-find-skill-or-agent). |

Tiếp tục với [Cài đặt Kit](../../../guides/installing-kits),
[Engineer Kit](../../engineer) hoặc `ak:cook` khi project đã có implementation
scope được chấp nhận.

## Biết các giới hạn hiện tại

- Skill phụ thuộc planning, implementation, testing, review, design và media
  capability thực sự khả dụng trong runtime hiện tại.
- Dependency cùng asset tool có thể cần network access hoặc provider setup;
  workflow không thể tạo credential hay service availability còn thiếu.
- `--fast` giảm research overhead, không giảm implementation verification.
- `--parallel` chỉ hữu ích khi công việc tách được thành ownership độc lập.
- Stable và beta chứa cùng workflow cùng mode behavior của `ak:bootstrap`.
