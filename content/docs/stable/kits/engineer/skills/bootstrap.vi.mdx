Dùng `ak:bootstrap` để đưa project mới từ outcome đã chấp nhận tới code chạy
được. Skill điều phối research, chọn stack, design, implementation, testing,
code review, tăng cường UX/AI-experience và onboarding thay vì chỉ tạo một
scaffold khó kiểm chứng. Không có phase planning riêng: brainstorm contract đã
khóa đi thẳng tới `ak:cook`, và cook tự lập implementation plan của nó.

## Chọn ak:bootstrap cho project mới

### Dùng ak:bootstrap khi

- Bạn bắt đầu project hoặc full-stack setup từ đầu.
- Bạn có thể nêu product outcome, constraint, non-goal và acceptance criteria
  quan sát được, hoặc bạn muốn `--ask` phỏng vấn bạn tới khi chốt xong.
- Bạn muốn nối quyết định stack và design với implementation đã kiểm thử.
- Bạn chấp nhận mode đã chọn tạo project file và documentation.

### Chọn workflow khác khi

- Bạn đang thay đổi project hiện có với scope đã rõ. Dùng `ak:cook`.
- Bạn vẫn cần so sánh product direction. Dùng `ak:brainstorm` trước.
- Bạn chỉ cần implementation plan. Dùng `ak:plan`.
- Bạn cần đưa code hiện có ra CLI hoặc MCP server. Dùng `ak:agentize`.

## Chuẩn bị project và runtime

Trước khi bắt đầu:

- Hoàn thành [Làm quen](../../../getting-started/onboarding) và xác nhận
  Engineer Kit đã được cài cho runtime cùng scope đang dùng.
- Mở directory sẽ sở hữu project mới.
- Quyết định có cho phép khởi tạo Git nếu directory chưa là repository không.
- Nêu constraint bắt buộc về stack, compatibility, security, delivery và
  licensing trước khi bắt đầu lựa chọn tự động.
- Không đưa credential vào request. Chỉ cung cấp sau qua setup flow được project
  chấp nhận.

| Runtime | Cách gọi | Ranh giới khả dụng |
| --- | --- | --- |
| Claude Code | `/ak:bootstrap ...` | Phân phối native là mặc định; phân phối plugin rõ ràng cũng được hỗ trợ. Workflow có thể dùng toàn bộ collaboration surface Claude được hỗ trợ. |
| Cursor | `/ak:bootstrap ...` | Slash invocation theo cách gọi Engineer Skill do người dùng xác minh. Capability về Agent, plan và approval phụ thuộc surface Cursor đang hoạt động. |
| Codex | `$ak:bootstrap ...` | Native Skill discovery được hỗ trợ. Phase delegated hoặc parallel cần session Codex hiện tại cung cấp multi-agent capability tương ứng. |

Xem [Runtime adapter](../../../concepts/runtime-adapters) trước khi cho rằng mọi
runtime có cùng orchestration control.

Nếu không truyền cờ mode, Skill dùng `--auto`.

| Mode | Thay đổi điều gì | Hành vi phê duyệt |
| --- | --- | --- |
| `--auto` (mặc định) | Tự động research, chọn stack và design, rồi chuyển thẳng contract cho `ak:cook --auto` | Giữ opening contract gate và chỉ dừng tại authorization boundary (secret còn thiếu, hành động destructive/outward-facing chưa được duyệt, hoặc chi phí chưa được duyệt) |
| `--full` | Refine yêu cầu, rồi hỏi trước khi chọn tech stack và design nếu bạn chưa nêu sẵn preference | Hỏi về material decision còn thiếu ở từng bước đó; tiếp tục trong scope đã chấp nhận qua `ak:cook` |
| `--fast` | Chạy research, stack và design research trong một batch song song, không có design gate, rồi một plan gọn bên trong `ak:cook --fast` | Giữ opening contract cùng verification/safety gate bình thường của `ak:cook` |
| `--parallel` | Tạo dependency graph và giao ownership implementation không chồng lấn bên trong `ak:cook --parallel` | Giữ opening contract; chỉ hỏi về material decision còn thiếu |

`--ask` không phải một mode; nó chỉ đổi cách opening brainstorm gate đóng lại.
Nó kích hoạt `ak:advise` để phỏng vấn bạn từng câu một tới khi outcome, scope,
constraint, non-goal, acceptance criteria và definition of done được chốt và
bạn xác nhận, rồi tiếp tục theo mode đã chọn. Không có `--ask`, `--auto` tự
quyết từng khoảng trống từ prompt của bạn, project instructions và workspace
hiện có, ghi mỗi lựa chọn thành assumption; `--full`, `--fast` và `--parallel`
chỉ hỏi về quyết định có thể thay đổi đáng kể product hoặc safety.

`--yagni` kết hợp được với mọi mode. Flag này opt in vào việc challenge và cắt
scope không cần thiết cho outcome đã nêu; khi không có flag, Skill scaffold đầy
đủ scope được yêu cầu và không thêm phần việc ngoài yêu cầu. Flag được chuyển
tiếp tới `ak:cook` và `ak:code-review` để lựa chọn này tồn tại qua từng handoff.

`--ultra` kết hợp được với mọi mode, kể cả `--parallel`. Nó khiến phase code
review chạy `/ak:code-review codebase --ultra` (gồm cả review lại sau khi tăng
cường UX/AX), dùng best-of-5 candidate dispatch, verification và
evidence-validated union finalizer của code review. `ak:cook` và
`ak:enhance-ux-ax` vẫn chạy với flag phù hợp mode của chúng. Không kết hợp
`--ultra` với `codebase parallel` của code review — Skill đó coi đây là hard
stop.

## Mô tả project rõ ràng

Một request hữu ích gồm:

- **Outcome:** Nêu người dùng có thể làm gì khi project chạy.
- **Constraints:** Nêu technology, platform, compatibility, security rule và
  delivery boundary bắt buộc.
- **Non-goals:** Loại trừ feature gần kề không nên vào implementation đầu tiên.
- **Acceptance criteria:** Đưa ra phép kiểm tra quan sát được cho main path,
  failure behavior và edge case quan trọng.
- **Authority boundary:** Nêu có cho phép Git initialization, dependency
  installation, external research, asset generation, commit, publication hoặc
  deployment không.
- **Definition of done:** Nêu brief có nhắm tới live target (production, một
  store, một registry) không; project chỉ hoàn tất sau khi được release ở đó
  và được xác minh theo cách người dùng hoặc client thật sẽ tiếp cận.

Với ví dụ incident response, hãy nêu thêm ai được xem incident, event nào vào
audit log, "private" có nghĩa gì và validation nào chứng minh release đầu dùng
được.

## Hiểu workflow

1. **Skill khóa project contract.** Skill ghi nhận hoặc dùng lại outcome,
   constraint, non-goal, acceptance criteria và definition of done, đối chiếu
   từng surface project có (web, mobile, CLI, API, MCP, WebMCP, library) với
   `references/project-brief-checklist.md`.
2. **Skill kiểm tra trạng thái Git.** Skill kiểm tra destination thực tế và
   dùng lại project cùng branch convention hiện có thay vì scaffold lại hoặc
   reset; chỉ khởi tạo Git cho project mới khi brief yêu cầu.
3. **Skill research và chọn setup.** Độ sâu, parallelism và approval gate theo
   mode đã chọn.
4. **Skill tạo design evidence khi phù hợp.** Skill có thể tạo design guidance,
   wireframe, screenshot và generated asset qua design cùng media tool khả
   dụng. Project không có visual interface sẽ thiết kế interface contract
   (command, route, tool schema, public API) thay vào đó.
5. **Skill triển khai qua ak:cook.** Không có phase planning riêng; brainstorm
   contract cùng kết quả research, stack và design đi thẳng tới `ak:cook` với
   flag theo mode, và cook tự lập implementation plan cùng chạy test.
6. **Skill chạy code review.** `ak:code-review` review project mới
   (`--ultra` khi bootstrap nhận flag đó); blocking finding quay lại `ak:cook`
   với cùng mode flag tới khi review pass.
7. **Skill tăng cường UX và AX cho web surface.** Khi project có website hoặc
   web app, `ak:enhance-ux-ax --auto` chạy sau khi code review pass và thay
   đổi của nó được review theo cùng cách; bước này được bỏ qua và báo rõ với
   CLI, API, MCP server hoặc library.
8. **Skill release và xác minh live khi contract yêu cầu.** Khi contract đã
   chấp nhận có release hoặc nhắm tới live target, Skill cấp phát những gì
   brief cho phép, release qua pipeline và xác minh từng surface theo cách
   người dùng hoặc client thật sẽ tiếp cận. Nếu không, Skill báo project chỉ
   được xác minh local.
9. **Skill hoàn tất project handoff.** Skill đánh giá documentation, cập nhật
   plan state, hướng dẫn onboarding và báo changed file, check, risk cùng next
   action.

## Giữ quyền phê duyệt và an toàn ở bạn

<Callout type="warn" title="Mode tự động và parallel có thể đổi trạng thái repository">
  `--auto`, `--fast` và `--parallel` tiếp tục mà không dừng phê duyệt thường lệ
  khi opening contract đã khóa. Dùng `--full` hoặc `--ask` khi một quyết định
  cần review trước khi thực hiện.
</Callout>

Automatic execution không cấp authority ngoài scope. External research, asset
generation, dependency installation, credential use, commit, push,
publication và deployment vẫn phụ thuộc tool khả dụng cùng scope bạn đã duyệt.
Phase release và xác minh live chỉ chạy khi contract yêu cầu, và việc cấp
phát, staging, production release vẫn là các điểm phê duyệt riêng bên trong
phase đó.

Parallel mode cần exclusive file ownership và dependency rõ ràng. Worker hoặc
worktree riêng giúp giảm edit collision; chúng không phải operating-system
sandbox và không làm conflicting change tự động an toàn để merge.

## Xác minh kết quả

Một lần chạy hoàn tất nên cung cấp:

- Project chạy được và khớp outcome cùng non-goal đã chấp nhận.
- Quyết định stack cùng design được ghi trong documentation của project khi có
  ảnh hưởng lâu dài.
- Test thực và project check, với failure đã xử lý hoặc được báo rõ.
- Kết quả code review không che giấu critical finding.
- Với web surface, kết quả `ak:enhance-ux-ax` đối chiếu DONE contract của nó,
  hoặc ghi rõ project không có web surface.
- Bước onboarding cho phần configuration vẫn cần bạn thực hiện.
- Final report ngắn gọn với changed file, validation, remaining risk,
  definition of done cùng việc đã đạt hay chưa, và câu hỏi chưa giải quyết.

Xem generated wireframe hoặc passing build là bằng chứng trung gian. Project chỉ
hoàn tất khi acceptance criteria, test, review, tăng cường UX/AX (với web
surface) và onboarding path thống nhất.

## Xử lý sự cố hoặc tiếp tục

| Triệu chứng | Bước tiếp theo an toàn |
| --- | --- |
| Skill hỏi về product trước setup | Cung cấp outcome, constraint, non-goal hoặc acceptance criterion còn thiếu. Mọi mode đều giữ opening gate này. |
| Stack được chọn không đúng | Dừng trước approval, thêm compatibility hoặc delivery constraint còn thiếu rồi chạy lại quyết định liên quan. |
| Parallel work chồng lấn | Dừng writer, tách file ownership hoặc chạy tuần tự phase phụ thuộc rồi xác minh integrated tree. |
| Design hoặc external tool không khả dụng | Giữ limitation hiển thị và chọn local alternative được hỗ trợ hoặc bỏ output tùy chọn bằng quyết định rõ ràng. |
| Test thất bại gần cuối | Giữ failure hiển thị và quay lại implementation hoặc debugging; không đánh dấu scaffold hoàn tất. |
| Blocking finding của code review hoặc UX/AX sống sót qua ba lần fix | Dừng và báo cáo kèm bằng chứng thay vì tiếp tục vượt qua review hoặc enhancement gate. |
| Runtime không nhận diện Skill | Xác nhận target cùng scope, mở runtime session mới, rồi làm theo [Runtime không tìm thấy Skill hoặc Agent](../../../troubleshooting/runtime-cannot-find-skill-or-agent). |

Tiếp tục với [Cài đặt Kit](../../../guides/installing-kits),
[Engineer Kit](../../engineer) hoặc `ak:cook` khi project đã có implementation
scope được chấp nhận.

## Biết các giới hạn hiện tại

- Skill phụ thuộc planning, implementation, testing, review, design và media
  capability thực sự khả dụng trong runtime hiện tại.
- Dependency cùng asset tool có thể cần network access hoặc provider setup;
  workflow không thể tạo credential hay service availability còn thiếu.
- `--fast` giảm research overhead, không giảm implementation verification.
- `--parallel` chỉ hữu ích khi công việc tách được thành ownership độc lập.
- Tăng cường UX/AX và xác minh live chỉ chạy cho những surface và release
  target mà contract đã chấp nhận thực sự nêu ra.
