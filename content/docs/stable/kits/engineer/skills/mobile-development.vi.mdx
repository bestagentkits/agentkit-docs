Dùng `ak:mobile-development` để lập kế hoạch, triển khai, debug hoặc xác minh
mobile feature cho React Native, Flutter, iOS native với Swift/SwiftUI hoặc
Android native với Kotlin/Jetpack Compose. Skill nhấn mạnh constraint mobile:
màn hình nhỏ, network gián đoạn, tài nguyên device, platform convention, secure
storage, accessibility, real-device testing cùng staged release.

## Chọn một platform boundary

### Dùng ak:mobile-development khi

- Target là app iOS hoặc Android và framework đã rõ.
- Bạn cần quyết định native hay cross-platform dựa trên team, feature, device
  cùng maintenance constraint.
- Bạn triển khai offline sync, authentication, notification, deep link,
  accessibility, performance hoặc platform-specific capability.
- Bạn cần mobile debugging hoặc release-readiness workflow với device evidence.

### Chọn workflow khác khi

- Target là responsive website hoặc PWA thay vì mobile app được cài. Dùng
  `ak:frontend-development` hoặc `ak:web-frameworks`.
- Bạn cần product hoặc visual direction trước implementation. Dùng
  `ak:brainstorm` hoặc `ak:frontend-design`.
- Bạn tích hợp payment provider. Dùng `ak:payment-integration` cho provider
  contract đó cùng mobile SDK boundary.
- Bạn chỉ cần code review hoặc test độc lập. Dùng `ak:code-review` hoặc
  `ak:test`.

## Chuẩn bị toolchain, device và service

Trước khi bắt đầu:

- Hoàn thành [Làm quen](../../../getting-started/onboarding) và xác nhận
  Engineer Kit đã được cài cho runtime cùng scope hiện tại.
- Nêu chính xác một stack chính: React Native/Expo, Flutter, Swift/SwiftUI hoặc
  Kotlin/Compose. Đọc version framework, language, SDK, build tool, package
  manager cùng minimum OS đã cài từ project.
- Xác định device được hỗ trợ, screen class, accessibility need, offline
  behavior, data-conflict policy, background work, battery budget cùng
  performance target.
- Dùng development backend, test account, simulator/emulator fixture cùng
  physical device đã duyệt. Giữ signing key, certificate, provisioning profile,
  keystore, API token, push credential, user data cùng production log ngoài
  prompt, source control, screenshot và artifact không được bảo vệ.
- Nêu rõ có cho phép cài dependency, sinh native project, đổi pod hay Gradle,
  điều khiển device, network proxy, analytics/crash service, signing, store
  upload hoặc rollout không.

Reference đi kèm mô tả snapshot toolchain 2024–2025. Store SDK requirement,
framework version, device support, API, review rule cùng submission deadline
phải được xác minh với nguồn chính thức hiện tại.

| Runtime | Cách gọi | Ranh giới khả dụng |
| --- | --- | --- |
| Claude Code | `/ak:mobile-development ...` | Có thể sửa và chạy local tool khả dụng; quyền Xcode, Android, device, signing cùng store tùy host và quyền rõ ràng. |
| Cursor | `/ak:mobile-development ...` | Dùng slash syntax đã được người dùng xác minh; parity rộng hơn về Agent, Hook, device cùng IDE chưa được thiết lập. |
| Codex | `$ak:mobile-development ...` | Dùng native Skill discovery; Hook được chuyển đổi một phần và device/IDE capability tùy session. |

Xem [Runtime adapter](../../../concepts/runtime-adapters) để hiểu khác biệt theo
từng component.

## Chạy Skill

Argument shape được khai báo là `[platform] [feature]`. Bắt đầu bằng
`react-native`, `flutter`, `ios` hoặc `android`, rồi nêu OS/device matrix,
network behavior, test cùng release boundary được hỗ trợ.

## Quan sát các giai đoạn mobile

1. **Lần chạy xác minh stack và device matrix thực tế.** Skill đọc project
   version, native module, generated area, build variant cùng minimum OS support
   trước khi chọn pattern.
2. **Lần chạy xác định mobile state và constraint.** Touch, safe area, system
   navigation, permission, offline data, conflict, background work,
   accessibility, battery, memory cùng network behavior luôn rõ ràng.
3. **Lần chạy chọn architecture tương thích platform.** Skill giữ state,
   navigation, storage, dependency injection cùng native-module boundary của
   project thay vì đưa vào architecture tổng quát.
4. **Lần chạy triển khai feature slice nhỏ nhất.** Code, native config,
   localization, permission, migration cùng generated artifact nằm trong
   ownership boundary đã duyệt.
5. **Lần chạy xác minh tăng dần.** Static cùng unit check chạy trước, rồi tới
   emulator/simulator, physical device đã duyệt, constrained network,
   accessibility service, profiling cùng E2E theo yêu cầu.
6. **Lần chạy báo cáo release readiness.** Tệp đổi, package, permission,
   service, device coverage, measurement, signing need, store metadata cùng
   bước upload/rollout chưa làm được liệt kê.

## Giữ device, data, signing và store dưới quyền duyệt

<Callout type="warn" title="Mobile tooling đi qua nhiều trust boundary">
  Build và test có thể điều khiển device, cài hoặc gỡ app, capture screen cùng
  traffic, liên hệ analytics hay push service, dùng signing material và upload
  artifact. Xác nhận từng device, account, service cùng store action.
</Callout>

- Lệnh package, CocoaPods, Gradle, code generation cùng native build có thể chạy
  script, viết lại project file, tải toolchain lớn và tạo cache hay artifact
  đáng kể.
- Network proxy cùng crash/session-replay tool có thể capture token, user data,
  request body, screen và interaction. Dùng dữ liệu giả lập, redact log và xin
  duyệt privacy trước external telemetry.
- Lưu token trong Keychain, storage dựa trên KeyStore hoặc abstraction bảo mật
  đã duyệt của project. Đừng hardcode credential hay giả định biometric success
  tương đương backend authorization.
- Offline write cần behavior về durable identity, retry, conflict, deletion và
  rollback. Optimistic UI phải thể hiện unsynced cùng failed state.
- Real-device testing cần cho release confidence nhưng không cấp quyền dùng
  personal device, production account hay customer data thật.
- Signing, TestFlight/internal-track upload, phased rollout, store submission,
  production release cùng rollback cần phê duyệt riêng.

## Xác minh kết quả

Kết quả hoàn tất nên cung cấp:

- Platform, bằng chứng toolchain đã cài, minimum OS/device matrix cùng
  user-visible state contract.
- Chính xác tệp đổi, native configuration, permission, package, generated
  output, local schema, environment name cùng external service.
- Kết quả static, unit, component/widget, integration, E2E, accessibility,
  localization, permission, offline, conflict cùng recovery test tập trung.
- Bằng chứng launch, frame, memory, network, battery hoặc app size có thể so
  sánh khi performance nằm trong scope, đo trên environment cùng device đã nêu.
- Device coverage cùng gap, crash/log evidence đã loại dữ liệu nhạy cảm và xác
  nhận signing/upload/release không xảy ra trừ khi được cấp quyền.

## Xử lý sự cố hoặc tiếp tục

| Triệu chứng | Bước tiếp theo an toàn |
| --- | --- |
| Reference API hoặc build setting không có | Đọc SDK/framework đã cài cùng OS version được hỗ trợ, rồi dùng API tương thích của project hoặc lập kế hoạch upgrade riêng. |
| Chạy trên simulator nhưng lỗi trên device | Giữ device/OS/build evidence, kiểm tra permission, architecture, signing, network, memory cùng native log trước khi đổi code. |
| Offline data bị trùng hoặc mất | Dừng sync, giữ local cùng server record, kiểm tra ID, queue ordering, conflict/deletion policy và thêm deterministic recovery test. |
| Profiler hoặc proxy làm lộ dữ liệu nhạy cảm | Dừng capture, bảo vệ hoặc xóa artifact, rotate credential bị lộ, redact configuration và tiếp tục bằng dữ liệu giả lập. |
| Store validation từ chối build | Xác minh SDK, target API, privacy declaration, entitlement, permission, signing cùng metadata hiện tại mà không upload build khác tùy tiện. |
| Runtime không nhận diện Skill | Xác nhận target cùng scope, mở session mới, rồi làm theo [Runtime không tìm thấy Skill hoặc Agent](../../../troubleshooting/runtime-cannot-find-skill-or-agent). |

Tiếp tục với `ak:test` cho verification độc lập, `ak:devops` cho CI/CD workflow
được duyệt riêng hoặc [Tổng quan Engineer Kit](../../engineer) cho delivery được
điều phối.

## Biết các giới hạn hiện tại

- Framework comparison, adoption figure, performance percentage, budget, SDK
  requirement cùng store timeline trong source là guidance cũ, không phải
  guarantee hiện tại hay acceptance criteria phổ quát.
- Skill không chứa Xcode, Android Studio, SDK, emulator, device, developer
  account, signing identity, store credential hay device farm.
- Reference không chứng minh support cho mọi OS, device, architecture, native
  SDK, background mode, accessibility service hay store policy.
- Skill cung cấp pattern, không có mobile test suite, security audit, privacy
  review, crash service, build pipeline hay release monitor đi kèm.
- Stable và beta chứa nội dung Skill cùng resource giống nhau trong cặp release
  này. Diagnostic Codex Hook của beta không thay đổi workflow này.
