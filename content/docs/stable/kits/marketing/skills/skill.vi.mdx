Dùng `ak:skill` để tạo hoặc cải thiện Marketing Skill tái sử dụng trong project
hiện tại. Skill định tuyến một trong sáu action tới workflow tập trung, giữ
`SKILL.md` ngắn gọn bằng progressive disclosure và phân biệt planning cần review
trước với action sửa tệp trực tiếp.

## Chọn ak:skill cho task lifecycle của Skill

### Dùng ak:skill khi

- Bạn muốn tạo Marketing Skill từ mô tả, URL tài liệu hoặc source repository.
- Bạn cần thêm reference hay script vào Skill hiện có.
- Bạn muốn có optimization plan và review gate trước khi đổi Skill.
- Bạn cần sửa Skill từ tệp `logs.txt` ở project root.
- Bạn muốn lập plan cho Skill mới hoặc áp dụng content update có giới hạn.

### Chọn workflow khác khi

- Bạn vẫn cần chọn giữa Skill, Agent, command và workflow. Dùng
  `ak:kit-builder` để chọn component và tạo scaffold.
- Bạn cần install hay refresh Marketing Kit thay vì author nội dung project.
  Làm theo [Cài đặt Kit](../../../guides/installing-kits).
- Bạn chỉ cần đọc hoặc giải thích một Skill. Hãy yêu cầu analysis mà không chọn
  action có mutation.
- Bạn định sửa Skill ở user scope. Việc đó cần quyền riêng, rõ ràng; project
  scope là mặc định.

## Chuẩn bị target và bằng chứng

Trước khi bắt đầu:

- Xác nhận Marketing Kit đã được cài đúng runtime cùng scope hiện tại.
- Đọc instruction của repository và tìm project Skill directory.
- Giữ thay đổi không liên quan và nêu chính xác target Skill.
- Với `fix-logs`, kiểm tra `logs.txt` ở project root rồi loại secret hay dữ liệu
  cá nhân trước khi dùng.
- Với URL hay repository source, xác định ranh giới network, download và external
  tool được phép trước khi research.

| Runtime | Cách gọi | Ranh giới khả dụng |
| --- | --- | --- |
| Claude Code | `/ak:skill ...` | Chạy lifecycle workflow do Marketing sở hữu cùng authoring reference hướng Claude. |
| Cursor | `/ak:skill ...` | Dùng Skill đã được chuyển qua slash invocation; tool hay subagent được nêu vẫn phụ thuộc runtime đang hoạt động. |
| Codex | `$ak:skill ...` | Dùng native Skill discovery; đường dẫn hay capability riêng Claude là hướng dẫn, không phải tương đương Codex tự động. |

## Chạy Skill

Từ đầu tiên theo vị trí là action. Ví dụ này lập plan cho Skill mới và giữ
implementation sau một lần phê duyệt riêng:

### Chọn action có chủ đích

| Action | Input bắt buộc | Ranh giới mutation và review |
| --- | --- | --- |
| `add <skill-name> <ref-prompt>` | Skill hiện có và reference hoặc script cần thêm | Sửa project Skill sau khi giải quyết chi tiết còn thiếu. |
| `create <prompt-or-url>` | Mô tả, URL tài liệu hoặc repository source | Research khi cần rồi tạo project Skill; network và cài tool cần phê duyệt. |
| `fix-logs [skill-name]` | `logs.txt` ở project root cùng target tùy chọn | Chẩn đoán lỗi đã ghi rồi chỉ sửa project Skill được cấp quyền. |
| `optimize <skill-name> [prompt]` | Skill hiện có và constraint tùy chọn | Đề xuất plan, xin review, ghi plan đã duyệt rồi hỏi lại trước implementation. |
| `plan <skill-name> [prompt]` | Tên Skill mới và outcome mong muốn | Tạo implementation plan cần review trước; duyệt lưu plan không phải duyệt implement. |
| `update <skill-name> [prompt]` | Skill hiện có và thay đổi được yêu cầu | Áp dụng update trực tiếp có giới hạn; dùng `optimize` nếu cần plan gate trước. |

Chỉ sáu action này được public Skill contract định tuyến. Đừng dựa vào internal
reference không được liệt kê như một action được hỗ trợ khác.

## Hiểu các giai đoạn

1. **Parse action và target.** Skill hỏi phần quan trọng còn thiếu thay vì đoán
   tên Skill hay scope.
2. **Tải reference tương ứng.** Mỗi action có rule riêng cho research, review,
   output và mutation.
3. **Kiểm tra project scope.** `SKILL.md`, reference, script, instruction của
   repository và log liên quan được đọc trước khi thay đổi.
4. **Chỉ research theo quyền đã cấp.** Tra tài liệu hoặc phân tích repository có
   thể dùng network và external tool; update local đơn giản không ngầm cho phép
   crawl rộng.
5. **Lập plan hoặc sửa theo action.** `plan` và `optimize` thêm review gate.
   `add`, `create`, `fix-logs` và `update` có thể đi tới thay đổi project file đã
   được cấp quyền.
6. **Xác minh progressive disclosure.** Entry file giữ ngắn gọn còn hướng dẫn
   chi tiết và deterministic helper chuyển vào resource tập trung.
7. **Báo cáo bằng chứng và quyền còn thiếu.** Lần chạy liệt kê đường dẫn, check,
   rủi ro chưa xử lý cùng bước Git hay distribution chưa được duyệt.

## Kiểm soát research và mutation

<Callout type="warn" title="Project scope là quyền mặc định">
  Đừng sửa Skill ở user scope trừ khi người dùng cấp quyền rõ ràng cho scope và
  target chính xác đó. URL hay GitHub source có thể dẫn tới network access,
  repository summarization hoặc yêu cầu cài helper; hãy duyệt riêng các tác động
  đó. Không đặt credential, private source hay dữ liệu cá nhân vào tệp Skill,
  plan, log hoặc report.
</Callout>

Phê duyệt planning có hai ranh giới: duyệt proposal cho phép workflow lưu plan đã
nêu; implementation chỉ bắt đầu sau xác nhận implementation riêng. Commit, push,
package export, publication hay release về sau cũng là quyết định riêng.

## Xác minh output và bằng chứng

Một lần chạy hoàn tất nên cung cấp:

- Action đã chọn, target Skill, project scope và non-goal đã chấp nhận.
- Tệp chính xác được tạo hoặc thay đổi, gồm reference hay script mới.
- `SKILL.md` ngắn gọn với description nêu khi nào Skill nên được kích hoạt.
- Bằng chứng tệp được tham chiếu tồn tại và script có test đại diện hoặc lý do
  được ghi rõ khi chưa chạy.
- Với `plan` hoặc `optimize`, vị trí plan đã duyệt, phase file, success criteria,
  rủi ro và trạng thái implementation.
- Tóm tắt diff cuối cùng với câu hỏi chưa giải quyết cùng mọi external action
  hay distribution action chưa được duyệt.

## Xử lý sự cố và tôn trọng giới hạn

| Triệu chứng | Bước tiếp theo an toàn |
| --- | --- |
| Thiếu action hoặc argument | Cung cấp một action được hỗ trợ và target project Skill chính xác. |
| `logs.txt` chứa secret hay lỗi không liên quan | Dừng, redact dữ liệu nhạy cảm và thu hẹp bằng chứng trước `fix-logs`. |
| URL research mở rộng vượt target | Nêu lại domain, link, tệp và quyền network/tool được phép. |
| Lần chạy bắt đầu sửa trong `plan` hoặc trước khi optimization được duyệt | Dừng và quay lại review gate; duyệt plan và duyệt implementation là riêng biệt. |
| Skill không được discovery sau khi sửa | Xác nhận đường dẫn, runtime, scope và mở session mới với [Runtime không tìm thấy Skill hoặc Agent](../../../troubleshooting/runtime-cannot-find-skill-or-agent). |

Các action reference trong package chủ yếu hướng Claude và có thể nêu tool,
Agent hay đường dẫn không có ở runtime khác. Workflow không thể chứng minh source
bên ngoài đầy đủ, cài tool khi chưa được duyệt hay tự đưa project Skill vào
Marketing package đã phát hành. Tiếp tục với [Marketing Kit](../../marketing)
hoặc dùng `ak:kit-builder` cho component không phải Skill.
