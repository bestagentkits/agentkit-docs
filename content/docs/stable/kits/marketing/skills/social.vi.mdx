Dùng `ak:social` để tạo post, thread, carousel, story hoặc reel theo platform,
hoặc lập schedule theo tuần, tháng hay campaign. Skill có reference workflow
cho provider API, nhưng scheduling script đi kèm chỉ preview queued post; việc
publish thực cần integration riêng.

## Chọn ak:social cho draft và plan sẵn sàng theo channel

### Dùng ak:social khi

- Bạn có audience, message, proof, brand voice, channel và CTA đã duyệt.
- Bạn cần content cho `twitter`/`x`, `linkedin`, `instagram`, `tiktok`,
  `youtube`, `facebook` hoặc `threads`.
- Bạn cần draft `post`, `thread`, `carousel`, `story` hoặc `reel`.
- Bạn cần `schedule` theo tuần, tháng hoặc campaign có tên.

### Chọn workflow khác khi

- Bạn vẫn cần positioning, content pillar hoặc campaign strategy.
- Bạn cần phản hồi community management đang hoạt động có yếu tố safety,
  moderation, legal hoặc crisis escalation.
- Bạn muốn assistant authorize OAuth, chi tiền, publish, delete, comment,
  repost hoặc đổi account đang hoạt động. Đó là external action riêng.

## Chuẩn bị content và authority input

Xác nhận Marketing Kit đã được cài cho đúng runtime và scope. Cung cấp target
platform, content type, audience, objective, claim đã xác minh, brand rule, CTA,
media path, account owner, timezone, campaign date và output có phải draft-only
hay không. Với schedule, cung cấp content inventory hoặc topic thực cùng
capacity của team.

Policy, format, disclosure rule, quota và API version hiện tại của platform có
thể khác reference đi kèm. Xác minh với tài liệu provider chính thức trước
approval hoặc implementation.

| Runtime | Cách gọi | Ranh giới khả dụng |
| --- | --- | --- |
| Claude Code | `/ak:social ...` | Phân phối native là mặc định; provider action vẫn cần credential đã cấu hình và approval rõ ràng. |
| Cursor | `/ak:social ...` | Skill được projection sang Cursor và cách gọi bằng slash đã được người dùng xác minh; không ngụ ý account đã kết nối. |
| Codex | `$ak:social ...` | Skill dùng native discovery của Codex; drafting cục bộ được hỗ trợ không chứng minh provider API parity. |

Input canonical có dạng `[platform] [type] OR [schedule]`. Route schedule nhận
`week`, `month` hoặc `campaign [name]`.

## Hiểu các giai đoạn

1. **Xác nhận channel và objective.** Ghi platform, content type, audience,
   action mong muốn, source evidence và account boundary.
2. **Nạp brand context.** Áp dụng voice, terminology, visual direction,
   prohibited claim và disclosure requirement đã duyệt.
3. **Soạn theo platform.** Cấu trúc loại post được yêu cầu và đề xuất hashtag,
   hook, CTA cùng media treatment mà không giả định hiệu suất.
4. **Validate artifact.** Validator đi kèm có thể kiểm tra rule về text và media
   được nhúng cho platform hỗ trợ; check có thể cũ và không phải provider
   acceptance.
5. **Lập timing khi được yêu cầu.** `schedule` tạo markdown schedule và calendar
   artifact. `schedule-post.js` đi kèm in preview và nêu rõ actual posting cần
   API integration.
6. **Trả evidence và approval.** Báo file, source, validation warning, thời gian
   đề xuất, timezone và mọi external action còn chờ.

## Giữ provider effect sau gate riêng

<Callout type="warn" title="API example có thể thay đổi account đang hoạt động">
  Provider reference workflow gồm OAuth scope và write call có thể upload media,
  publish post, reply, comment hoặc repost. Không chạy chúng từ yêu cầu drafting.
  Xác nhận chính xác account, content, visibility, credential, provider contract
  hiện tại và human approval ngay trước bất kỳ external call nào.
</Callout>

Không để token lộ trong prompt, log hoặc content artifact. Review privacy,
copyright, endorsement, sponsorship và AI-content disclosure, community rule
cùng moderation risk. Unified API service có thể phát sinh chi phí và thêm data
processor; duyệt riêng quan hệ provider đó.

## Xác minh output và bằng chứng

Draft thông thường được ghi vào `assets/posts/{platform}/{date}-{slug}.md`.
Route `schedule` ghi `assets/posts/schedule-{period}.md` và có thể thêm
`assets/posts/calendar-{period}.md`.

Kết quả hoàn chỉnh xác định platform, content type, source, brand rule, media,
timezone, thời gian đề xuất, validator version hoặc assumption và publish
status. Với provider action thực, yêu cầu platform post ID hoặc URL được trả về
và kiểm tra kết quả live; preview “scheduled” cục bộ không chứng minh đã remote
schedule hoặc publish.

## Xử lý sự cố và biết giới hạn

| Triệu chứng | Bước tiếp theo an toàn |
| --- | --- |
| Platform limit hoặc format xung đột provider | Xem tài liệu chính thức và API response hiện tại của provider là nguồn chuẩn. |
| Scheduler báo `pending` | Đây là local preview object, không phải remote state; cấu hình và duyệt integration riêng nếu cần. |
| Media validation pass nhưng upload fail | Kiểm tra account hiện tại, MIME type, size, duration, provider permission và API response. |
| Có token hoặc rate-limit error | Dừng call lặp lại, bảo vệ token, theo hướng dẫn recovery của provider và không đoán retry limit. |
| Draft có claim thiếu bằng chứng hoặc trend giả | Xóa hoặc gắn evidence hiện tại trước approval. |
| Runtime discovery thất bại | Làm theo [Runtime không tìm thấy Skill hoặc Agent](../../../troubleshooting/runtime-cannot-find-skill-or-agent). |

Skill không thể bảo đảm reach, engagement, virality, conversion, provider
acceptance hay dữ liệu platform đi kèm còn hiện hành. Tiếp tục với [tổng quan
Marketing Kit](../../marketing), đồng thời giữ mọi tác động lên account live
trong workflow được cấp quyền riêng.
