Dùng `ak:test` để biến một thay đổi hoặc câu hỏi về chất lượng thành bằng chứng
validation mới. Skill có thể chạy unit, integration, end-to-end, build, coverage
và UI check dựa trên browser. Skill cũng có thể tạo test suite bao phủ, optimize
suite cùng chi phí CI, hoặc audit suite để tìm test yếu. Các rule
test-principles của Skill chi phối scope, layer, environment và cách thực thi
cho mọi operation; hãy tải chúng trước khi thiết kế hoặc thay đổi test.

## Chọn ak:test khi kết quả cần có là validation

### Dùng ak:test khi

- Bạn cần bằng chứng test tập trung hoặc rộng sau khi triển khai hay sửa bug.
- Project cần validation type, lint, build hoặc coverage trước khi bàn giao.
- Landing page, form hoặc website khác cần check visual, responsive,
  accessibility, form hay console.
- Bạn cần QA report có cấu trúc, test suite mới, CI optimization an toàn hơn
  hoặc test audit có bằng chứng.

### Chọn workflow khác khi

- Một test fail cần chẩn đoán root cause và sửa. Dùng [`ak:debug`](./debug),
  rồi [`ak:fix`](./fix).
- Bạn muốn triển khai kèm giai đoạn test. Dùng [`ak:cook`](./cook).
- Bạn cần thiết kế delivery plan thay vì thực thi validation. Dùng
  [`ak:plan`](./plan).
- Bạn không kiểm soát target site hoặc thiếu quyền cho automated browsing,
  protected route, submit form hay tạo load.

## Chuẩn bị test surface

Trước khi bắt đầu:

- Hoàn tất [Onboarding](../../../getting-started/onboarding) và xác nhận
  Marketing Kit đã được cài cho runtime cùng scope bạn đang dùng.
- Mở project và cung cấp thay đổi, requirement, vùng đang fail hoặc test scope
  dùng để quyết định command.
- Giữ sẵn test runner, dependency, fixture, biến môi trường và build tooling của
  project.
- Với UI testing, cung cấp URL được cấp quyền, ưu tiên staging hoặc dữ liệu
  fixture, và nêu form nào được phép submit hay account state nào được phép
  thay đổi.
- Với protected UI route, chọn test authentication project-native hoặc tự đăng
  nhập thủ công. Giữ credential ngoài prompt, screenshot và report.

| Runtime | Cách gọi | Ranh giới khả dụng |
| --- | --- | --- |
| Claude Code | `/ak:test ...` | Phân phối native là mặc định; phân phối plugin rõ ràng cũng được hỗ trợ. |
| Cursor | `/ak:test ...` | Cách gọi bằng slash đã được người dùng xác minh. Điều này không thiết lập runtime parity đầy đủ. |
| Codex | `$ak:test ...` | Skill dùng discovery native của Codex; không suy ra parity rộng hơn cho Hook và statusline. |

## Chọn operation

Skill nhận `[context]`, `ui [url]` hoặc `create|optimize|audit [scope]`. Nếu bạn
cung cấp scope, Skill tiến hành validation code liên quan. Khi không có argument,
Skill hỏi bạn muốn chạy operation nào. Dùng `ui <url>` để chọn trực tiếp browser
workflow, hoặc bắt đầu bằng `create`, `optimize` hay `audit` để làm việc với
chính test suite.

| Operation | Nội dung bao phủ | Input hữu ích |
| --- | --- | --- |
| Kiểm thử code (mặc định) | Type hoặc syntax check, unit, integration, end-to-end, coverage và production build | Behavior đã đổi, module bị ảnh hưởng, command bắt buộc và threshold của project |
| `ui <url> [options]` | Page discovery, screenshot, responsive behavior, accessibility, form, console error và user flow | URL được cấp quyền, tùy chọn `--headless`, `--mobile` hoặc `--auth`, viewport và ranh giới data safety |
| `create [scope]` | Scout code cùng docs, lập coverage matrix, rồi tạo hoặc mở rộng test suite | Feature hoặc workflow cần bao phủ, framework hiện có và critical path |
| `optimize [scope]` | Phân tích CI/CD, git history, code cùng docs, rồi giảm thời gian và chi phí test mà không mất coverage | Job chậm, bằng chứng CI timing, group quan trọng về safety và workflow change được phép |
| `audit [scope]` | Tìm test deceptive, disabled, unfinished, ineffective, redundant, outdated hoặc unsafe và báo cáo finding đã xếp hạng kèm đề xuất sửa | Scope suite hoặc CI, lo ngại về độ tin cậy và skip đã biết |

Với `create`, `optimize` và `audit`, thêm `--advice` để dùng checkpoint tư vấn
của `kongming` hoặc `--interview` để duyệt từng proposed change group trước khi
edit. `--ultra` chạy năm analysis candidate read-only độc lập trong một parallel
wave với một verifier: `create` và `optimize` chọn nguyên vẹn một design thắng
cuộc, còn `audit` trả về union finding đã được xác minh bằng bằng chứng và
deduplicate. Các flag có thể kết hợp với nhau. Khi không có `--interview`,
`create` và `optimize` áp dụng thay đổi trực tiếp và báo cáo đầy đủ change list;
`audit` báo cáo finding và chỉ sửa khi bạn yêu cầu thêm việc sửa.

```text
/ak:test create "Cover the newsletter signup workflow" --interview
/ak:test optimize "Reduce pull-request CI time" --advice
/ak:test audit "Check skipped and ineffective form tests" --ultra
```

Command và coverage threshold do project định nghĩa được ưu tiên. Khi project
không định nghĩa threshold, Skill báo cáo coverage thực tế cùng behavior quan
trọng còn thiếu thay vì tự đặt một ngưỡng phần trăm.

## Dùng impact selection và các mode semantic tùy chọn

Với repository có test-impact manifest đáng tin cậy, `optimize` dùng
[`ak test optimize --base <ref> --json`](../../../reference/cli/test/optimize) để lập kế hoạch chọn các nhóm check theo
thứ hạng một cách tất định, kèm lý do chọn hoặc bỏ qua. Việc lập kế hoạch là
read-only. `--run` thực thi các lệnh thuộc repository đã được chọn, và đây không
phải sandbox; `--output <new-file>` lưu kết quả cục bộ. Khi không chắc chắn, phạm
vi chọn được mở rộng về phía full suite đã khai báo, các nhóm bắt buộc và policy
check vẫn phải chạy, và policy mapping chưa được giải quyết sẽ chặn việc thực
thi. Đường này không liên hệ provider semantic nào.

Các mode semantic chỉ chạy khi opt in, và Skill không bao giờ suy ra consent từ
một key có sẵn trong môi trường. Với grant tường minh cho consumer `test-impact`,
`--semantic shadow` giữ nguyên baseline có hiệu lực, còn `--semantic advisory`
chỉ có thể thêm check hoặc mở rộng phạm vi chọn. Mode semantic đã được cấp quyền
có thể gửi dữ kiện ngắn gọn tới provider bên ngoài và phát sinh chi phí.
[`ak test classify-e2e`](../../../reference/cli/test/classify-e2e) cần grant riêng và không bao giờ thay đổi lịch chạy E2E
hay class manifest. Với UI testing, một thử nghiệm shadow
[`ak eval ui`](../../../reference/cli/eval/ui) được yêu cầu, có grant tường minh `ui-regression`, có
thể thêm tín hiệu regression từ bằng chứng đã quan sát; nó không bao giờ biến một
lỗi thành đạt hay thay đổi kết quả UI test.

## Hiểu điều gì xảy ra trong một lần chạy

1. **Skill xác định scope.** Skill nối thay đổi gần đây hoặc requirement với
   validation surface nhỏ nhất hữu ích, ở layer thấp nhất đáng tin cậy.
2. **Skill chạy check liên quan hẹp nhất trước.** Type check hoặc build check
   chạy khi chúng bao phủ contract bị ảnh hưởng.
3. **Skill thực thi các suite đã chọn** và phân tích kết quả, tập trung vào test
   fail, flaky, chậm và bị skip.
4. **Skill đo coverage khi phù hợp** và chỉ ra critical path, error handler cùng
   nhánh edge case chưa được bao phủ.
5. **Skill kiểm tra UI khi được chọn.** Skill dùng
   [`ak:agent-browser`](./agent-browser) hoặc browser test project-native, tổ
   chức test plan, lưu screenshot trong một report directory, và có thể chia các
   check page, form, navigation, user flow, accessibility, responsive layout,
   performance, security và SEO cho các subagent `tester` chạy song song.
6. **Skill tạo report.** Skill trả kết quả ngắn gọn cho lần chạy nhỏ hoặc ghi
   report có cấu trúc vào vị trí report của repository.

## Giữ tác động của test trong tầm kiểm soát

<Callout type="warn" title="Test đã fail thì vẫn là fail">
  Skill không bỏ qua test fail và không dùng mock, skip hay thủ thuật khác để
  làm build trông như đạt. Skill báo cáo lỗi và chuyển việc tìm root cause sang
  debugging và fixing.
</Callout>

- Test command có thể tạo file coverage, screenshot, build output, dữ liệu tạm
  hoặc browser state. Hãy nêu vị trí artifact được phép và yêu cầu dọn dẹp.
- Mutation spot-check của `create` hoặc `audit` sửa code đang được test một lần
  để chứng minh test fail trước một bug hợp lý, rồi revert lại.
- UI flow và end-to-end test có thể submit form hoặc thay đổi dữ liệu nếu ứng
  dụng hoạt động như vậy. Hãy chạy chúng trên test environment an toàn.
- Operation UI không triển khai fix. Việc tìm root cause của sản phẩm thuộc về
  `ak:debug` và `ak:fix`.

## Xác minh report

Một kết quả hoàn chỉnh nên cung cấp:

- Scope chính xác và mọi command đã chạy.
- Tổng số test pass, fail, skip, cùng thời lượng.
- Mọi test fail kèm error message và stack trace liên quan.
- Giá trị coverage cùng file hoặc function cụ thể chưa được bao phủ khi có yêu
  cầu coverage.
- Build status, warning và vấn đề dependency khi có build verification.
- Page UI đã test, đường dẫn screenshot, console error và viewport đã check hoặc
  bị bỏ qua.
- Critical issue, recommendation đã xếp ưu tiên và câu hỏi chưa giải quyết.

Chỉ coi lần chạy là đạt khi các check được yêu cầu báo không có lỗi, build thoát
thành công nếu có build, và threshold của project được đáp ứng. Một check chạy
một phần hoặc bị skip chỉ chứng minh surface thực sự đã chạy.

## Xử lý sự cố hoặc tiếp tục

| Triệu chứng | Bước tiếp theo an toàn |
| --- | --- |
| Không cung cấp test scope | Chọn operation khi được hỏi, rồi nêu thay đổi, requirement hoặc URL. |
| Test bị flaky | Chạy lại suite bị ảnh hưởng nhỏ nhất, kiểm tra timing và shared state, rồi báo cáo tính không tất định thay vì lấy trung bình. |
| Protected route redirect tới login | Dùng auth setup project-native hoặc đăng nhập thủ công, không paste credential vào prompt. |
| Browser tool không khả dụng | Chạy UI test project-native nếu có và báo cáo screenshot, interaction hoặc accessibility check vẫn chưa được xác minh. |
| Screenshot chứa dữ liệu nhạy cảm | Không publish hay commit; redact hoặc capture lại với fixture an toàn. |
| Runtime không nhận diện Skill | Xác nhận target cùng scope, mở runtime session mới, rồi làm theo [Runtime không tìm thấy Skill hoặc Agent](../../../troubleshooting/runtime-cannot-find-skill-or-agent). |

Chuyển lỗi cho `ak:debug` và `ak:fix`, hoặc tiếp tục với `ak:git` sau khi
validation được yêu cầu đã đạt.

## Biết giới hạn hiện tại

- Skill bị giới hạn trong test runner, browser, credential, URL và environment
  khả dụng ở session hiện tại.
- Hướng dẫn của Skill cũng nhắc tới `ak:chrome-profile` và `ak:web-testing`.
  Package Marketing Kit cho Claude Code không bao gồm các Skill đó, vì vậy hãy
  dùng `ak:agent-browser` hoặc browser test project-native trừ khi chúng được
  cài từ nguồn khác.
- Tỷ lệ coverage không chứng minh behavior nằm ngoài assertion hoặc điều kiện
  runtime đã được chạy.
- Cách gọi Cursor bằng slash là bằng chứng do người dùng xác minh, không phải
  bằng chứng về runtime parity đầy đủ.
