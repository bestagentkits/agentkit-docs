Use `ak:content-marketing` to structure a content program before production. It
can map content pillars and topic clusters, build an editorial calendar, plan a
blog post, audit an inventory, or design a repurposing workflow from evidence
you provide.

## Choose ak:content-marketing for program-level decisions

### Use ak:content-marketing when

- You need a content strategy tied to an audience and business objective.
- You need owners, statuses, channels, keywords, or dates organized in an
  editorial calendar.
- You need a keep, update, consolidate, redirect, or delete recommendation for
  an existing inventory.
- You want a brief or cluster map before asking another Skill to draft assets.

### Choose another workflow when

- You only need one piece of copy. Use `ak:write` with a bounded brief.
- You need keyword evidence or a technical search audit. Use `ak:seo` first.
- You need to send email, publish social posts, redirect URLs, delete pages, or
  change a production CMS. This Skill plans those actions but does not grant
  authority to perform them.

## Prepare useful inputs

Confirm Marketing Kit is installed for the current runtime and scope. Provide
the objective, audience evidence, approved brand voice, channels, content
inventory, current performance data, constraints, owners, review stages, and
the time period you actually control. Mark assumptions and missing data.

For an audit, provide source URLs or files plus the metrics you want considered.
For a calendar, provide real capacity and approval lead time. The bundled
frequency examples are templates, not required cadence or performance promises.

| Runtime | Invocation | Availability boundary |
| --- | --- | --- |
| Claude Code | `/ak:content-marketing ...` | Native delivery is the default; explicit plugin delivery is also supported. |
| Cursor | `/ak:content-marketing ...` | The Skill is projected to Cursor and slash invocation is user-verified; broader runtime parity is not implied. |
| Codex | `$ak:content-marketing ...` | The Skill uses native Codex discovery; Marketing Hook coverage remains capability-specific. |

The canonical input shape is `[content-type] [topic]`. Name the desired artifact
and decision boundary instead of asking for a generic content plan.

## Understand the stages

1. **Frame the program.** Confirm audience, goals, buyer-journey stage,
   channels, constraints, and available evidence.
2. **Audit the current state.** Review inventory, traffic, engagement,
   conversion, search health, freshness, accuracy, and brand alignment when the
   required data exists.
3. **Choose pillars and clusters.** Connect a small set of core themes to
   audience needs, business goals, and keyword evidence.
4. **Design the workflow.** Define content types, briefs, owners, statuses,
   review gates, distribution choices, and repurposing paths.
5. **Build the calendar or report.** Place approved work into a practical time
   period and attach measures that can be observed later.
6. **Review before execution.** A person approves claims, priorities, owners,
   redirects, deletions, paid distribution, and publication.

## Keep strategy separate from external action

<Callout type="warn" title="A calendar is not publishing authority">
  A `Scheduled` or `Published` status in a template is planning data. The Skill
  does not authorize a CMS write, URL redirect, deletion, audience contact,
  media spend, or platform account change. Approve and execute those actions in
  their own controlled workflow.
</Callout>

Use current, attributable evidence for customer claims, case-study results,
comparisons, and search metrics. Brand voice should guide tone and terminology;
it must not be used to invent proof. Review legal, privacy, accessibility,
copyright, and channel requirements before production or distribution.

## Verify outputs and evidence

Depending on the request, expect a strategy document, pillar and cluster map,
editorial calendar, content brief, repurposing map, or audit report. The audit
workflow organizes reports under
`assets/reports/content/{date}-{content-type}-audit.md`.

A useful result names the input sources, separates evidence from assumptions,
records owners and statuses, defines measurable success signals, and identifies
every action still awaiting approval. Audit recommendations should include the
item, issue, action, priority, and supporting metric rather than only a score.

## Troubleshoot and know the limits

| Symptom | Safe next step |
| --- | --- |
| The plan feels generic | Add audience evidence, business objective, current inventory, channel constraints, and real capacity. |
| The Skill proposes unsupported claims | Remove them or attach a source and uncertainty note before drafting. |
| Audit metrics are missing | Label the affected recommendation qualitative; do not fabricate traffic, ranking, conversion, or revenue data. |
| The cadence is unrealistic | Replace template frequency with the team's actual production and review capacity. |
| A redirect or deletion is recommended | Preview the affected URLs, dependencies, analytics, and recovery path in a separate approved workflow. |
| Runtime discovery fails | Follow [Runtime cannot find a Skill or Agent](../../../troubleshooting/runtime-cannot-find-skill-or-agent). |

The frameworks organize decisions; they do not guarantee traffic, rankings,
engagement, leads, or sales. Continue with the [Marketing Kit
overview](../../marketing), use `ak:write` for approved copy, or use `ak:seo`
when search evidence is the missing input.
