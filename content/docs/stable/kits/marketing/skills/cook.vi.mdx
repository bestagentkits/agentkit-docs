Dùng `ak:cook` trong Marketing Kit để triển khai task kỹ thuật rõ ràng hoặc
implementation plan đã duyệt trong project hiện tại. Skill scout codebase, tạo
hoặc tải plan, thay đổi tệp, kiểm thử kết quả theo mặc định và yêu cầu code
review trước khi hoàn tất.

Đây là workflow delivery code dù được resolve qua Marketing Kit. Hãy dùng
Marketing domain Skill cho campaign strategy, copy, audience research hoặc
creative production; dùng `ak:cook` khi deliverable là implementation như
component landing page, tích hợp analytics hoặc thay đổi code automation.

## Chọn ak:cook khi scope kỹ thuật đã sẵn sàng

### Dùng ak:cook khi

- Behavior code, constraint, non-goal và acceptance criteria đã biết.
- Bạn có plan đã duyệt và muốn thực thi theo bằng chứng project hiện tại.
- Bề mặt marketing cần feature kỹ thuật hoặc refactor có test và code review.
- Bạn chấp nhận chỉnh sửa workspace đúng scope và lệnh validation.

### Chọn workflow khác khi

- Outcome marketing hoặc cách tiếp cận chưa rõ. Bắt đầu với
  [`ak:brainstorm`](./brainstorm).
- Bạn cần implementation plan hoặc CRO plan do Marketing sở hữu mà chưa
  implementation. Dùng [`ak:plan`](./plan).
- Bạn có bug hoặc check thất bại cụ thể. Dùng [`ak:fix`](./fix), workflow chứng
  minh root cause trước khi đổi code.
- Bạn cần tư vấn không mutation workspace. Dùng [`ak:ask`](./ask).
- Deliverable là campaign content hoặc marketing asset thay vì code. Chọn
  domain Skill phù hợp trong [Marketing Kit](../../marketing).

## Chuẩn bị project và ranh giới quyền hạn

Trước khi bắt đầu:

- Hoàn thành [Làm quen](../../../getting-started/onboarding) và xác nhận
  Marketing Kit đã cài cho đúng runtime cùng scope.
- Mở project nơi assistant được phép sửa tệp và chạy check.
- Giữ công việc không liên quan và nêu rõ tệp, module cùng public contract.
- Cung cấp requirement cụ thể hoặc path plan đã duyệt.
- Đọc instruction repository và nêu Git, network call, provider account,
  publication, deployment cùng sensitive data có nằm ngoài lần chạy hay không.

| Runtime | Cách gọi | Ranh giới khả dụng |
| --- | --- | --- |
| Claude Code | `/ak:cook ...` | Delivery native là mặc định; plugin rõ ràng cũng được hỗ trợ. |
| Cursor | `/ak:cook ...` | Cách gọi slash đã được người dùng xác minh; không chứng minh Claude parity đầy đủ. |
| Codex | `$ak:cook ...` | Dùng discovery Skill native của Codex; Hook chỉ được projection một phần và không có statusline Marketing. |

### Chọn mode thực thi có chủ đích

| Input hoặc flag | Hiệu ứng | Vẫn bắt buộc |
| --- | --- | --- |
| Không có mode flag hoặc `--interactive` | Workflow đầy đủ với review gate của con người | Opening contract, plan, implementation, testing, review và finalization |
| Path plan đã duyệt | Tải plan hiện có và bỏ bước tạo plan mới | Bằng chứng project hiện tại, implementation, testing và review |
| `--fast` | Bỏ research và chuyển từ scout sang plan ngắn | Vẫn có plan trước code, testing và review |
| `--parallel` | Cho phép phase độc lập chạy đồng thời | Dependency rõ ràng và ownership tệp không chồng lấn |
| `--auto` | Bỏ các lần dừng review thường lệ | Test, code review, security policy và escalation khi blocker chưa xử lý |
| `--no-test` | Bỏ giai đoạn testing | Code review bắt buộc và cảnh báo rõ thiếu bằng chứng test |
| `--tdd` | Thêm behavior tests-first trong từng phase phù hợp | Base mode đã chọn và completion gate |
| `--advice` | Thêm checkpoint tư vấn `kongming` với routing theo host: Fable 5 cho Claude subscription, `gpt-5.6-sol` với effort high cho Codex và `claude-fable-5-high` cho Cursor | Advice không implement, duyệt hay mở rộng quyền hạn |

Đừng dùng `--auto` hoặc `--no-test` để vượt qua quyết định thiếu, check thất bại
hay side effect.

## Mô tả công việc kỹ thuật chính xác

Cung cấp năm thành phần:

- **Outcome:** Behavior người dùng hoặc hệ thống cần implementation.
- **Constraints:** Pattern hiện có, rule consent và privacy, compatibility,
  module cùng tool phải giữ.
- **Non-goals:** Công việc campaign, analytics, content hoặc infrastructure gần
  kề bị loại trừ.
- **Acceptance criteria:** Behavior quan sát được, error case, test và
  repository check.
- **Authority boundary:** Git, network/provider access, live account,
  publication, deployment, spend hoặc destructive action có bị loại trừ không.

## Hiểu các giai đoạn delivery

1. **Ghi nhận hoặc dùng lại contract.** Workflow ghi outcome, constraint,
   non-goal và acceptance criteria.
2. **Phát hiện mode.** Flag rõ ràng được ưu tiên; path plan chọn thực thi plan;
   mặc định là interactive.
3. **Scout project.** Skill tìm stack, tệp liên quan, pattern, test, tài liệu,
   plan và public contract.
4. **Research và plan.** Research chạy khi mode yêu cầu. Plan đã review tồn tại
   trước implementation, kể cả trong `--fast`.
5. **Triển khai scope đã duyệt.** Công việc theo thứ tự plan và convention
   project hiện tại. Làm song song cần ownership tệp rõ ràng.
6. **Đơn giản hóa khi có tín hiệu.** Live diff lớn có thể kích hoạt pass
   simplification đúng scope mà không đổi behavior.
7. **Test và review.** Test chạy trừ khi chọn `--no-test`. Code review bắt buộc
   mọi mode và kiểm tra acceptance, regression, public contract, pattern project
   cùng lỗi repository.
8. **Hoàn tất bằng chứng.** Workflow đối chiếu plan state, đánh giá docs impact,
   báo cáo tệp và check, rồi chỉ vào Git workflow qua phê duyệt riêng.

## Tách phê duyệt khỏi hiệu ứng bên ngoài

<Callout type="warn" title="Automation không mở rộng quyền hạn">
  `--auto` có thể bỏ lần dừng thường lệ nhưng không cấp quyền truy cập secret,
  phát sinh chi phí, thay đổi marketing platform hay live account, publication,
  liên hệ audience, commit, push, pull request, deployment, destructive action
  hoặc chấp nhận regression. Duyệt riêng từng hiệu ứng bên ngoài.
</Callout>

Nếu test hoặc review phát hiện regression, public contract đổi hay side effect,
workflow nên dừng và hiển thị lỗi, nguyên nhân cùng lựa chọn có scope. Đừng che
bằng chứng bằng `--no-test`, `--auto` hay force operation.

## Xác minh output và bằng chứng

Lần chạy hoàn tất nên cung cấp:

- Implementation diff đúng scope và theo pattern hiện có.
- Test được thêm hoặc cập nhật cùng command và kết quả mới, trừ khi chủ động
  chọn `--no-test`.
- Phát hiện code review và cách xử lý mọi blocker hoặc warning.
- Bằng chứng cho từng acceptance criterion và blast-radius check.
- Tiến độ plan được cập nhật khi lần chạy dùng plan.
- Báo cáo cuối nêu tệp đã đổi, check, rủi ro còn lại và phê duyệt vẫn cần.

Implementation chưa hoàn tất chỉ vì tệp đã đổi. Test và repository check liên
quan phải pass, review không còn blocker và bạn chấp nhận diff. Với `--no-test`,
hãy ghi rõ thiếu functional test evidence.

## Xử lý sự cố lần chạy

| Triệu chứng | Bước tiếp theo an toàn |
| --- | --- |
| Runtime không tìm thấy `ak:cook` | Xác nhận target và scope, khởi động lại runtime, rồi làm theo [Runtime không tìm thấy Skill hoặc Agent](../../../troubleshooting/runtime-cannot-find-skill-or-agent). |
| Skill route task campaign content vào code delivery | Dừng và chọn Marketing domain Skill; `ak:cook` là technical implementation. |
| Skill hỏi để làm rõ | Bổ sung outcome, constraint, non-goal, acceptance criterion hoặc quyết định quyền hạn. |
| Review gate dừng lần chạy | Review bằng chứng hiện tại, yêu cầu sửa, duyệt stage có scope tiếp theo hoặc dừng. |
| Test hoặc review phát hiện regression | Giữ lỗi hiển thị và chọn sửa, lập lại plan, giữ compatibility hoặc dừng. |
| Tệp ngoài scope bị đổi | Dừng, kiểm tra diff, giữ công việc không liên quan và đọc [Projects, artifacts và checkpoints](../../../concepts/projects-artifacts-checkpoints). |
| Planning hoặc Agent surface được tham chiếu không khả dụng | Báo dependency thiếu và không giả lập kết quả phê duyệt hay verification. Runtime projection không đảm bảo mọi dependency nội bộ đều gọi được. |

## Biết giới hạn hiện tại

- Source workflow hướng đến code và implementation; Marketing Kit không biến
  nó thành campaign executor tổng quát.
- Skill chỉ dùng được tool, credential, project access và validation command có
  trong session.
- Runtime projection phụ thuộc capability nên Agent delegation, Hook, task
  tracking và UI có thể khác.
- Workflow không đảm bảo conversion, revenue, campaign performance, provider
  behavior hay deployment success.
- Stable và beta có source content cùng invocation `ak:cook` giống nhau.

Tiếp tục với [`ak:plan`](./plan) để chuẩn bị công việc, [`ak:fix`](./fix) cho
defect cụ thể hoặc [Tổng quan Marketing Kit](../../marketing) cho domain workflow.
