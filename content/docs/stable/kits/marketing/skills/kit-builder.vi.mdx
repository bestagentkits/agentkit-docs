Dùng `ak:kit-builder` để chọn và tạo scaffold cho Skill, Agent, command hoặc
workflow của Marketing automation. Skill cung cấp guide tập trung, template và
trình khởi tạo Python; bạn vẫn sở hữu contract của component, đường dẫn được tạo,
đăng ký package, kiểm thử và review.

## Chọn ak:kit-builder cho cấu trúc component

### Dùng ak:kit-builder khi

- Bạn cần quyết định kiến thức tái sử dụng thuộc về Skill, autonomous handler
  thuộc về Agent, user action thuộc về command hay quy trình nhiều bước thuộc về
  workflow.
- Bạn muốn scaffold ở project scope với placeholder và section chuẩn.
- Bạn đang mở rộng Marketing automation và cần guide hoặc template riêng cho
  từng loại component.
- Bạn muốn review cấu trúc trước khi điền instruction theo domain.

### Chọn workflow khác khi

- Bạn chỉ cần create, add, optimize, fix, plan hoặc update một Marketing Skill.
  Dùng `ak:skill`, workflow sở hữu lifecycle đó.
- Bạn cần install, refresh, audit hoặc remove Marketing Kit. Dùng lifecycle của
  AgentKit CLI trong [Cài đặt Kit](../../../guides/installing-kits).
- Bạn cần bản nháp dùng một lần thay vì runtime component tái sử dụng.
- Bạn đã sẵn sàng publish hay phân phối component. Skill này tạo scaffold tệp;
  nó không duyệt package export, commit, push, release hay deploy.

## Chuẩn bị project và runtime

Trước khi bắt đầu:

- Hoàn thành [Làm quen](../../../getting-started/onboarding) và xác nhận
  Marketing Kit đã được cài đúng runtime cùng scope hiện tại.
- Mở project nơi bạn được phép tạo hoặc thay thế tệp component.
- Đọc instruction của repository và kiểm tra tên component hiện có trước khi
  chọn target.
- Chuẩn bị Python nếu trình khởi tạo sẽ tạo scaffold.
- Chọn loại component và tên lowercase-hyphenated.

| Runtime | Cách gọi | Lần chạy có thể làm gì |
| --- | --- | --- |
| Claude Code | `/ak:kit-builder ...` | Tải authoring guide trong package và có thể tạo tệp project hướng Claude sau khi được duyệt. |
| Cursor | `/ak:kit-builder ...` | Dùng Skill đã được chuyển qua slash invocation; đường dẫn component được tạo vẫn theo source Marketing. |
| Codex | `$ak:kit-builder ...` | Dùng native Skill discovery; không tự biến scaffold hướng Claude thành package export native của Codex. |

Xem [Runtime adapter](../../../concepts/runtime-adapters) trước khi giả định
component được tạo có discovery hay activation giống nhau ở mọi nơi.

## Chạy Skill

Yêu cầu trực tiếp loại component và tên. Ví dụ này yêu cầu xem trước trước khi
tạo bất kỳ tệp nào:

<Tabs items={['Claude Code', 'Cursor', 'Codex']}>
  <Tab value="Claude Code">

```text
/ak:kit-builder skill campaign-brief — preview the destination and files before creating them
```

  </Tab>
  <Tab value="Cursor">

```text
/ak:kit-builder skill campaign-brief — preview the destination and files before creating them
```

  </Tab>
  <Tab value="Codex">

```text
$ak:kit-builder skill campaign-brief — preview the destination and files before creating them
```

  </Tab>

Mặc định, Skill scaffold đầy đủ scope được yêu cầu và không thêm phần việc ngoài
yêu cầu. Thêm `--yagni` để challenge và cắt component scope không cần thiết cho
outcome đã nêu.

### Chọn component có chủ đích

| Loại | Đích scaffold mặc định | Dùng cho |
| --- | --- | --- |
| `skill` | `.claude/skills/<name>/SKILL.md` cùng `references/` và `scripts/` | Instruction, reference và deterministic helper có thể tái sử dụng |
| `agent` | `.claude/agents/<name>.md` | Subagent chuyên biệt với trigger, process và output có giới hạn |
| `command` | `.claude/commands/<name>.md` hoặc đường dẫn lồng nhau cho tên có dấu hai chấm | User action hướng Claude |
| `workflow` | `.claude/workflows/<name>.md` | Quy trình nhiều phase với assignment, gate và output |

Trình khởi tạo nhận `python scripts/init_component.py <type> <name>` và tùy chọn
`--path <output-dir>`. Xem lần gọi script đó là chi tiết implementation của Skill,
không phải lệnh AgentKit CLI.

## Hiểu các giai đoạn

1. **Phân loại outcome tái sử dụng.** Skill phân biệt domain knowledge,
   autonomous handler, user action và process orchestration.
2. **Kiểm tra target.** Skill kiểm tra tên hiện có rồi tải guide cùng template
   tương ứng trước khi đề xuất đích.
3. **Review kế hoạch scaffold.** Bạn xác nhận loại, tên, đường dẫn, placeholder
   và việc target hiện có có thể bị thay thế hay không.
4. **Tạo tệp project.** Trình khởi tạo tạo directory đã chọn và ghi skeleton của
   component.
5. **Điền contract.** Thay mọi placeholder bằng trigger, bước, quality gate,
   output, reference hoặc script đúng với component.
6. **Xác minh discovery và behavior.** Test component trong runtime dự kiến, rồi
   review riêng mọi thay đổi package manifest hay distribution.

## Giữ mutation và phê duyệt rõ ràng

<Callout type="warn" title="Scaffold là một repository mutation">
  Trình khởi tạo ghi tệp và có thể thay thế target hiện có cùng tên. Hãy kiểm tra
  đích và diff trước. Việc tạo scaffold không cấp quyền sửa `kit.yaml`, cài
  dependency, truy cập network, commit, push, publish hay deploy.
</Callout>

Template là điểm bắt đầu, không phải bằng chứng component đã được export hay hoạt
động. Marketing Kit hiện dùng Skills làm bề mặt gọi cho người dùng và không có
command catalog. Vì vậy, tệp `.claude/commands/` được tạo không trở thành
Marketing command đã phát hành nếu thiếu thiết kế package và review riêng.

## Xác minh output và bằng chứng

Một lần chạy hoàn tất nên cung cấp:

- Loại component đã chọn và lý do nó phù hợp hơn các lựa chọn khác.
- Đường dẫn chính xác đã tạo hoặc thay đổi cùng nội dung hiện có được giữ lại.
- Scaffold không còn placeholder chưa giải thích trong component hoàn chỉnh.
- Reference hoặc script chỉ khi chúng cải thiện progressive disclosure hay làm
  deterministic step có thể tái tạo.
- Check dùng để xác nhận syntax, runtime discovery, happy path và failure path
  đại diện.
- Danh sách riêng các hành động package, Git, publication hoặc deployment vẫn
  cần phê duyệt.

## Xử lý sự cố và tôn trọng giới hạn

| Triệu chứng | Bước tiếp theo an toàn |
| --- | --- |
| Đã chọn sai loại component | Dừng trước khi ghi và so sánh lại ranh giới của bốn loại. |
| Target đã tồn tại | Kiểm tra nội dung cùng diff; chọn tên mới hoặc duyệt update có giới hạn thay vì ghi đè mù quáng. |
| Không có Python hoặc trình khởi tạo | Dùng template trong package theo cách thủ công và báo rằng deterministic initialization đã bị bỏ qua. |
| Scaffold không được discovery | Xác nhận runtime, scope, đích và việc mở session mới với [Runtime không tìm thấy Skill hoặc Agent](../../../troubleshooting/runtime-cannot-find-skill-or-agent). |
| Scaffold tồn tại nhưng không thuộc Kit đã phát hành | Review package export riêng; việc tạo tệp không tự sửa resolved catalog. |

Các guide hướng Claude và có một số pattern component lịch sử. Chúng không thiết
lập cross-runtime parity, public command catalog hay distribution tự động. Tiếp
tục với [Marketing Kit](../../marketing) hoặc dùng `ak:skill` khi component mong
muốn chính là một Skill.
