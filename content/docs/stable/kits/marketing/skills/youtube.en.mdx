Use `ak:youtube` to extract an authorized video's content and repurpose it into
one of three bounded deliverables: a blog post, an infographic pack, or a set of
social drafts. The Skill routes the selected subcommand, uses VidCap.xyz when
the workflow needs video metadata, captions, summaries, screenshots, or
comments, and keeps the source URL attached to the result.

## Choose ak:youtube for repurposing

### Use ak:youtube when

- You have a YouTube URL and permission to use the source material.
- You want `blog`, `infographic`, or `social` output derived from that video.
- You need captions, timestamps, screenshots, or comments as evidence for a
  draft.
- You can review quotations, claims, attribution, brand voice, and platform
  fit before release.

### Choose another workflow when

- You need to create a new video, script, or storyboard. Use `ak:video`.
- You only need a thumbnail. Use `ak:youtube-thumbnail-design`.
- You need general channel strategy, upload management, or live analytics. The
  routed surface here is content repurposing, not channel administration.
- You do not have the rights or consent needed to download, quote, transform,
  or redistribute the source.

## Prepare the source and provider access

Before you start:

- Complete [Onboarding](../../../getting-started/onboarding), and confirm
  Marketing Kit is installed for the current runtime and scope.
- Supply a valid YouTube video URL and the desired `blog`, `infographic`, or
  `social` subcommand.
- Confirm that the video, transcript, frames, comments, music, likenesses, and
  other included material may be processed for your intended use.
- Make `VIDCAP_API_KEY` available if the VidCap-backed extraction path is used.
- Allow outbound network requests to `https://vidcap.xyz/api/v1`; the bundled
  client authenticates with the `X-API-Key` header.
- Ensure Python can run the bundled client with `requests` and `python-dotenv`
  when the workflow calls it directly.
- Choose a writable project where the generated Markdown, HTML, PNG, and JSON
  assets may be created.

| Runtime | Invocation | Availability boundary |
| --- | --- | --- |
| Claude Code | `/ak:youtube ...` | Native delivery is the default; explicit plugin delivery is also supported. Provider calls still require the local credential and network access. |
| Cursor | `/ak:youtube ...` | Slash invocation is user-verified. This does not establish identical tool, browser, or Hook behavior across Cursor setups. |
| Codex | `$ak:youtube ...` | The Skill uses native Codex discovery. Hook projection is partial and does not change VidCap requirements. |

See [Runtime adapters](../../../concepts/runtime-adapters) before assuming
component-level parity.

### Select a routed output

| Subcommand | Intended result | Packaged output convention |
| --- | --- | --- |
| `blog` | Long-form article draft with source attribution, metadata, headings, takeaways, and CTA | `assets/articles/{date}-{slug}.md` |
| `infographic` | Infographic source, visual export, and supporting data | `assets/infographic/{date}-{slug}.html`, `.png`, and `.json` |
| `social` | Platform-specific social drafts plus an optional combined pack | `assets/posts/{platform}/{date}-{slug}.md` and `assets/posts/{date}-{slug}-all-platforms.md` |

The first word is the router. Operations such as `caption`, `comments`, `info`,
`summary`, and `screenshot` belong to the bundled VidCap client used inside the
workflow; they are not additional top-level `ak:youtube` subcommands.

## Follow the repurposing stages

1. **Confirm the brief.** The Skill identifies the routed output, source URL,
   audience, voice, platforms, desired attribution, and authority boundary.
2. **Extract source evidence.** The workflow can request metadata, captions,
   summaries, screenshots, or comments through VidCap. Availability depends on
   the video and provider response.
3. **Select usable material.** It organizes key points, timestamps, quotations,
   statistics, frames, and audience reactions without treating them as verified
   claims by default.
4. **Create the selected draft.** The `blog`, `infographic`, or `social`
   reference shapes the artifact and its normal output path.
5. **Review content and visuals.** Check transcript accuracy, quote context,
   source attribution, brand consistency, readable exports, and claims that
   need independent support.
6. **Stop at the approved boundary.** The Skill presents files and evidence.
   Uploading, posting, scheduling, or changing an account remains a separate
   action.

## Keep rights, approvals, and external effects explicit

<Callout type="warn" title="A source URL is not permission">
  Only process, download, quote, transform, and redistribute material you are
  allowed to use. Obtain consent before reusing a person's likeness, voice, or
  private information, and review platform terms plus applicable copyright,
  publicity, privacy, and advertising requirements.
</Callout>

| Work category | Normal boundary |
| --- | --- |
| Guidance and drafting | The Skill may analyze supplied evidence and create local draft files. Review every claim and quotation. |
| Local mutations | Output directories and artifact files may be created or replaced in the chosen project. Confirm the destination and preserve unrelated work. |
| Provider and network effects | VidCap requests send the source URL and requested processing options to an external service. API availability, model behavior, quotas, and charges are controlled by that provider. |
| Publishing and account effects | The workflow does not by itself authorize uploading, posting, scheduling, changing metadata, responding to comments, or modifying a YouTube or social account. |

Do not place API keys in prompts, source content, frontmatter, or generated
files. Keep credentials in the runtime's approved secret mechanism.

## Review outputs and evidence

A useful run should leave you with:

- The requested Markdown, HTML, PNG, or JSON files at the reported paths.
- The original YouTube URL and enough timestamps or transcript context to trace
  important statements.
- Clear separation between source facts, viewer comments, generated summaries,
  and new marketing interpretation.
- A list of missing captions, unavailable frames, uncertain quotations, or
  claims that require another source.
- A short report naming provider operations performed, files created, review
  results, and any external action still awaiting approval.

For an infographic, inspect both the browser-rendered visual and its source
data. For social output, re-check current platform limits before posting. For a
blog, verify direct quotes against the transcript or original video instead of
trusting the generated article alone.

## Troubleshoot safely

| Symptom | Safe next step |
| --- | --- |
| Runtime does not recognize `ak:youtube` | Confirm target and scope, start a fresh session, then follow [Runtime cannot find a Skill or Agent](../../../troubleshooting/runtime-cannot-find-skill-or-agent). |
| The Skill cannot route the request | Put exactly one of `blog`, `infographic`, or `social` first, then provide the URL. |
| `VIDCAP_API_KEY not set` appears | Add the key through the approved local secret mechanism; do not paste it into the prompt or commit it. |
| VidCap returns an HTTP error or times out | Keep the partial evidence, report the status, and retry later or use authorized source material supplied locally. Do not invent missing transcript or comment data. |
| Captions, comments, or screenshots are absent | Treat that input as unavailable. Ask for a transcript or source assets instead of inferring exact quotes or frames. |
| Output contains an unsupported claim | Remove or qualify it, trace it to the video, and obtain an independent source when the claim needs verification. |
| Files appear outside the intended folder | Stop, inspect the diff, and preserve unrelated work. Review [Projects, artifacts, and checkpoints](../../../concepts/projects-artifacts-checkpoints). |

Continue with the [Marketing Kit overview](../../marketing), or use
[Installing kits](../../../guides/installing-kits) for discovery and lifecycle
help.

## Know the current limits

- The packaged router exposes only `blog`, `infographic`, and `social`.
- VidCap is an external dependency. Private, removed, region-restricted,
  age-gated, captionless, or otherwise unsupported videos may not yield the
  expected evidence.
- AI summaries and article conversions can omit context or introduce errors;
  comments are audience statements, not verified facts.
- Model selection, provider limits, availability, latency, and cost can change
  outside AgentKit. The Skill does not promise a particular model or result.
- Generated drafts do not guarantee search ranking, engagement, conversion, or
  platform acceptance.
- Runtime projection is capability-specific; browser, image-generation, and
  supporting Skill availability can differ even when invocation succeeds.
