Dùng `ak:agentkit` khi task trải qua nhiều bước hoặc domain, Skill đã cài phù
hợp chưa rõ hoặc công việc cần sequence ngắn với verification theo risk. Skill
này là router: phân loại, chọn và dispatch. Skill cùng Agent được định tuyến sở
hữu domain work.

## Chỉ chọn ak:agentkit khi routing có giá trị

### Dùng ak:agentkit khi

- Request mơ hồ, nhiều bước, nhiều domain hoặc rủi ro cao.
- Nhiều Skill đã cài có thể áp dụng và thứ tự của chúng quan trọng.
- Bạn cần quyết định specialist có fresh context hoặc independent reviewer có
  cải thiện kết quả không.
- Bạn muốn route record cùng completion gate rõ trước execution.

### Bỏ qua ak:agentkit khi

- Bạn đã nêu Skill cần dùng. Gọi trực tiếp Skill đó.
- Một Skill đã cài rõ ràng sở hữu task một bước.
- Request chỉ là hội thoại, ý kiến hoặc câu hỏi fact.
- Bạn cần headless job qua nhiều CLI hay worktree, hoặc team nhiều session được
  điều phối. Chúng thuộc capability Engineer riêng khi được cài.
- Capability chưa được cài. Không route tới Skill hoặc Agent tưởng tượng.

## Chuẩn bị inventory đã cài

Trước khi bắt đầu:

- Hoàn thành [Làm quen](../../../getting-started/onboarding), cài Marketing Kit
  và mở session mới sau installation.
- Nêu final deliverable, constraint, non-goal, acceptance criteria và authority
  boundary.
- Kiểm kê Skill cùng Agent thực sự hiển thị cho runtime hiện tại. Description đã
  cài, không phải catalog ghi nhớ, là routing authority.
- Ghi link có risk cao nhất: effect user-visible, credential, data, money,
  destructive, public-contract, deployment hoặc mass-audience làm tăng yêu cầu
  verification.
- Xác định request chỉ routing hay cho phép execution sau khi route được chọn.

| Runtime | Cách gọi | Ranh giới khả dụng |
| --- | --- | --- |
| Claude Code | `/ak:agentkit ...` | Skill có thể kiểm kê Skill hiển thị cùng Agent type khả dụng. Delegation dùng Agent capability cùng permission hiện tại của Claude Code. |
| Cursor | `/ak:agentkit ...` | Cách gọi bằng slash đã được người dùng xác minh. Skill routing có thể dùng capability hiển thị, nhưng packaged source không thiết lập contract Agent dispatch Cursor tương đương. |
| Codex | `$ak:agentkit ...` | Skill discovery là native. Packaged Agent dispatch yêu cầu AgentKit Codex Agent runtime local đã đăng ký; nếu không, công việc ở inline và phải báo gap. |

Xem [Runtime adapter](../../../concepts/runtime-adapters) trước khi giả định
runtime parity.

## Theo các giai đoạn routing

1. **Áp dụng proportionality gate.** Dùng trực tiếp Skill đã nêu hoặc rõ ràng;
   trả lời câu hỏi trivial mà không thêm routing ceremony.
2. **Phân loại công việc.** Ghi một workflow class, size, risk cùng domain count,
   chọn class của final deliverable.
3. **Kiểm kê capability đã cài.** Xác nhận mọi Skill cùng Agent candidate tồn tại
   trong runtime hiện tại. Làm inline hoặc báo gap khi không có.
4. **Tạo chain ngắn nhất.** Chọn một primary owner cho mỗi intent và dùng subset
   của understand → decide → execute → verify → deliver. Mỗi link cần entry cùng
   exit evidence đã nêu.
5. **Chỉ delegate tại trigger.** Dùng specialist cho noisy discovery, independent
   work, testing, high-risk review hoặc repeated failure. Parallel work cần
   ownership tách biệt.
6. **Thực thi risk gate và báo cáo.** Low risk dùng executor check; elevated risk
   thêm verification cùng self-review; high risk thêm independent review cùng
   confirmation rõ trước irreversible action.

Chain dài hơn nên truyền artifact path cùng report ngắn thay vì prose summary bị
mất thông tin. Link thất bại không được advance: diagnose hoặc rescope rồi tiếp
tục tại link đó. Hai lần thất bại liên tiếp trên cùng link nên dừng với input
nhỏ nhất còn thiếu.

## Tách routing khỏi authority

<Callout type="warn" title="Route không thể cấp permission mới">
  Chọn Skill, Agent hoặc automatic sequence không cấp quyền secret access,
  external call, account change, spending, publication, deployment, destructive
  operation hoặc mass-audience contact. Link high-risk cần independent review
  cùng confirmation rõ của bạn trước irreversible step.
</Callout>

Subagent chỉ nhận delegation contract. Mỗi dispatch nên nêu một outcome, file
hoặc source cần đọc, modification được phép, acceptance criteria, constraint,
report location cùng completion status. Session điều khiển giữ conflict
resolution, approval và final acceptance.

## Xác minh routing evidence

Route hoàn tất nên cung cấp:

- `Route: <class> | size: <size> | risk: <risk> | domains: <n>`.
- Skill hoặc Agent đã cài sở hữu mỗi link.
- Entry evidence, output artifact và exit check cho mỗi link.
- Delegation timing cùng ownership tách biệt khi dùng Agent.
- Verification và reviewer gate khớp effect có risk cao nhất.
- Record link đã chạy, artifact đã tạo, check đã hoàn tất, gap và action vẫn chờ
  approval.

## Xử lý sự cố và hiểu giới hạn

| Triệu chứng | Bước tiếp theo an toàn |
| --- | --- |
| Route nêu capability còn thiếu | Kiểm kê lại session hiện tại, bỏ link không tồn tại rồi làm inline hoặc báo gap. |
| Chain dài hơn deliverable cần | Collapse link không tạo reusable artifact và không bỏ verification bắt buộc. |
| Agent không khả dụng | Giữ công việc inline và nêu dispatch capability thiếu; không giả delegation. |
| Hai link cố sửa cùng file | Chạy tuần tự dưới một owner hoặc tách ownership trước mọi parallel work. |
| Cùng link thất bại hai lần | Dừng, giữ evidence và yêu cầu input nhỏ nhất còn thiếu thay vì replay cùng prompt. |
| Route high-risk tới publish, spend, data hoặc deployment | Yêu cầu verification, independent review cùng approval rõ trước khi tiếp tục. |

Router chỉ biết capability discoverable trong active installation. Router không
đảm bảo mọi runtime expose Agent tool, Hook hoặc parallel behavior tương đương.
Tiếp tục với [Marketing Agent](../agents) để hiểu ranh giới role đi kèm và
[tổng quan Marketing Kit](../../marketing) cho workflow do con người kiểm soát.
