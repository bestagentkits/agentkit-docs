Dùng `ak:referral-program-building` để thiết kế customer referral loop cho SaaS
hoặc digital product. Skill bao phủ reward model, provider selection,
attribution, technical implementation sketch, fraud control, email draft và
measurement. Skill cũng có thể review program hiện có và đề xuất experiment có
giới hạn.

Skill tạo strategy cùng implementation blueprint. Skill không làm schema sẵn
sàng cho production, thay đổi product, cài tracking, thu thập personal data, gửi
email, phát reward, mua provider hay launch program nếu chưa có authorization
và implementation review riêng.

## Chọn ak:referral-program-building cho customer referral

### Dùng ak:referral-program-building khi

- Bạn cần so sánh one-sided, two-sided, tiered, milestone, product-credit,
  discount, cash, gift hoặc status-based reward với economics hiện tại.
- Bạn cần quyết định build-versus-buy cùng integration requirement cho referral
  provider.
- Bạn cần blueprint cho referral code, link, attribution, reward state hoặc
  dashboard.
- Bạn cần fraud review, reward delay, manual approval, fulfillment email cùng
  program measurement flow.
- Bạn muốn cải thiện refer-a-friend experience hiện có bằng cohort và funnel
  evidence được cung cấp.

### Chọn workflow khác khi

- Bạn cần chương trình affiliate, creator, KOL/KOC hoặc agency có compensation.
  Dùng [`ak:affiliate-marketing`](./affiliate-marketing).
- Bạn cần launch hay campaign plan xoay quanh referral mechanic đã duyệt. Dùng
  [`ak:launch-strategy`](./launch-strategy) hoặc [`ak:campaign`](./campaign).
- Bạn chỉ cần implementation plan cho product change đã duyệt. Hãy chuyển
  referral contract đã review sang engineering workflow phù hợp.
- Bạn chưa biết reward cost, margin, qualifying conversion, refund handling hay
  customer eligibility. Hãy xử lý economics trước.

## Chuẩn bị program và data contract

Cung cấp product cùng user journey, referrer và referee đủ điều kiện,
qualifying event, reward type cùng cost, currency, cap, refund hoặc reversal
rule, attribution window, consent cùng notice requirement, target surface, data
model hiện có, email policy, fraud-review owner, fulfillment process, budget
ceiling và success measure.

Ví dụ provider lịch sử gồm Rewardful, ReferralCandy, Viral Loops,
FirstPromoter và Voucherify. Xác minh price, feature, integration, security,
contract cùng data-processing term hiện tại trước khi chọn hoặc mua provider.

| Runtime | Cách gọi | Ranh giới khả dụng |

| Cursor | `/ak:referral-program-building ...` | Cách gọi slash đã được người dùng xác minh. Điều này không chứng minh parity cho provider hay automation. |
| Codex | `$ak:referral-program-building ...` | Hỗ trợ native Skill discovery. Hook chỉ được projection một phần và integration vẫn tách biệt. |

## Đi qua các giai đoạn referral program

1. **Xác định program.** Xác nhận participant, qualifying event, reward ở mỗi
   phía, cap, exclusion, attribution, refund cùng reversal behavior, budget,
   owner và non-goal.
2. **Mô hình hóa reward economics.** So sánh reward type cùng milestone bằng
   margin, service cost, liability, redemption, fulfillment, tax, provider fee
   và fraud exposure hiện tại. Giữ amount như scenario cho đến khi được duyệt.
3. **Chọn requirement cho build hoặc provider.** Map payment, product, CRM,
   email, analytics, webhook, mobile, reporting, accessibility, security và
   privacy need. Dùng current primary evidence cho mọi buying recommendation.
4. **Thiết kế technical contract.** Xác định code creation, referral link,
   attribution, state, idempotency, reversal, cap, audit record, dashboard và
   failure handling. Chỉ coi bundled schema cùng endpoint example là starting
   sketch.
5. **Thêm abuse và review control.** Xác định self-referral, velocity,
   duplicate, payment, refund, device hay network signal, manual review, appeal,
   reward delay và false-positive handling.
6. **Chuẩn bị communication và launch.** Soạn introduction, progress, reminder
   cùng fulfillment message; test end to end; chỉ soft-launch sau khi có
   product, data, finance, legal, support và go/no-go approval.
7. **Đo lường và iterate.** Ghi participation, referred conversion, reward cost,
   fulfillment, refund, fraud, customer quality cùng incremental value bằng
   definition và comparison period rõ ràng.

## Review technical sketch trong package

Reference của Skill đề xuất các bề mặt minh họa chính xác sau:

| Bề mặt | Tên canonical trong sketch |
| --- | --- |
| User field | `id`, `email`, `referral_code`, `referred_by_id`, `created_at` |
| Referral field | `id`, `referrer_id`, `referee_id`, `status`, `reward_amount`, `conversion_timestamp`, `created_at` |
| Click field | `id`, `referral_code`, `ip_address`, `device_fingerprint`, `click_timestamp`, `converted` |
| Generate | `POST /api/referrals/generate` → `referral_code`, `referral_url`, `share_urls` |
| Liệt kê cho user | `GET /api/users/:id/referrals` → `referrals` và `stats` với `total`, `converted`, `pending` |
| Apply code | `POST /api/referrals/apply` với `referral_code` và `email` → `success`, `message`, `discount_applied` |
| Convert | `POST /api/referrals/:id/convert` → `success`, `reward_issued` |

<Callout type="warn" title="Reference schema không phải production contract">
  Sketch lưu email, IP address và device fingerprint, đồng thời dùng ví dụ state
  cùng attribution đơn giản. Trước implementation, review authentication,
  authorization, consent, minimization, encryption, retention, deletion,
  idempotency, race condition, reward liability, abuse, accessibility, audit,
  observability, regional rule và recovery. Không copy SQL hay JavaScript trực
  tiếp vào live system.
</Callout>

Reference cũng cho thấy pattern cookie, UTM, subdomain, deep link và mobile
attribution. Behavior provider cùng platform thay đổi; xác minh mechanism đã
chọn và có privacy cùng engineering approval trước khi thu thập hay lưu signal.

## Tách riêng tác động product, data, email và payout

| Tác động được đề xuất | Ranh giới phê duyệt |
| --- | --- |
| Thay đổi database, API, UI, cookie hoặc mobile | Yêu cầu engineering plan đã duyệt, security cùng privacy review, test, migration và rollback strategy cùng product sign-off. |
| Thu thập IP, device, email hoặc referral event | Duyệt lawful basis, notice, field được phép, access, retention, deletion, vendor flow và false-positive handling. |
| Email hoặc in-product message | Duyệt audience, trigger, consent, sender, claim, amount, frequency, opt-out và support path trước khi gửi. |
| Tạo hoặc fulfill reward | Duyệt eligibility, amount, currency, cap, tax, refund cùng reversal, accounting, payment authority và dispute handling. |
| Mua hoặc integrate vendor | Duyệt current price, contract, credential, data processing, access scope, operational owner và exit plan. |

## Review output và bằng chứng

Report path canonical là
`assets/reports/performance/{date}-referral-program.md` khi dùng quy ước
asset-organizing trong package. Kết quả hoàn tất nên gồm program rule cùng
economics, provider requirement, technical contract, câu hỏi threat cùng
privacy review, message draft, rollout gate, metric definition, source system,
approval owner và quyết định chưa xử lý.

Không trình bày conversion, retention, cost, growth hay ROI example lịch sử như
kết quả dự kiến. Với program hiện có, giữ query definition, date range, cohort
selection, reward status, refund và data gap cùng report.

## Xử lý sự cố an toàn

| Triệu chứng | Bước tiếp theo an toàn |
| --- | --- |
| Runtime không nhận diện `ak:referral-program-building` | Xác nhận target và scope Marketing Kit, khởi động lại runtime, rồi làm theo [Runtime không tìm thấy Skill hoặc Agent](../../../troubleshooting/runtime-cannot-find-skill-or-agent). |
| Reward amount không bền vững | Bỏ khỏi launch scope, chạy lại model bằng margin cùng liability hiện tại và nhận finance approval. |
| Provider recommendation có vẻ cũ | Xác minh official feature, pricing, data term, integration và migration option hiện tại trước purchase. |
| Attribution tạo duplicate hoặc dispute | Xác định precedence, idempotency, deduplication, reversal, manual review và audit evidence trước khi issue reward. |
| Fraud rule chặn user hợp lệ | Dừng automatic action, giữ bằng chứng, review bias cùng shared-network case và dùng appeals process đã duyệt. |
| Email copy có invented earning hoặc urgency | Bỏ claim, thay placeholder bằng fact đã duyệt và giữ message ở trạng thái unsent đến khi review. |
| Implementation đã thay production | Dừng rollout, ghi current state cùng affected record, làm theo recovery plan của product và không áp dụng corrective write diện rộng. |

## Biết các giới hạn hiện tại

- Provider detail, price, benchmark, implementation pattern và case-study
  outcome trong package là historical example, không phải current guarantee.
- Skill không thể đảm bảo participation, conversion, retention, acquisition
  cost thấp hơn, viral growth, customer value, fraud prevention hay ROI.
- Implementation sketch không thay thế product, engineering, security, privacy,
  legal, finance, accounting, tax, accessibility hoặc support review.
- Cài đặt không tạo provider access, production data contract, payout mechanism
  hay quyền liên hệ customer.
