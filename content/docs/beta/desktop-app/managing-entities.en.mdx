The Entities group holds the building blocks AgentKit knows about on this
computer. Desktop inspects and, for Kits and external Skills, installs them; it
does not run a skill or agent. After this page you will know what each surface shows and where its
edits stop.

## Install and inspect Kits

![Kits page with the install wizard open on the destination step](/gui/kits-install-wizard.webp)

The Kits page shows your license state, licensed and available Kits, and existing
global and project installs. The **Install** wizard walks three steps — choose a
destination (a coding agent, or all registered agents; global or a single
project), review version and safety, then confirm.

Kit removal is a CLI workflow, not a Desktop action. Preview it before confirming
with `--yes`.

## Read Subagents

![Subagents list with an agent detail pane and its frontmatter](/gui/subagents-list-detail.webp)

Subagents lists every agent AgentKit sees, with filters for source, install
state, and runtime. The detail pane shows the agent's model, tool grants, and
runtime, plus its frontmatter and rendered instructions.

The detail pane's **Recent use** panel lists up to 20 recorded sessions that
delegated to the agent, newest first, with the project, date, and call count
when the session called it more than once; select one to open the session.
Delegation is read from Task/Agent tool calls whose `subagent_type` names the
agent. If some projects' sessions could not be read, the panel says the count
may be low.

This surface is read-only: it inspects the agent definition. Launch the agent
from its coding assistant, not from here.

## Browse Commands

![Commands grouped by their source command](/gui/commands-grouped.webp)

Commands groups every registered command by its source, with the description and
owning Kit for each. Use search and the source/runtime filters to find one, then
**View** its definition.

The **Invocations** column and the detail pane's **Command usage** panel show how
many times each command ran in the last 30 days, counting repeats within one
session. The count is an estimate parsed from the command tag Claude Code
records when a slash command runs, and an invocation recorded under a namespace
the catalog entry does not carry is not matched, so that command can show `0`.

Like Subagents, this is an inspector. Running a command happens in the coding
assistant that owns it.

## Add external Skills

The Skills page's **External** tab manages third-party Skills from the open
Skills CLI ecosystem, the same way as `ak skills external`. Pick the coding
agent and install scope, search skills.sh or enter a source, then **Inspect**
it or **Preview add**. Installed external Skills list their status, with
**Update** and **Remove**; every change shows a plan first and runs only when
you **Apply** it. **Diagnose** runs the read-only `doctor` checks.

The tab needs the Skills CLI installed on this computer. The web dashboard
shows the equivalent CLI commands instead. See [External
Skills](../guides/external-skills) for sources, safety checks, and flags.

## Check Hooks in the harness

![Hooks page showing installed and registered hooks in the harness](/gui/hooks-harness.webp)

Hooks shows how many hooks are installed versus registered in the harness, plus
blocks and warnings. Each row lists its matcher and lets you toggle **Active** or
**Remove from harness**.

Desktop manages harness registration here; it does not edit the soft hook
preferences in `config.yaml`. Review the matcher before changing a hook's state.

## Inspect Sessions

![Sessions list with recorded session evidence](/gui/sessions-list.webp)

Sessions summarizes recorded Claude Code and Codex work — project, session, and
message counts, durations, and a searchable recent-sessions table. **Open** a row
to inspect its evidence.

The table includes **Tool calls** and **Tokens** columns for each session. A
session's detail shows a **Token usage** tile with the input, output, cache, and
reasoning split. It totals the whole main transcript, not tokens spent by
delegated subagents; those appear in the Dashboard's **Tokens by subagent**
panel. The **Subagents spawned**, **Tool calls by type**, and **Errors in
session** panels count only the messages on the page you are viewing, by
design. These figures are derived on this machine from local session
transcripts and the session index; AgentKit sends no telemetry for them.

Desktop is a session inspector, not a launcher, and it reads only supported
session sources.

## Verify MCP servers

![MCP servers list with sources and verification status](/gui/mcp-servers.webp)

The MCP surface lists configured servers, the config files they came from, the
known catalog, and how many are verified. Each server shows its source
`config.toml`, scope, and status, with **Edit**, **Disable**, **Verify**, and
**Delete** actions.

Verification runs only when you ask for it. Preview any configuration change
before applying it, because it can alter the target runtime's setup.
