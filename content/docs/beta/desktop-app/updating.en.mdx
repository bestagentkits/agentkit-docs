---
title: Update the Desktop app
description: Use AgentKit's signed paired-update flow, restart safely, and recover without bypassing verification.
---

Desktop auto-update is opt-in in vAK_DESKTOP_VERSION. Before enabling it, install the
standard `ak` CLI separately and keep the CLI and Desktop on the same release.

```bash
ak --version
ak self-update --check
```

The check uses your saved update channel, or the running release binary's
channel when none is saved, then `stable`. It reads signed release metadata and
does not install an update. The result reports the channel and its source. Confirm that the reported channel is the one you
intend to follow. If the CLI belongs to Homebrew or Scoop, use the manager
command AgentKit reports instead of replacing that CLI in place.

On macOS, a Desktop app opened from Finder can inherit a minimal `PATH`. When
you enable auto-update without a saved CLI path, Desktop checks `PATH`, then
`~/.local/bin/ak`, `/opt/homebrew/bin/ak`, and `/usr/local/bin/ak`. Each
candidate still passes normal path and executable validation, and a candidate
whose version does not match Desktop is skipped. If no matching CLI is found,
install or expose the same-release CLI before enabling auto-update. Package
manager detection still applies to the resolved candidate.

## Know the platform boundary

| Desktop platform | vAK_DESKTOP_VERSION paired update |
| --- | --- |
| macOS Intel and Apple silicon | Supported for a matching CLI and Desktop transaction |
| Linux x64 | Supported for a matching CLI and Desktop transaction |
| Windows x64 | Stages the matching CLI and Desktop artifacts, then a trusted handoff helper commits the swap after the parent process releases the executables |
| Linux ARM64 and Windows ARM64 | No vAK_DESKTOP_VERSION Desktop package was published to update |

Windows does not replace Desktop in-process. After staging, quit the running
CLI or Desktop so the handoff helper can finish the verified swap.

## What the signed flow verifies

Before staging a candidate, AgentKit verifies the signed channel pointer, the
immutable manifest and its digest, release compatibility, and each selected
artifact's declared size and SHA-256. The matching CLI and Desktop candidates
are staged under:

```text
$AGENTKIT_HOME/cache/binaries/<version>
```

The paired transaction is recorded at:

```text
$AGENTKIT_HOME/updater/pending-binary-update.json
```

The default `$AGENTKIT_HOME` is `~/.agentkit` on macOS and Linux and
`%USERPROFILE%\.agentkit` on Windows.

## Apply and restart

1. In Desktop update settings, opt in to automatic update checks and staged
   apply only if you want that behavior.
2. Let Desktop stage the matching CLI and Desktop artifacts through the signed
   flow.
3. Quit Desktop normally when it reports that a restart is required.
4. Open the same installed Desktop app again.

At the next Desktop launch, AgentKit rereads the pending transaction, verifies
the staged sizes and SHA-256 values again, and replaces the CLI and Desktop as
one transaction before opening the window. Temporary backups are removed after
a successful commit. There is no retained user-facing rollback copy afterward.
On macOS and Linux, that launch then restarts into the new version; if the
restart fails, the update takes effect on the next launch.

You can also drive the paired flow from the CLI. On Windows this stages the
artifacts and launches the handoff helper instead of replacing Desktop in-process:

```bash
ak self-update --include-desktop --yes
```

Restart Desktop to complete the staged transaction. See the
[`ak self-update` reference](../reference/cli/self-update) for manager
ownership, dry-run, output, and exit behavior.

## When a Kit needs a newer AgentKit

A Kit release can require a newer AgentKit than the running Desktop. When you
install a Kit from the Kits page or the onboarding Kit step, or apply a Kit
update, Desktop reads the AgentKit version that each selected Kit requires for
every selected runtime before it writes anything. If the app is too old, a
notice titled **This kit needs a newer AgentKit** names the required and
current versions, and Desktop recovers in four steps:

1. **Preparing update**: Desktop saves the Kit action, then downloads and
   verifies the matching CLI and Desktop from your release channel through the
   signed flow above. It never switches channels or updates the CLI alone to
   satisfy a Kit. Only a download that failed on the network is retried, at
   most twice.
2. **Restarting when safe**: Desktop waits until no task is running and no
   page has unsaved changes. On Windows it then restarts by itself, and
   **Restart now** restarts it at once. On macOS and Linux, quit and reopen
   AgentKit; that launch completes the staged update. If the notice says the
   update has not finished yet, quit and reopen AgentKit once more.
3. **Resuming kit action**: on the next launch, Desktop checks the requirement
   again and runs the saved action once. A Kit update resumes as a review:
   open **Kits → Update** to review and apply it.
4. **Completed**: AgentKit is updated and the Kit action finished.

A saved action that has not resumed within 24 hours is dropped, and your
installed Kits stay as they were. The setting **Update AgentKit automatically
when a kit needs it**, in **Settings → App → Updates**, is on by default and
independent of automatic update checks. Turn it off to update AgentKit yourself
before you retry the Kit action. When recovery cannot run, see
[An update will not complete](./troubleshooting#an-update-will-not-complete).

## After a rollback to v2

After `ak rollback --to v2`, the home is held at v2. The update banner says
AgentKit was rolled back to v2, so updates install only when you start them,
and the Settings update panel says turning automatic updates on installs nothing
by itself. An update you start from the banner releases the hold once it
installs or stages a v3 release.

While `ak rollback --to v2` is still running, the banner says so, names that
command, and offers no update. Finish the rollback first. See
[Rolling back to v2](../guides/rolling-back-to-v2).

## Kit update windows and the License screen

Kit update windows are separate from Desktop updates. Updates to kits are
covered for 12 months and renewal extends them, but an ended window never locks
Desktop, the CLI, or installed kits.

Open **System → License** to see each kit's window: the date updates are covered
through, the patch line, the latest covered version, the sources of coverage,
and, when a newer release needs renewal, **Renew updates**. The button opens
your renewal page in the browser. The screen states that installed versions keep
working. Desktop's own update flow above uses the signed release channel, which
update windows do not gate.

## Recover a staged update

If verification or replacement fails:

1. Do not delete the pending file, staged directory, or temporary backup named
   in the error.
2. Keep the currently working CLI and Desktop installation in place.
3. Correct ordinary causes such as insufficient disk space, file permissions,
   or another process holding the executable.
4. Reopen the same Desktop app to retry the still-verified pending transaction.

If a later replacement step fails, AgentKit attempts to restore both installed
binaries. When restoration succeeds, it retains the pending transaction for a
retry. If the error says rollback also failed, stop and preserve every reported
path; do not manually mix binaries from different versions.

On Windows, or when no pending transaction exists, use the manual verified
package flow in [Installation](./installation). Replacing only the Desktop
package preserves AgentKit state. Never fix an update by deleting the entire
AgentKit home.
