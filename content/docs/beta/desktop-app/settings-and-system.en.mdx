The System group holds app-level configuration and maintenance: sending
feedback, editing settings, managing the local analytics index, designing a
status line, and migrating providers. After this page you will know what each
surface changes and what stays local.

## Send feedback safely

![Feedback form with a redacted preview panel](/gui/feedback-form.webp)

Feedback files a report in the AgentKit issue tracker. Fill in the type, title,
area, and description, optionally attach a redacted diagnostics summary, and
review the **Redacted preview** before submitting.

Feedback is sent only when you submit it. Preview the payload first, and never
include a license key, session file, or unmasked config value.

## Edit app settings

![Settings App tab showing appearance and runtime preferences](/gui/settings-app.webp)

Settings holds App preferences (appearance, theme, sidebar width), a config
editor, effective-config inspection, and the database tab. Theme changes apply to
this machine immediately; some preferences are marked as coming later.

Interface preferences are local Desktop state. The config editor changes AgentKit
configuration, so review effective values before saving.

## Manage the local analytics index

![Settings Database tab with the local analytics index controls](/gui/settings-database.webp)

The Database tab manages the local analytics index that backs the Dashboard. It
shows what is serving, the fact count, last success, and privacy, with
**Disable**, **Refresh**, **Rebuild**, and **Delete index** actions.

The index is optional, local-only, and disposable — nothing is uploaded.
Rebuilding recomputes it from supported session sources on this device.

## Read provider usage limits

The top-bar badge and popover show the same local usage-limit data as
`ak usage limits` and the browser dashboard. Open the badge, choose a provider
(`claude`, `codex`, or `all`), and read both rolling windows (`5h` and the
trailing 7-day window) from the local analytics index.

A cold or absent index returns zeroed windows together with an index state, so
the view explains the empty state instead of showing a misleading zero. Nothing
leaves this machine; rebuild the index from the Database tab when the windows
look stale.

## Review Skill and agent insights

The Insights page reads that same local evidence store: collect bounded native
sources, record outcome evaluations, compare a baseline against a candidate, and
inspect the evidence behind one record. Consent for collection and sharing is
explicit and separate from local evidence, and a monthly contribution is frozen
and privacy-filtered on this machine so you review the payload before sending
it. Leaving consent unset keeps every insight local.

## Design a status line

![Status line designer with themes, sections, and a live preview](/gui/status-line-designer.webp)

The Status Line designer builds a Claude Code status line by drag-and-drop: pick
a color theme, set context-window and usage-quota thresholds, and arrange the
Model, Directory, Git, Cost, and other sections across lines with a live preview.
Save writes the status-line configuration.

## Migrate providers

![Migrate wizard discovering migration sources](/gui/migrate-wizard.webp)

The Migrate wizard moves a Claude Code stack toward other providers across four
steps — Discover, Reconcile, Execute, and Summary. Discover lists migration
sources (such as `~/.claude`, `~/.claudekit`, and `~/.agentkit`) with file counts
and sizes so you choose what to include.

Review each step before executing, because migration changes provider setup on
this device.
