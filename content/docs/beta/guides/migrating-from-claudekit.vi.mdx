Nếu bạn đang dùng ClaudeKit, `ak migrate` phát hiện cài đặt, phân loại nội
dung và tạo **kế hoạch di chuyển theo từng người dùng**. Lệnh quét
`~/.claude/`, `~/.claudekit/` và thư mục hiện tại. Không có file nào được ghi
cho đến khi bạn chọn áp dụng rõ ràng.

Mọi cờ và mã thoát: xem
[`ak migrate`](../reference/cli/ak_migrate) và
[`ak migrate rollback`](../reference/cli/ak_migrate_rollback).

<Steps>
  <Step>
    ### Chạy dry-run (mặc đnh)

    ```bash
    ak migrate
    ```

    **Dry-run là mặc định** — xem trước kế hoạch mà không ghi file. Thêm
    `--from=ck` nếu muốn chỉ rõ nguồn (hiện chỉ hỗ trợ nguồn này).
  </Step>
  <Step>
    ### Xem kế hoạch

    Đọc những gì lệnh sẽ thay đổi tại mục tiêu di chuyển. Dùng `--json` hoặc
    `--no-interactive` khi cần đầu ra máy đọc được trong CI.
  </Step>
  <Step>
    ### Áp dụng di chuyển

    Khi kế hoạch ổn:

    ```bash
    ak migrate --from=ck --dry-run=false --yes
    ```

    Các cổng an toàn runtime vẫn áp dụng; `--yes` bỏ qua hộp thoại tương tác.
  </Step>
  <Step>
    ### Chọn native hay project plugin (tuỳ chọn)

    Mặc định kế hoạch theo chế độ giao hàng đã phát hiện. Để **cho phép giao
    qua Claude Code project plugin**:

    ```bash
    ak migrate --from=ck --switch-to-plugin --dry-run=false --yes
    ```
  </Step>
  <Step>
    ### Xác minh và cài kit

    Sau di chuyển, đăng nhập và cài kit nếu cần. Xem
    [Cài đặt kit](./installing-kits).
  </Step>
  <Step>
    ### Hoàn tác nếu cần

    Nếu áp dụng thất bại hoặc bạn muốn quay lại:

    ```bash
    ak migrate rollback
    ```

    Lệnh khôi phục trạng thái trước khi áp dụng từ nhật ký rollback được ghi
    khi apply thất bại.
  </Step>
</Steps>

## Lưu ý

- **`--force-unlock`** xoá khoá di chuyển còn sót sau lần chạy bị crash trước
  khi thử lại.
- **`--no-backup` trên cài global** bỏ qua snapshot và takeover ClaudeKit, để
  nội dung CK vẫn hoạt động. Chỉ dành cho người dùng nâng cao — ưu tiên hành
  vi backup mặc định trừ khi bạn chắc cần tuỳ chọn này.
