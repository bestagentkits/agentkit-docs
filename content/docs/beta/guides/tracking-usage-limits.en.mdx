---
title: Tracking usage limits
description: Read local, per-provider token usage limits from the CLI and Desktop, and turn on the local analytics index that powers them.
---

`ak usage limits` and the Desktop usage-limit badge both read the same local,
opt-in analytics index — no request leaves your machine to produce these
numbers.

## Turn on the local index

Usage limits stay empty until AgentKit has counted some session activity:

```bash
ak analytics enable
```

This builds the local analytics index under `~/.agentkit/analytics/`
(override with `AGENTKIT_HOME`) from your existing Claude Code and Codex
session history. Until it has counted usage, `ak usage limits` and the Desktop
card point you back to this command instead of showing a number.

## Read it from the CLI

```bash
ak usage limits
ak usage limits --provider claude --window 5h
ak usage limits --json
```

`ak usage limits` sums local session-token facts into two rolling windows per
provider — trailing `5h` and trailing `week` — and reports both together
unless you narrow with `--window`. See the [command
reference](../reference/cli/usage/limits) for every flag and exit code.

## Read it from Desktop

The top-bar badge mirrors the same data: open it, pick a provider, and read
both windows. See [Read provider usage
limits](../desktop-app/settings-and-system#read-provider-usage-limits) for the
badge states and the Dashboard's Usage limits card.

## Understand provenance

Every row carries a provenance tag that says where its numbers came from.
Today's release always reports `raw_only` — a token count summed straight
from your local session history, with no quota or percentage attached.
AgentKit reserves two more precise tiers, `provider_reported` and
`plan_preset`, for provider-reported data in a later release; neither is
available yet.
