New repo, unfamiliar area, or a large blast radius — orient first so later
brainstorm / plan / fix steps cite real paths.

<Callout type="info">
  Scout is the default entry. Pair with repomix or graph tools when you need a
  packed context dump. Skill syntax:
  [Engineer kit cheatsheet](../kits/engineer).
</Callout>

## When to use

- First day on a service or a module you have never touched.
- Before a plan that might span many packages.
- When debug needs a map of callers and configs.

## Workflow

<Steps>
<Step>

### Fast map

```text
/ak:scout auth middleware session cookie
```

Search for symbols, configs, and nearby tests. Prefer native search; only
escalate to external probes when the skill documents that path and you permit
it.

</Step>
<Step>

### Pack context when the tree is large

```text
/ak:repomix
```

Use repomix (or similar packers the kit ships) when the agent needs a bounded
snapshot of relevant files. Keep the pack scoped — whole-monorepo dumps dilute
signal.

</Step>
<Step>

### Hand off with evidence

Summarize: project type, relevant modules, existing patterns, in-flight plans
under `./plans/`, and public contracts you must not break. Then continue to
[the core loop](./core-loop) or [debug and fix](./debug-and-fix) with that
summary in the prompt.

</Step>
</Steps>

## Sample prompts

```text
/ak:scout rate limit redis
/ak:scout "export function createSession" ts
/ak:repomix
```

## Pitfalls

- **Orient forever** — stop when you can name paths and constraints; planning
  starts after that.
- **Unscoped packs** — huge context windows hide the files that matter.
- **Stating behavior from names alone** — open the file; do not invent APIs from
  folder titles.
