import { Callout } from 'fumadocs-ui/components/callout';

[`ak secrets`](../reference/cli/secrets) giữ các giá trị nhỏ có tên, như API
key, token và certificate, trong keychain của hệ điều hành hoặc một file vault
mã hoá bằng age. Coding agent dùng giá trị qua tham chiếu `${secret:NAME}` thay
vì một file `.env` không được quản lý hay một lệnh export trong shell. Hướng dẫn
này giải thích các lệnh phối hợp với nhau thế nào; trang của từng lệnh có đầy
đủ flag, giá trị mặc định và exit code. Ứng dụng Desktop có [trang
Secrets](../desktop-app/secrets) riêng.

<Callout type="warning" title="Grant nghĩa là tin agent với giá trị">
  Vault sắp xếp và audit quyền truy cập. Nó không niêm phong giá trị khỏi một
  agent mà bạn đã grant. Hãy đọc [Giới hạn](#giới-hạn) trước khi grant một
  secret.
</Callout>

## Các lệnh

| Việc cần làm | Lệnh |
| --- | --- |
| Lưu hoặc thay một giá trị | [`ak secrets set`](../reference/cli/secrets/set), [`ak secrets rotate`](../reference/cli/secrets/rotate) |
| Xem những gì đã lưu (không bao giờ có giá trị) | [`ak secrets list`](../reference/cli/secrets/list), [`ak secrets get`](../reference/cli/secrets/get) |
| Mô tả một secret để tìm được nó | `ak secrets annotate` |
| Tìm secret theo metadata | `ak secrets search` |
| Đọc profile và nguồn gốc của một secret (không bao giờ có giá trị) | `ak secrets describe` |
| Xoá một giá trị | [`ak secrets delete`](../reference/cli/secrets/delete) |
| Chuyển file `.env` vào vault | [`ak secrets import-env`](../reference/cli/secrets/import-env) |
| Cho agent đọc một secret | [`ak secrets grant`](../reference/cli/secrets/grant) |
| Xin quyền truy cập trước khi dùng (agent) | `ak secrets request` |
| Trả lời yêu cầu agent để lại | [`ak secrets approve`](../reference/cli/secrets/approve) |
| Xem hoặc xoá grant | [`ak secrets grants`](../reference/cli/secrets/grants), [`ak secrets revoke`](../reference/cli/secrets/revoke) |
| Chạy một chương trình với secret trong môi trường | `ak secrets run` |
| Trỏ một tên vào một trong nhiều secret | `ak secrets alias` |
| Kiểm tra hoặc pin lại binary của agent | [`ak secrets trust`](../reference/cli/secrets/trust) |
| Đọc ledger truy cập | [`ak secrets audit`](../reference/cli/secrets/audit) |
| Kiểm kê vault | [`ak secrets export`](../reference/cli/secrets/export) |
| Quản lý vault và recovery key của file backend | [`ak secrets recovery`](../reference/cli/secrets/recovery) |
| Đồng bộ vault giữa các thiết bị của bạn (bản xem trước) | `ak secrets sync`, `ak secrets devices`; xem [Đồng bộ đám mây](#đồng-bộ-đám-mây) |

Giá trị được đọc từ `--value=-` (stdin), `--value-file` hoặc một prompt không
hiện ký tự, không bao giờ từ một giá trị flag dạng literal vốn sẽ nằm lại trong
lịch sử shell. `ak secrets get` in `[redacted]` trừ khi bạn truyền `--reveal`
trong terminal.

Tên của một secret (ref) không được chứa `/`, byte NUL, ký tự điều khiển, ký tự
ghi đè hoặc cô lập hướng chữ (bidi), hay ký tự ngắt dòng. `ak secrets list` và
prompt duyệt in tên đúng như khi lưu, nên những ký tự này có thể khiến tên trông
như một tên khác. Tên do phiên bản cũ đã lưu vẫn đọc được, nhưng không thể
rotate hay duyệt; hãy chuyển giá trị sang một tên thường bằng `ak secrets set`,
rồi xoá tên cũ.

## Chọn backend

| Backend | Dùng khi | Agent có resolve được không |
| --- | --- | --- |
| Keychain (mặc định) | Máy có keychain hệ điều hành hoạt động: macOS Keychain, Windows Credential Manager, hoặc Secret Service trên Linux | Có |
| File | Máy không có keychain dùng được | Không: passphrase của vault chỉ được đọc từ terminal, nên lần resolve của agent thất bại (exit 7) |
| Memory | Test và demo; không lưu lại gì | Chỉ trong tiến trình |

Backend được chọn từ `--backend`, rồi `AGENTKIT_SECRETS_BACKEND`, rồi `backend`
trong phần `secrets` của `$AGENTKIT_HOME/config.yaml`, và nếu không có thì là
keychain. Vì vậy một config máy chọn file backend sẽ khiến mọi lần resolve của
agent thất bại, dù không flag nào nói vậy. Hãy dùng keychain trên máy nào mà
agent cần secret; file backend hợp với vault chỉ mình bạn đọc từ terminal.

Keychain hệ điều hành có thể hỏi bạn cho phép truy cập ở lần đầu `ak` đọc một
mục, hoặc sau khi nâng cấp làm binary thay đổi. Prompt đó là cơ chế kiểm soát
truy cập của chính keychain.

## Thiết lập file backend

```bash
ak secrets recovery init --label <label>                 # create the vault and one recovery key
ak secrets recovery add <age-public-key> --label <label>  # enroll another recovery key
ak secrets recovery list
```

`recovery init` hiển thị recovery private key một lần và không lưu ở đâu cả.
Hãy cất nó ở nơi máy không chạm tới được: nếu bạn mất passphrase và mọi recovery
key, không ai mở được vault. Nếu quên passphrase, hãy chạy một lệnh đọc vault với
`--unlock-with-recovery` trong terminal, dán recovery key và chọn passphrase mới.

Máy ghi nhớ phiên bản vault mới nhất mà nó từng thấy. Nếu vault trên đĩa cũ hơn
(khôi phục từ bản sao lưu hoặc bị một bản sao cũ sync đè), các lệnh mở vault sẽ
thất bại. Hãy tìm nguyên nhân trước; nếu vẫn muốn giữ vault cũ hơn, chạy
[`ak secrets recovery accept-rollback`](../reference/cli/secrets/recovery/accept-rollback).
Các lần ghi sau bản sao cũ đó sẽ mất.

## Cho agent dùng một secret

Agent viết một tham chiếu vào tool call:

```text
curl -H "Authorization: Bearer ${secret:NAME}" <url>
```

Hook PreToolUse `secrets-inject` của Kit core thay giá trị vào trong bộ nhớ ngay
trước khi tool chạy. Trong Claude Code, nó chỉ quét lệnh của `Bash` và
`PowerShell` cùng URL của `WebFetch`. Với mỗi tham chiếu, nó chạy `ak secrets resolve`, lệnh này xác định
agent gọi bằng cách duyệt cây tiến trình và băm binary của agent; bên gọi không
bao giờ được lấy từ flag. Mọi lỗi đều chặn tool call thay vì chuyển tiếp tham
chiếu nguyên văn.

Khi `ak run` khởi động một agent Codex hoặc Grok, các tham chiếu
`${secret:NAME}` trong môi trường truyền cho agent đó được resolve theo cùng cách,
và lần chạy dừng lại nếu một giá trị không thể được release.

Một lần resolve chỉ thành công khi có grant khớp bốn trường: secret, project,
fingerprint binary của agent và mục đích. Mục đích rỗng là một giá trị literal,
không phải wildcard, và block luôn thắng mọi allow trên cùng scope. Lấy
fingerprint của agent từ
[`ak secrets trust <adapter> --json`](../reference/cli/secrets/trust) hoặc từ
một yêu cầu đang chờ.

`ak secrets grant --allow-host <host>` giới hạn một allow vào các URL `WebFetch`
nhắm tới những host được liệt kê. Một grant bị giới hạn sẽ từ chối mọi lần
release mà Hook không kiểm tra được đích đến, bao gồm mọi tham chiếu trong
`Bash` hoặc `PowerShell`. Giới hạn này chỉ áp dụng cho đường thay giá trị của chính Hook; xem
[`ak secrets grant`](../reference/cli/secrets/grant) để biết quy tắc so khớp
chính xác.

### Trả lời yêu cầu duyệt

Khi không grant nào bao phủ một lần resolve, nó không hỏi. Nó thất bại an toàn
(exit 8) và để lại một yêu cầu cho bạn. Trả lời bằng
[`ak secrets approve`](../reference/cli/secrets/approve) trong terminal của
chính bạn, hoặc trong hộp duyệt trên [trang Secrets](../desktop-app/secrets) của
Desktop:

| Câu trả lời | Tác dụng |
| --- | --- |
| Deny | Từ chối yêu cầu này và không lưu gì; lần resolve sau sẽ hỏi lại |
| Allow once | Release secret đúng một lần |
| Allow for a while | Một allow tự hết hạn: mặc định 24 giờ trong CLI (`--ttl` đổi được); 15 phút, 1 giờ (mặc định) hoặc 8 giờ trong Desktop |
| Always allow (allow until revoked) | Một allow không hết hạn |

Một agent cứ xin mà không có grant sẽ bị giới hạn tốc độ theo fingerprint rồi bị
giữ trong thời gian chờ (exit 9). Một job chạy dưới grant thường trực không bao
giờ chạm tới giới hạn này.

`grant` và `approve` từ chối chạy (exit 6) khi có agent nằm phía trên chúng
trong cây tiến trình, và Desktop từ chối câu trả lời khi một agent đã khởi động
ứng dụng. Điều này ngăn agent tự duyệt yêu cầu của chính nó theo cách hiển
nhiên; đây là gờ giảm tốc, không phải ranh giới.

### Xin quyền truy cập trước khi dùng

Một agent đã chọn được credential bằng `ak secrets search` và
`ak secrets describe` có thể xin nó trước khi dùng:

```bash
ak secrets request <ref> --purpose "<lý do cần>"
ak secrets request <ref> --exec <program> --env <VAR>   # exec scope cho ak secrets run
```

Yêu cầu nằm chờ trong cùng hộp duyệt mà một lần resolve bị từ chối đổ vào, để
bạn trả lời bằng `ak secrets approve`. Một yêu cầu không bao giờ đọc hay release
giá trị, không bao giờ ghi grant và không bao giờ tiêu một allow-once; chỉ câu
trả lời của bạn mới cấp quyền. Nó nhận diện agent giống cách resolve làm và bị
từ chối (exit 6) khi không xác định được agent nào. Các yêu cầu lặp lại cho cùng
một scope chỉ là một mục trong hộp duyệt, và agent hỏi quá thường xuyên bị giữ
trong thời gian cool-down (exit 9). Lệnh thoát 0 khi yêu cầu đang chờ, hoặc khi
đã có grant bao phủ scope đó. Không gì trong profile của secret quyết định một
yêu cầu: nó chỉ được đáp bằng một grant trên đúng scope mà nó nêu.

### Revoke

```bash
ak secrets revoke <ref> --agent sha256:<hash>   # one scope, allow or block
ak secrets revoke --agent sha256:<hash> --all   # every grant that binary holds
```

Revoke chặn các lần đọc sau này. Nó không thu hồi giá trị agent đã đọc, nên hãy
rotate secret sau một lần revoke khẩn cấp.

### Sau một lần release

Giá trị đã release tới được tiến trình và tham số của tool, và runtime có thể
ghi lại call đã chạy, kèm giá trị, vào transcript session của nó. AgentKit chỉ
giữ hash và độ dài của mỗi giá trị đã release, trong các release manifest dưới
`$AGENTKIT_HOME/diagnostics/manifests/`. Hai lệnh dùng chúng để gỡ các giá trị
đã release về sau:

- [`ak diagnostics export`](../reference/cli/diagnostics/export) gỡ chúng khỏi
  gói hỗ trợ khi đọc được các manifest.
- [`ak sessions redact`](../reference/cli/sessions/redact) tìm chúng trong các
  session file Claude Code đã đăng ký. Lệnh chạy thử (dry run) trừ khi bạn truyền
  `--apply --yes`, và sao lưu trước khi ghi lại.

## Chạy một chương trình với secret

`ak secrets run` khởi chạy một chương trình với các secret chỉ được đưa vào
những biến môi trường mà `--env` nêu:

```sh
ak secrets run --env VAR=REF [--env VAR=REF ...] -- <program> [args...]
```

Lệnh phục vụ coding agent. Nó nhận diện bên gọi giống cách
`ak secrets resolve` làm, bằng cách duyệt cây tiến trình và băm binary của
agent, và từ chối (exit 6) khi không xác định được bên gọi.

### Exec grant

Mỗi cặp `VAR=REF` cần một exec grant cho agent đang gọi trên đúng chương trình
này: đường dẫn đã giải mọi symlink, và hash nội dung của nó. Hãy cấp một grant,
hoặc để agent tự xin bằng `ak secrets request`:

```sh
ak secrets grant <ref> --agent sha256:<hash> --exec <program> --env <VAR>
ak secrets request <ref> --exec <program> --env <VAR>
```

`--exec` nhận chương trình theo tên trên `PATH` hoặc theo đường dẫn, và cần đi
cùng `--env`. Một chương trình tìm thấy ở chỗ khác trên `PATH`, hoặc đã thay đổi
kể từ khi grant (nâng cấp làm đổi hash), sẽ không khớp grant nào. Mỗi scope
chưa được bao phủ được gửi tới
[`ak secrets approve`](../reference/cli/secrets/approve), và lần chạy thoát với
mã 8; thu hẹp hộp duyệt về các yêu cầu exec bằng
`ak secrets approve --env <VAR>`. Grant thường không bao giờ release ở đây, và
exec grant không bao giờ release cho `resolve` hay inject Hook.

Mọi scope đều được kiểm tra, và chương trình được băm lại, trước khi đọc bất kỳ
giá trị nào, nên một lần chạy bị kiểm tra grant từ chối sẽ không tiêu
allow-once nào. Nếu chương trình vẫn không khởi chạy được sau khi giá trị đã
release, ledger ghi lại rằng nó chưa bao giờ chạy. Một `REF` không có giá trị
lưu trữ mà trùng tên một [alias](#alias-một-tên-nhiều-tài-khoản) sẽ đi theo
alias đó một bước, và exec grant được kiểm tra theo đích của alias.

### Chương trình chạy thế nào

- **Không qua shell.** Chương trình được khởi chạy trực tiếp, nên không gì
  trong đối số được mở rộng. Shell và launcher bị từ chối, cũng như các biến
  điều khiển loader, runtime hoặc endpoint mạng.
- **Môi trường dựng lại.** Một vài biến được sao chép từ môi trường của `run`
  (home, user, locale, terminal, thư mục tạm), `PATH` là danh sách cố định các
  thư mục hệ thống, cộng thêm các biến đã grant; không gì khác, kể cả proxy và
  tuỳ chọn runtime. Chương trình chạy một helper cài ngoài thư mục hệ thống phải
  gọi nó bằng đường dẫn.
- **Output bị gạch.** Output của chương trình được chuyển tiếp với mọi giá trị
  đã grant, và các dạng escape của nó, bị gạch bỏ. Vài byte cuối được giữ lại
  cho tới khi chương trình ghi thêm hoặc thoát, nên một prompt không có ký tự
  xuống dòng có thể hiện muộn. Output đi qua pipe, không phải terminal, và
  `--json` không được hỗ trợ.
- **Tín hiệu và exit.** Ctrl-C từ terminal tới được chương trình, còn SIGTERM
  và SIGHUP được chuyển tiếp cho nó. `ak` chờ nó thoát và không bao giờ kill nó.
  Exit status của chương trình là của `run` (128 cộng số hiệu tín hiệu nếu một
  tín hiệu kết thúc nó). Lỗi của chính `ak` luôn in một dòng lỗi bắt đầu bằng
  `secrets run:`.

`ak secrets run --help` liệt kê mọi exit code.

### Những gì exec grant không giới hạn

Exec grant giới hạn chương trình nào nhận giá trị, không giới hạn chương trình
làm gì với nó:

- Chương trình có thể gửi giá trị đi bất cứ đâu, ghi nó vào file, hoặc truyền
  nó cho một tiến trình con của riêng nó.
- Đối số không thuộc scope. Một interpreter chạy bất kỳ script nào được đưa,
  và một chương trình như `curl`, `wget` hay `gh` có thể bị đối số bảo gửi một
  biến đi bất cứ đâu hoặc chạy một chương trình khác.
- Bất kỳ tiến trình nào cùng user đều đọc được môi trường của chương trình
  trong lúc nó chạy.

Chỉ cấp exec scope cho chương trình mà chính bạn sẵn sàng trao giá trị. Xem
[Giới hạn](#giới-hạn).

### Alias: một tên, nhiều tài khoản

Khi bạn giữ một key cho mỗi tài khoản, hãy trỏ một tên duy nhất vào key bạn muốn
dùng và chuyển đổi bằng một lệnh:

```sh
ak secrets alias set CLAUDE_API_KEY CLAUDE_API_KEY_1   # chọn tài khoản 1
ak secrets alias set CLAUDE_API_KEY CLAUDE_API_KEY_2   # chuyển sang tài khoản 2
ak secrets alias list
ak secrets alias unset CLAUDE_API_KEY                  # bản thân secret không bị đụng tới
```

Khi đó một tham chiếu `${secret:CLAUDE_API_KEY}`, và `REF` của
`ak secrets run --env VAR=CLAUDE_API_KEY`, tới được secret mà alias đang trỏ.
Các quy tắc:

- **Secret đã lưu thắng.** Alias chỉ được dùng khi không có secret nào mang tên
  đó.
- **Một bước.** Đích là một alias khác, hoặc không có giá trị lưu trữ, bị từ
  chối như một secret không tồn tại (exit 3). Đích không cần tồn tại khi bạn đặt
  alias; thiếu đích chỉ là cảnh báo, nên bạn có thể đặt alias trước khi sync
  mang giá trị về.
- **Alias không cấp quyền gì.** Grant, approval và dòng audit đều nêu đích, nên
  hãy grant `CLAUDE_API_KEY_1`, không phải `CLAUDE_API_KEY`. Dòng audit ghi alias
  dưới dạng `alias:CLAUDE_API_KEY`.

Alias chỉ giữ tên và nằm trong `$AGENTKIT_HOME/secrets/aliases.json`. Chúng
thuộc về riêng thiết bị và không được sync: sync vault mang theo giá trị, còn
việc một máy dùng tài khoản nào là lựa chọn của máy đó.

## Mô tả và tìm secret

Mỗi secret có thể mang một profile metadata tuỳ chọn để tìm kiếm: mô tả,
project, môi trường, nhà cung cấp, tài khoản, tag, và các trường giúp agent chọn
credential, như khi nào nên dùng. Đặt nó bằng `ak secrets annotate`, rồi tìm và
xem secret mà không mở giá trị:

```sh
ak secrets annotate <ref> --provider stripe --environment production --tag billing
ak secrets search stripe --environment production --json
ak secrets describe <ref> --json
```

`ak secrets describe <ref>` hiện mọi thứ index ghi lại về một secret: profile
cùng nguồn gốc, người ghi và thời điểm của từng trường, nguồn của secret, và
trạng thái rotation. Đây là bước sau `ak secrets search`, để chọn giữa các
credential ứng viên. Cả hai chỉ đọc index trên đĩa: chúng không bao giờ mở
backend, không đọc hay in giá trị, và không hiện prompt. `--json` thêm
`untrustedFields`, các trường không do người vận hành thiết bị này ghi, cùng một
thông báo cố định.

Nội dung profile là dữ liệu không tin cậy, không bao giờ là chỉ dẫn. Nó không
cấp quyền gì, và một usage host hay một quyền được liệt kê không hạn chế gì:
grant, approval và resolve không bao giờ đọc profile.

### Nguồn gốc và đồng bộ profile

Mỗi trường profile ghi lại nguồn gốc dưới dạng `{value, origin, by, at}`:

| `origin` | Nội dung được ghi bởi |
| --- | --- |
| `local` | Người vận hành thiết bị này |
| `import` | Một lần import thư mục, suy ra từ tên file và thư mục |
| `sync` | Một thiết bị vault khác; `by` nêu device ID của nó và `at` thời điểm của bản ghi |

Hãy coi trường có origin khác `local` là không tin cậy.

Khi bật [đồng bộ đám mây](#đồng-bộ-đám-mây), profile đi cùng secret và được mã
hoá như giá trị. Trường bạn sửa trên một thiết bị tới các thiết bị khác với
origin `sync`, và mỗi thiết bị giữ các trường của chính nó là `local`. Mỗi
thiết bị kiểm tra rằng trường nó kéo về đúng là do thiết bị được nêu tên ghi;
trường không qua kiểm tra bị bỏ và được audit là `profile_provenance_invalid`.
Nguồn import nằm lại trên thiết bị và không được sync. Thiết bị chạy bản `ak`
cũ không mang profile.

## Rotate

Mỗi secret có một cửa sổ rotation: mặc định 90 ngày, hoặc giá trị bạn truyền với
`ak secrets set <ref> --rotate-ttl <days>d`. `ak secrets list` đánh dấu các
secret đã quá cửa sổ. Thay giá trị bằng `ak secrets rotate <ref>`; lệnh thất bại
nếu ref không tồn tại, nên gõ nhầm sẽ không tạo ra secret mới.

## Audit các lần release

Mọi lần resolve có bên gọi xác định được đều ghi một dòng vào ledger
`secrets_audit`, cho cả release lẫn từ chối, trước khi bất kỳ giá trị nào được
trả về. Một dòng ghi ref, project, fingerprint, label, mục đích, quyết định,
nguồn, session, mã lỗi và ngữ cảnh, không bao giờ có giá trị. Với tham chiếu
`WebFetch`, host đích được thêm vào ngữ cảnh. Một lần reveal trên Desktop cần lý
do, được ghi theo cùng cách.

Đọc ledger bằng [`ak secrets audit`](../reference/cli/secrets/audit) hoặc trên
trang **Audit log** của Desktop. Ledger được giữ cho tới khi bạn đổi retention
của nó bằng [`ak data retention --class secrets_audit`](../reference/cli/data/retention).

Khi Desktop đang mở, mỗi lần release còn hiển thị một thông báo trong ứng dụng
có nút **Revoke this agent's grants**, và tạo một thông báo hệ điều hành với
tiêu đề **Secret released** khi không ai đang nhìn cửa sổ. Không thông báo nào
chứa giá trị; xem [trang Secrets](../desktop-app/secrets#theo-dõi-các-lần-release-secret).

## Export

```bash
ak secrets export --json                               # inventory on stdout, no values
ak secrets export --out ./inventory.json               # the same, as a file only you can read
ak secrets export --include-values --out ./values.age  # confirms, then writes an age-encrypted file
```

Bản export mặc định không có giá trị. `--include-values` cần terminal tương tác
và một đường dẫn `--out` kết thúc bằng `.age`; giá trị không bao giờ ra stdout.
Lệnh hỏi bạn xác nhận và chọn passphrase, và không gì trên máy giữ passphrase
đó, nên mất passphrase là mất bản export. Giải mã bằng CLI `age` gốc, ví dụ
`age --decrypt values.age | jq .`, và đối xử với mọi file đã giải mã như chính
các secret bên trong.

## Chuyển từ `.env`

```bash
ak secrets import-env <path>           # skips keys that already exist
ak secrets import-env <path> --force   # overwrites them instead
```

Lệnh chỉ báo số lượng, không bao giờ báo giá trị, và đọc tối đa 1 MiB. Sau đó
hãy grant cho các agent cần từng key, đổi lệnh sang dùng `${secret:NAME}`, và xoá
file `.env`.

## Đồng bộ đám mây

Vault nằm trên một máy. Tính năng đồng bộ mã hoá đầu-cuối, tự chọn bật, đang
được phát triển với tên [ak-vault](https://vault.agentkit.best). Giai đoạn đầu,
đồng bộ giữa các thiết bị của cùng một chủ sở hữu, là bản xem trước thử nghiệm
với các lệnh được ẩn khỏi `ak secrets --help`. Chạy `ak secrets sync status --json`
để xem, mà không cần liên hệ máy chủ, thiết bị này đã đồng bộ chưa và phiên đăng
nhập của bạn có đồng bộ được không. Dịch vụ đồng bộ production chạy
tính năng này theo các quyết định miễn trừ của chủ sở hữu, và đợt đánh giá bảo
mật do chính chủ sở hữu thực hiện, không phải bên thứ ba độc lập. Đồng bộ vẫn ở
giai đoạn tiền phát hành, chưa phát hành chính thức và chưa được khuyến nghị
cho credential production. Chia sẻ với đồng đội và CI chưa được xây dựng. Trạng
thái được theo dõi tại
[release gates](https://github.com/bestagentkits/ak-vault/blob/main/docs/security/release-gates.md)
của ak-vault.

Thiết kế giữ vault cục bộ làm nguồn sự thật:

- Mỗi thiết bị mã hoá tên, giá trị, người tạo, các mốc thời gian và chu kỳ
  rotate của secret trước khi tải lên, nên máy chủ đồng bộ chỉ lưu và chuyển
  tiếp bản mã, không đọc được secret nào. Profile của secret cũng được mã hoá
  như vậy khi đồng bộ. Grant, trust pin, phê duyệt và audit release ở lại trên
  thiết bị.
- Thay đổi thành viên được chủ vault ký và nối chuỗi băm, nên máy chủ không thể
  tự thêm người đọc hay giấu một lần gỡ bỏ.
- Các chỉnh sửa đồng thời được giữ lại thành xung đột để bạn xử lý, không bao
  giờ bị ghi đè âm thầm, và một thiết bị cũ không thể làm sống lại secret đã xoá.
- Mỗi thiết bị giữ grant của riêng nó: policy được đồng bộ chỉ có thể thu hẹp
  những gì agent được đọc, không bao giờ mở rộng.

[Giao thức và mô hình mối đe doạ](https://vault.agentkit.best/security/) được
công khai.

Thay đổi chỉ được truyền đi khi `ak secrets sync now` chạy. Giữ nó chạy liên tục
bằng `--watch`, chế độ đồng bộ thay đổi cục bộ trong vài giây và hỏi máy chủ
theo chu kỳ:

```bash
ak secrets sync now --watch           # đồng bộ liên tục cho tới khi bị ngắt
ak secrets sync now --watch --relay   # đồng thời trả lời các AI tool kết nối qua remote MCP
```

### Dashboard trình duyệt và AI tool (staging)

Hai tính năng tiền phát hành được xây trên sync. Cả hai chỉ chạy trên staging
và không dành cho credential production:

- [Dùng vault từ trình duyệt](./secrets-vault-dashboard): đăng ký trình duyệt
  làm thiết bị và quản lý secret trong vault dashboard, nơi không bao giờ lộ
  giá trị.
- [Kết nối AI tool với vault](./secrets-vault-remote-mcp): cho Claude Code,
  Claude.ai, ChatGPT, Cursor hoặc VS Code truy cập secret qua remote MCP, thông

Remote MCP thu hẹp một cam kết: máy chủ vẫn không lưu bản rõ và không giữ key
nào, nhưng một lời gọi remote MCP không được mã hoá đầu-cuối, vì bản rõ đi qua

[Trang remote MCP](./secrets-vault-remote-mcp#máy-chủ-thấy-những-gì) nói chính
xác những gì đi qua.

## Giới hạn

Đây là các ranh giới có chủ đích của phiên bản này:

- **Grant nghĩa là tin model của agent với bản rõ.** Một agent bị prompt
  injection có thể gửi giá trị đã grant tới bất kỳ host nào mà `--allow-host`
  không loại trừ. Grant không giới hạn dựa vào permission prompt của runtime, và
  `AGENTKIT_SECRETS_INJECT_AUTO_ALLOW=1` bỏ prompt đó.
- **Không có tường chắn sau khi inject.** Khi giá trị đã vào một tiến trình con,
  môi trường của nó hoặc một transcript, AgentKit không thể giữ nó lại. Redact
  và rotate là cách khắc phục.
- **Từ chối tự duyệt chỉ là gờ giảm tốc.** Một agent chạy dưới user của bạn có
  thể tách khỏi cây tiến trình hoặc sửa trực tiếp file grant.
- **Kiểm soát truy cập keychain thuộc về hệ điều hành.** Bất kỳ tiến trình nào
  chạy dưới user của bạn mà keychain cho vào đều đọc được một mục.
- **Kẻ tấn công bộ nhớ.** Ai đọc được bộ nhớ của `ak`, của Hook hoặc của tiến
  trình tool đều đọc được giá trị khi nó đang được dùng.
- **Cửa sổ cố định.** Cửa sổ grant và rotation là các khoảng thời gian cố định.
