Implement chưa xong khi review và vệ sinh ship chưa qua. Guide này là phần đuôi
sau cook/test (hoặc sau fix tập trung).

<Callout type="info">
  Cờ ship như `--dry-run` và `--skip-tests` nằm ở
  [bảng tra kit Engineer](../kits/engineer). Bỏ cổng là nợ rõ ràng.
</Callout>

## Khi nào dùng

- Feature branch local đã xanh, sẵn sàng PR.
- Cần review có cấu trúc trước khi người review xem diff.
- Cần đường ổn định tới branch `beta` hoặc `official`.

## Workflow

<Steps>
<Step>

### Review diff

```text
/ak:code-review
# or
/ak:review-pr
```

Yêu cầu finding cụ thể (đúng sai, regression, secret, đổi contract công khai).
Sửa issue chặn trước khi tách commit.

</Step>
<Step>

### Commit sạch

```text
/ak:git cm
```

Ưu tiên subject conventional một dòng. Để skill tách concern lẫn và quét
secret. Tránh gộp config lạ với code feature.

</Step>
<Step>

### Ship branch

```text
/ak:ship beta
# or
/ak:ship official
```

Ship gom pipeline (test, review, push, PR) về branch bạn chỉ. `--dry-run` trước
trên repo lạ. Tránh kết hợp `--skip-tests` với `--skip-review`.

</Step>
</Steps>

## Prompt mẫu

```text
/ak:code-review Focus on auth session edge cases
/ak:git cm
/ak:ship beta --dry-run
/ak:ship beta
```

## Cạm bẫy

- **Review hình thức** — đọc output skill mà không sửa finding.
- **Rò secret** — không commit token; quét lại sau lỗi amend.
- **Sai track** — `official` vs `beta` là lựa chọn sản phẩm; khớp quy trình release.
