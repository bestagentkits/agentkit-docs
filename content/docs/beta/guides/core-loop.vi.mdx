Đây là đường mặc định của kit Engineer cho việc giao hàng nhiều bước: khoanh vùng
công việc, lập kế hoạch, triển khai, chứng minh, rồi mở PR. Ví dụ: **thêm một
tính năng** (không phải sửa typo một dòng).

<Callout type="info">
  Claude Code dùng slash skill (`/ak:plan`). Codex dùng dạng dollar
  (`$ak:plan`). Cùng tên skill và cờ. Xem
  [bảng tra kit Engineer](../kits/engineer) cho toàn bộ cờ.
</Callout>

## Khi nào dùng workflow này

- Thay đổi sản phẩm/maintainer cần nhiều hơn một lần sửa.
- Yêu cầu còn mơ hồ, hoặc còn nhiều hướng khả thi.
- Bạn muốn plan bền trước khi code, và PR đã kiểm chứng ở cuối.

Bỏ qua vòng đầy đủ với Q&A trực tiếp hoặc sửa nhỏ đã chỉ rõ — hoặc nhảy thẳng
tới `/ak:fix` khi việc là bug đã định khung (xem
[Gỡ lỗi và sửa](./debug-and-fix)).

## Workflow

<Steps>
<Step>

### Khoanh outcome

```text
/ak:brainstorm Add export to CSV on the orders table
```

Ghi **outcome**, **constraints**, **non-goals**, và **acceptance criteria**
trước khi tranh luận thiết kế. Tái sử dụng plan/design đã chấp nhận nếu có; chỉ
bù khoảng trống quan trọng.

</Step>
<Step>

### Lập kế hoạch

```text
/ak:plan Add CSV export for orders — columns, auth, tests, empty states
```

Cờ hữu ích khi `SKILL.md` có ghi:

- `--fast` — đường nghiên cứu gọn hơn
- `--html` — artifact plan HTML tự chứa
- `--tdd` — cấu trúc tests-first theo phase

Đọc mọi stub phase được generate trước khi viết. Ưu tiên scaffolding CLI khi
có `ak`.

</Step>
<Step>

### Implement theo plan

```text
/ak:cook path/to/plan.md
# or
/ak:cook Add CSV export for orders --fast
```

Cook cần scope cụ thể (đường plan hoặc task rõ). Mặc định interactive; `--auto`
chỉ khi chấp nhận auto-approve. `--no-test` nới cổng test — phải nêu trade-off.

</Step>
<Step>

### Chứng minh thay đổi

```text
/ak:test
```

Chạy suite phủ surface mới và contract dùng chung đã chạm. Test fail là dừng,
không phải ghi chú ship.

</Step>
<Step>

### Commit và mở PR

```text
/ak:git cm
/ak:ship beta
```

`/ak:git` tách commit conventional và quét secret. `/ak:ship` chạy pipeline
branch → test → review → push → PR (`beta` hoặc `official`). Dùng `--dry-run`
khi chỉ muốn xem sẽ làm gì.

Tuỳ chọn: `/ak:journal` sau session khó để lần sau kế thừa ngữ cảnh.

</Step>
</Steps>

## Prompt mẫu

```text
/ak:brainstorm We need rate limits on the public API — what is in scope for v1?
/ak:plan Rate-limit public API with Redis, 100 req/min, document headers
/ak:cook plans/…/plan.md --tdd
/ak:test
/ak:ship beta --skip-journal
```

## Cạm bẫy

- **Code trước contract** — prompt mơ hồ tốn token; brainstorm trước khi outcome
  chưa rõ.
- **Bỏ scout** — cook vẫn cần ngữ cảnh codebase hiện tại; đừng bịa path.
- **Ship không test** — `--skip-tests` / `--no-test` là cửa thoát, không phải mặc định.
- **Lẫn track phát hành** — `ship beta` và `ship official` nhắm branch khác nhau.
