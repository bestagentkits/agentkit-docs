UI hỏng khi bỏ qua hệ visual sản phẩm hoặc bịa hệ mới. Workflow này giữ design
intent, implement, và review a11y trên một đường.

<Callout type="info">
  Mỗi experiment một design authority — đừng trộn instruction skill xung đột
  trong cùng run. Cú pháp và cờ:
  [bảng tra kit Engineer](../kits/engineer).
</Callout>

## Khi nào dùng

- Trang mới, redesign, hoặc component người dùng nhìn thấy.
- Style theo design system sẵn (ví dụ shadcn + token).
- Review a11y / Web Interface Guidelines trước ship.

## Workflow

<Steps>
<Step>

### Chốt design intent

```text
/ak:frontend-design Dashboard empty state for zero projects
```

Hoặc bắt đầu từ brand token đã có trong repo. Ưu tiên trung thành hệ hiện có
hơn gradient lạ và layout “AI SaaS” mẫu.

</Step>
<Step>

### Implement theo stack sẵn

```text
/ak:ui-styling Add filter chips using existing button and badge components
/ak:react-best-practices Review the new dashboard list for suspense and memo boundaries
```

Khớp pattern React/Next của project. Tái sử dụng token — không hex mới trừ khi
file brand sở hữu.

</Step>
<Step>

### Pass UX và a11y

```text
/ak:ui-ux-pro-max Review the filters for mobile, focus order, and empty states
/ak:web-design-guidelines Check contrast and interactive targets
```

Sửa contrast, focus, hit target trước review/ship. Ghép
[review và ship](./review-and-ship) khi UI lên branch.

</Step>
</Steps>

## Prompt mẫu

```text
/ak:frontend-design Settings page: profile + API tokens, dark-first
/ak:ui-styling Wire tokens only — no new palette
/ak:web-design-guidelines Audit the form for keyboard and labels
```

## Cạm bẫy

- **Chrome template** — gradient tím và lưới feature 3 cột bỏ brand.
- **Lẫn authority skill** — hai skill design cãi nhau một session.
- **Style không cấu trúc** — CSS đẹp trên markup inaccessible.
