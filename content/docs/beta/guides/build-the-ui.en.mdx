UI work fails when it skips the product visual system or invents a new one.
This workflow keeps design intent, implementation, and accessibility review on
one track.

<Callout type="info">
  Use one design authority per experiment — do not blend conflicting skill
  instructions in the same run. Syntax and flags:
  [Engineer kit cheatsheet](../kits/engineer).
</Callout>

## When to use

- New page, redesign, or component that users will see.
- Styling against an existing design system (for example shadcn + tokens).
- Accessibility or Web Interface Guidelines review before ship.

## Workflow

<Steps>
<Step>

### Set design intent

```text
/ak:frontend-design Dashboard empty state for zero projects
```

Or start from product brand tokens already in the repo. Prefer fidelity to the
existing system over novel gradients and stock “AI SaaS” layouts.

</Step>
<Step>

### Implement with the stack you have

```text
/ak:ui-styling Add filter chips using existing button and badge components
/ak:react-best-practices Review the new dashboard list for suspense and memo boundaries
```

Match the project’s React/Next patterns. Reuse tokens (`--color-fd-*` on this
docs site, or the app’s own tokens) — no new hex values unless the brand file
owns them.

</Step>
<Step>

### UX and a11y pass

```text
/ak:ui-ux-pro-max Review the filters for mobile, focus order, and empty states
/ak:web-design-guidelines Check contrast and interactive targets
```

Fix contrast, focus, and hit targets before review/ship. Pair with
[review and ship](./review-and-ship) when the UI lands on a branch.

</Step>
</Steps>

## Sample prompts

```text
/ak:frontend-design Settings page: profile + API tokens, dark-first
/ak:ui-styling Wire tokens only — no new palette
/ak:web-design-guidelines Audit the form for keyboard and labels
```

## Pitfalls

- **Template chrome** — purple gradients and three-column feature grids that
  ignore the brand.
- **Mixed skill authorities** — two design skills arguing in one session.
- **Style without structure** — pretty CSS on inaccessible markup.
