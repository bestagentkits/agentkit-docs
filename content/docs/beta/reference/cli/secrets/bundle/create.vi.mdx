Dùng `ak secrets bundle create` trên một thiết bị tin cậy để niêm phong các
secret mà một CI job được bảo vệ cần vào một file mã hoá. Job giải mã file đó
bằng `ak secrets run --bundle`. Vault có thể hỏi passphrase ở đây; trong CI
không có gì hỏi cả.

## Cách dùng

```bash
ak secrets bundle create --profile NAME --encrypt-for AGE_RECIPIENT --secret VAR=REF [--secret VAR=REF ...] --output FILE [flags]
```

```bash
ak secrets bundle create --profile ci-production --encrypt-for age1... --secret DEPLOY_TOKEN=${REF} --output ci-production.akv
ak secrets bundle create --profile ci-staging --encrypt-for age1... --secret A=${REF_A} --secret B=${REF_B} --output ci-staging.akv
```

## Tuỳ chọn

| Cờ | Mặc định | Mô tả |
| --- | --- | --- |
| `--profile NAME` | Bắt buộc | Nhãn ranh giới tin cậy lưu trong bundle, ví dụ `ci-production`. Từ 1 đến 64 ký tự thuộc `a-z`, `0-9`, `-` hoặc `_`. |
| `--encrypt-for AGE_RECIPIENT` | Bắt buộc | Public age recipient (`age1...`) mà [`ak secrets bundle keygen`](./keygen) đã in. |
| `--secret VAR=REF` | Bắt buộc | Đưa secret đã lưu `REF` vào bundle, giao dưới biến môi trường `VAR`. Lặp lại được, tối đa 64 lần. |
| `--output FILE` | Bắt buộc | File bundle cần ghi, với mode `0600`. |
| `--backend <name>` | Từ `AGENTKIT_SECRETS_BACKEND` hoặc `config.yaml`, nếu không thì `keychain` | Storage backend để đọc: `keychain`, `file` hoặc `memory`. |
| `--unlock-with-recovery` | `false` | Mở vault của file backend bằng recovery private key và đặt passphrase mới. |

Các cờ dùng chung nằm trong [quy ước CLI](../cli-conventions).

## Lệnh làm gì

Việc chọn là một allowlist tường minh: chỉ các secret được `--secret` nêu tên
mới được niêm phong, và không có chế độ export-all. Mỗi `VAR` phải là tên biến
mà [`ak secrets run`](../cli/ak_secrets_run) chấp nhận, và không `VAR` nào được
xuất hiện hai lần, không phân biệt hoa thường. Mỗi giá trị phải khác rỗng và tối
đa 16 KiB.

Lệnh đọc từng `REF` từ vault của thiết bị này và niêm phong các giá trị cho
recipient của `--encrypt-for`. Bundle chỉ mang tên các `VAR` và giá trị của
chúng, cùng profile và thời điểm tạo. Bundle không bao giờ mang grant,
membership, device key, tài liệu khôi phục, tên ref hay bất kỳ metadata nào
khác.

`--profile` đặt tên ranh giới tin cậy. `ak secrets run --bundle` từ chối bundle
có profile khác với profile mà nó được báo là phải nhận, nên hãy dùng một bundle
và một key cho mỗi ranh giới.

Lệnh ghi `--output` với mode `0600`, thay file đã có ở đó và tạo các thư mục
cha còn thiếu. Lệnh từ chối đích là symlink, thư mục, standard output hoặc
terminal, nên bundle không bao giờ bị in ra.

Ai giữ bundle và key của nó đều đọc được mọi giá trị bên trong.

## Đầu ra

Đầu ra text nêu file bundle, số secret và profile. JSON dùng
`kind=secrets.bundle.create` với các trường sau dưới `data`:

```text
out, count, profile
```

Đầu ra không bao giờ chứa giá trị secret.

## Kết quả và mã thoát

| Mã | Ý nghĩa |
| --- | --- |
| `0` | Đã ghi bundle. |
| `2` | Cờ, profile, recipient hoặc lựa chọn không hợp lệ, hoặc đích `--output` bị từ chối. |
| `3` | Một secret được chọn không tồn tại. |
| `5` | Không đọc được vault, hoặc không ghi được file. |
