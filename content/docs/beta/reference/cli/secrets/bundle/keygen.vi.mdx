Dùng `ak secrets bundle keygen` để tạo key mà một CI job được bảo vệ dùng để
giải mã bundle của nó. Tạo một key cho mỗi ranh giới tin cậy, ví dụ production
tách khỏi staging. Lệnh không bao giờ hỏi.

## Cách dùng

```bash
ak secrets bundle keygen --key-out PATH [flags]
```

```bash
ak secrets bundle keygen --key-out ./ci-production.key
ak secrets bundle keygen --key-out ./ci-staging.key --json
```

## Tuỳ chọn

| Cờ | Mặc định | Mô tả |
| --- | --- | --- |
| `--key-out PATH` | Bắt buộc | File để ghi CI key giải mã. Đường dẫn phải chưa tồn tại. |

Các cờ dùng chung nằm trong [quy ước CLI](../cli-conventions).

## Lệnh làm gì

Lệnh sinh một cặp key age X25519. Lệnh ghi nửa bí mật vào `--key-out` với mode
`0600`, tạo các thư mục cha còn thiếu, và không bao giờ in nó ra. Lệnh in public
recipient (`age1...`), chính là giá trị mà
[`ak secrets bundle create --encrypt-for`](./create) nhận.

Lệnh từ chối đường dẫn `--key-out` đã tồn tại, vì thay key sẽ làm các bundle đã
niêm phong cho key cũ không mở được nữa. Lệnh cũng từ chối symlink hoặc thư mục.

Nạp file key vào kho secret của môi trường CI được bảo vệ, rồi xoá file. Mặc
định job đọc key từ `AK_CI_DECRYPT_KEY`. Đừng bao giờ dùng lại passphrase của
vault cá nhân, recovery key hay device key ở đây.

## Đầu ra

Đầu ra text nêu file key và recipient. JSON dùng `kind=secrets.bundle.keygen`
với các trường sau dưới `data`:

```text
out, recipient
```

Không đầu ra nào chứa secret key.

## Kết quả và mã thoát

| Mã | Ý nghĩa |
| --- | --- |
| `0` | Đã ghi file key. |
| `2` | Thiếu `--key-out`, hoặc đường dẫn đã tồn tại, là symlink hoặc là thư mục. |
| `5` | Không sinh hoặc không ghi được key. |
