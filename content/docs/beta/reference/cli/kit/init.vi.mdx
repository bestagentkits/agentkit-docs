Dùng `ak kit init` khi bạn muốn resolve một Kit và chuyển các capability của Kit
đó sang runtime hoặc thư mục build. Hãy chọn target, scope và delivery mode trước
khi chạy, vì các lựa chọn này quyết định cả hoạt động mạng lẫn thay đổi trên
đĩa.

## Chọn đúng lệnh vòng đời

| Mục tiêu | Lệnh | Kết quả |
| --- | --- | --- |
| Đăng ký thư mục hiện có | `ak init [path]` | Ghi nhận ownership cho project hiện có; lệnh không cài Kit. |
| Tạo project mới | `ak new <project-name>` | Tạo thư mục project mới và có thể cài template hoặc Kit. |
| Cài một route của Kit | `ak kit init <kit-name>` | Resolve rồi tạo đầu ra của Kit cho runtime, scope và mode đã chọn. |
| Cài qua entry point tương đương | `ak kit install <kit-name>` | Dùng cùng hành vi cài đặt với tên lệnh hướng đến thao tác cài. |
| Đồng bộ lại route đã cài | `ak kit refresh <kit-name>` | Tạo lại đầu ra cho route và xoá đầu ra cũ còn thuộc quyền quản lý theo quy tắc vòng đời. |

Khi mục tiêu là cập nhật route hiện có, hãy dùng `ak kit refresh` thay vì thực
hiện một bản cài mới buộc ghi đè.

## Trước khi bắt đầu

Theo mặc định, Kit phát hành dùng remote registry có xác thực. Channel được
resolve theo thứ tự: `--channel` tường minh, rồi channel ghi trong install
receipt của destination đã có, rồi `kit.channel`, rồi `stable`. `--channel`
tường minh chỉ áp dụng cho request đó và không được lưu; nó không đổi các lần
`ak kit init`, `ak kit refresh` hay `ak update` sau. Receipt mâu thuẫn tạo cảnh
báo, chuyển sang `kit.channel` và không bao giờ bị ghi đè. Kit trả phí yêu cầu
phiên CLI hợp lệ và entitlement trước khi hiển thị preview hoặc ghi dữ liệu.

```bash
ak whoami
ak licenses
```

Quá trình resolve từ xa có thể gia hạn trạng thái xác thực cục bộ, liên hệ
registry, tải artifact dành riêng cho runtime và ghi verified cache. Cache đã
được xác minh đầy đủ có thể đáp ứng một số trường hợp lỗi offline; cache chưa có
hoặc không xác minh được sẽ bị từ chối an toàn.

Chỉ dùng `--local --kits-dir <dir>` khi chủ động chọn nguồn development hoặc
CI. Đây không phải phương án dự phòng khi xác thực hoặc entitlement thất bại.

<Callout type="info">
  Grok Build là signed registry target cho cài Kit thông thường. Chỉ dùng
  `--local --kits-dir <dir>` khi bạn chủ động chọn source development hoặc CI.
  AgentKit emit runtime file và lifecycle metadata cho Grok; Grok vẫn sở hữu
  authentication, model, trust, permission và sandbox behavior.
</Callout>

## Cách dùng

```bash
ak kit init <kit-name>
```

Trong script, hãy cung cấp một tên Kit có thể cài. Trên TTY tương tác, việc bỏ
trống tên có thể mở wizard thiết lập; lần gọi từ script thiếu tên sẽ thất bại.

Với ví dụ remote, hãy thay `<channel>` bằng kênh phát hành đang chọn trên header
tài liệu. Nếu bỏ `--channel`, lệnh dùng channel trong receipt hiện có, rồi
`kit.channel`, rồi `stable`.

## Tuỳ chọn của lệnh

| Cờ | Mặc định | Mô tả |
| --- | --- | --- |
| `--beta` | `false` | Viết tắt của `--channel beta`. |
| `--build-only` | `false` | Build vào thư mục cục bộ thay vì cài đặt. |
| `--channel <channel>` | Channel trong receipt, rồi `kit.channel`, rồi `stable` | Chọn channel remote registry chỉ cho request này; giá trị không được lưu. |
| `--exclude-skills <names>` | Trống | Cài toàn bộ Skill của Kit ngoại trừ tập tên phân tách bằng dấu phẩy. |
| `--accept-risks <token>` | Trống | Cùng `--fresh`, chấp nhận đúng các rủi ro an toàn mà kế hoạch trước đã liệt kê, bằng token đã in ra. |
| `--force` | `false` | Cho phép ghi đè đầu ra hiện có trong phạm vi vòng đời và snapshot. |
| `--fresh` | `false` | Đặt lại một install target đã chọn về chỉ còn đầu ra của Kit sau khi xác nhận và có snapshot đã xác minh. Không dùng cùng `--force`, `--no-backup`, `--build-only` hoặc `--out`. |
| `-g, --global` | `false` | Dùng thư mục user của adapter thay cho project hiện tại. |
| `--kits-dir <dir>` | Trống | Chọn thư mục Kit cục bộ rõ ràng cho development, CI hoặc local build. |
| `--local` | `false` | Dùng nguồn cục bộ đã chỉ định thay cho remote registry. |
| `--no-backup` | `false` | Bỏ qua recovery snapshot trước khi cài và biện pháp bảo vệ liên quan khi tiếp quản Claude native-global. |
| `--out <dir>` | Trống | Đặt thư mục gốc đầu ra cho route build hoặc export. Trên Windows, đường dẫn drive-relative như `D:out` thoát với mã `2` trước mọi thao tác ghi; hãy đặt đường dẫn trong dấu nháy hoặc dùng dấu gạch chéo xuôi. |
| `--registry-url <url>` | Biến môi trường hoặc mặc định của bản phát hành | Ghi đè URL gốc của AgentKit registry. |
| `--remote` | `true` | Dùng remote registry có xác thực; không cần truyền rõ vì đây là mặc định. |
| `--select-skills` | `false` | Chọn Skill của Kit bằng giao diện tương tác. |
| `--skills <names>` | Trống | Chỉ cài tập Skill phân tách bằng dấu phẩy. |
| `--switch-to-plugin` | `false` | Chọn Claude Code plugin delivery tại scope đã chọn. |
| `--target <ids>` | `claude-code` | Chọn một hoặc nhiều emitter target ID phân tách bằng dấu phẩy, gồm `dsh`, `grok` và `pi`; command facts sinh tự động có thể chậm hơn target projection Kit mới đăng ký. |
| `--version <version>` | Phiên bản mới nhất của channel | Chọn phiên bản Kit từ xa. |
| `--zip` | `false` | Với `--target portable`, ghi thêm một ZIP có thể upload cho mỗi Skill. |

`--skills`, `--exclude-skills` và `--select-skills` là các chế độ lựa chọn thay
thế nhau. `--select-skills` cần terminal tương tác. Các cờ dùng chung được liệt
kê trong [quy ước CLI](../cli-conventions).

## Chọn target, scope và mode

| Route | Project scope | User scope | Selector |
| --- | --- | --- | --- |
| Claude Code native | Tệp runtime trong `.claude` cùng metadata vòng đời trong `.agentkit` | Tệp runtime trong `~/.claude` cùng dữ liệu vòng đời AgentKit | `--target claude-code`; thêm `--global` cho user scope. |
| Claude Code plugin | `ak-<kit>` trong project | `ak-<kit>` dưới thư mục gốc Claude plugin đã cấu hình | Thêm `--switch-to-plugin`; thêm `--global` cho user scope. |
| Codex native | Skill trong `.agents/skills`, runtime Codex trong `<project>/.codex/`, cùng plugin package và lifecycle metadata trong `.agentkit/adapters/codex/<kit>/` | Skill trong `~/.agents/skills` và các bề mặt `~/.codex` khác | `--target codex`; thêm `--global` cho user scope. Bản cài project báo trạng thái trust Codex của project. |
| Cursor | Các bề mặt `.cursor` của project | Các bề mặt `.cursor` của user | `--target cursor`; thêm `--global` cho user scope. |
| DeepSeek Harness native | Skill dưới `.dsh/skills/` cùng lifecycle metadata dưới `.agentkit/adapters/dsh/<kit>/` | Skill dưới `${DSH_HOME:-~/.dsh}/skills/` cùng lifecycle metadata dưới `${AGENTKIT_HOME:-~/.agentkit}/adapters/dsh/<kit>/` | Dùng `--target dsh`; thêm `--global` cho user scope. |
| Grok Build native | Tệp runtime dưới `.grok` cùng lifecycle metadata dưới `.agentkit/adapters/grok/<kit>/` | Tệp runtime dưới `$GROK_HOME` (mặc định `~/.grok`) cùng lifecycle metadata dưới `${AGENTKIT_HOME:-~/.agentkit}/adapters/grok/<kit>/` | Dùng `--target grok`; thêm `--global` cho user scope. |
| Pi native spike | Tệp runtime dưới `.pi/skills`, `.pi/agents`, `.pi/rules` và `.pi/extensions` | Profile Pi coding-agent đang hoạt động (`PI_CODING_AGENT_DIR` hoặc `~/.pi/agent`) không có đoạn `.pi/` bổ sung | Dùng `--target pi`; thêm `--global` cho user scope. Profile đã có nội dung sẽ bị từ chối trừ khi `--force` cho phép ghi đè rõ ràng. |
| Oh My Pi native | Skill portable `ak-<slug>` dưới `.omp/skills`, cùng Agent, rule và `AGENTS.md` của project | Các bề mặt tương ứng dưới root profile OMP đã phân giải | Dùng `--target omp`; thêm `--global` cho user scope. OMP trong project cũng discover `.agents/skills` của project. |
| AGY | Không được hỗ trợ | Skill trong cả `~/.gemini/config/skills` và `~/.gemini/antigravity-cli/skills`, Agent tùy chọn trong `~/.gemini/config/agents/<name>/agent.md` | Dùng `--target agy --global`; remote source phân giải package `claude-code` đã ký, đánh dấu Agent đã projection là subagent và bỏ tool frontmatter không tương thích. |
| Local build | Thư mục `--out` đã chọn | Không phải install scope | Dùng `--build-only --out <dir>`. |
| Portable export | Thư mục `--out` đã chọn | Không phải install scope | Dùng `--target portable --out <dir>`; build mode được ngầm chọn. |

Bản cài project từ chối route trỏ vào bản cài cấp người dùng, chẳng hạn thư mục
project chính là thư mục home của bạn, `.agentkit` của project chính là AgentKit
home, hoặc `.claude`, `.codex` hay Pi extension của project trùng với root cấp
người dùng tương ứng. Bước kiểm tra áp dụng cho mọi target đã chọn, chạy trước
mọi bộ chọn Skill, preview, lock, snapshot hay thao tác ghi, và thoát `6`. Chạy
lại với `--global` để quản lý bản cài cấp người dùng, hoặc chạy từ một thư mục
project khác. Route build và export không bị kiểm tra.

Bản cài ở project scope và user scope có thể cùng tồn tại. Claude native và
plugin delivery là hai mode riêng trong cùng scope; việc chuyển mode là thao tác rõ ràng, có
snapshot bảo vệ. Codex không có đầy đủ mức tương đương với Claude về command,
Hook hoặc status line, vì vậy hãy xem kỹ cảnh báo thay vì giả định mọi
component đều được chiếu sang runtime.

Với Hook Codex global, wrapper đã thiết lập chỉ được alias leaf `hooks` cuối
cùng tới `~/.codex/hooks` canonical của user đã resolve, bằng symlink POSIX hoặc
directory junction trên Windows. AgentKit dùng path canonical đó cho command,
thao tác ghi, rollback và ownership. Parent có link và leaf resolve ra target
khác đều bị từ chối.

`portable` chỉ để export. `--target portable` không có `--out` trả mã `1` trước
preview, xác nhận, phân giải source, lifecycle preflight hoặc ghi đĩa:

```text
init: target "portable" is export-only and has no install mode; re-run with --out DIR to export a standalone build
```

Chỉ dùng `--out` sẽ giữ source mặc định từ remote và JSON báo `mode: "build"`.
Dùng rõ `--build-only --out` vẫn hợp lệ và chọn source mặc định cho local
development. Thêm `--zip` khi portable export cũng cần tạo một ZIP có thể upload
cho mỗi Skill. Portable không ghi install record. AGY chỉ hỗ trợ global và không
phải peer trong lifecycle refresh. Pi là target projection cài đặt, không phải
adapter `ak run`; dùng discovery riêng của Pi cho `.pi/skills` đã emit và đừng
thay bằng `--target omp` trừ khi bạn muốn dispatch qua Oh My Pi.

Projection OMP dùng thư mục portable `ak-<slug>` và `name: ak-<slug>` ở top-level
trong `SKILL.md` đã projection. Lệnh không viết lại alias trong body như
`/ak:cook` hoặc `$ak:cook`, còn `ak run <kit>/<skill> --target omp` giữ nguyên
selector dispatch. Trong project đã trust, `.omp/skills` của project che bản
`.agents/skills` xung đột với bản cài OMP project; `.agents/skills` của project
che bản trong profile OMP khi dùng bản cài global từ project đó. `ak kit init
--target omp` cảnh báo rồi tiếp tục mà không bỏ qua emission OMP, xóa hoặc viết
lại Skill, thay đổi `.agents` hay setting OMP, yêu cầu `--force` hoặc trả exit
`6`.

## Xem lại hành vi xác nhận

Trên TTY tương tác, install mode hiển thị preview destination và hỏi
`Continue? [y/N]:`. Nhấn Enter mà không nhập gì, hoặc nhập câu trả lời khác `y`
hay `yes`, đều là từ chối.

<Callout type="warning">
  `--json`, `--no-interactive` và stdin không phải TTY sẽ bỏ qua prompt cài đặt
  và có thể tiếp tục ghi dữ liệu mà không cần `--yes`. Trong tự động hoá, hãy
  dùng `--yes` để thể hiện chủ đích rõ ràng; đừng xem việc không có prompt là
  một chốt an toàn. Ngoại lệ là `--fresh`: lần chạy dạng script thiếu `--yes`
  sẽ dừng với mã `3`.
</Callout>

Hiện tại, từ chối trên TTY thoát với mã `1`, không phải `3`. Route build và
export không hiển thị install preview vì chúng ghi vào thư mục đầu ra đã chọn,
không phải install destination.

Khi chủ động tự động hoá, hãy chỉ định rõ route và xác nhận:

```bash
ak kit init engineer --target codex --yes --no-interactive --json --channel <channel>

# Cài Grok trong project từ nguồn local development rõ ràng.
ak kit init engineer --local --kits-dir ./kits --target grok --yes

# Cài Grok cho user từ cùng nguồn cục bộ rõ ràng.
ak kit init engineer --local --kits-dir ./kits --target grok --global --yes

# Portable export với một ZIP có thể upload cho mỗi Skill.
ak kit init engineer --target portable --out ./ak-export --zip
```

## Hiểu tác động trên đĩa

Một lần cài có thể ghi tệp native của runtime, metadata về ownership và vòng đời
AgentKit, cấu hình project, Hook script, thư mục Skill native và bản ghi chuyển
mode. Bản cài Codex global còn có thể đăng ký AgentKit MCP runtime trong cấu
hình Codex của user.

Tệp không xác định và tệp do người dùng sửa được giữ nguyên, trừ khi thao tác
được hỗ trợ cùng `--force` rõ ràng cho phép ghi đè có giới hạn. Trước khi refresh
phá huỷ hoặc ghi để chuyển mode, AgentKit thường tạo recovery snapshot. Không
dùng `--no-backup` cho cài đặt thông thường.

## Đặt lại một target với `--fresh`

`ak kit init <kit> --fresh` đặt lại một install target đã chọn về chỉ còn đầu ra
của Kit. Một target gồm một Kit, một runtime và một scope. Dùng lệnh này khi
lifecycle root riêng của Kit đã tích tụ tệp tuỳ chỉnh hoặc tệp cũ mà refresh hay
`--force` vẫn giữ lại. `ak kit install` nhận cùng cờ này.

```bash
# Xem kế hoạch; lần chạy dạng script dừng tại đây với mã 3.
ak kit init engineer --fresh --target codex

# Đặt lại sau khi đã xem kế hoạch.
ak kit init engineer --fresh --target codex --yes
```

Quá trình đặt lại chạy theo thứ tự:

1. Dựng kế hoạch chỉ đọc. Kế hoạch liệt kê reset root riêng của Kit, các tệp
   hiện có ở đó, tệp tuỳ chỉnh hoặc chưa được ghi nhận sẽ bị xoá, tệp đã ghi
   nhận có chỉnh sửa cục bộ sẽ bị bỏ (trong và ngoài reset root), link và tệp
   đặc biệt được giữ, các runtime root dùng chung không bị đặt lại, và mọi rủi
   ro an toàn.
2. Hỏi đồng ý một lần (xem bên dưới).
3. Dựng lại kế hoạch khi đang giữ khoá vòng đời. Nếu rủi ro an toàn đã thay đổi,
   lệnh hỏi lại trên TTY hoặc dừng với mã `3` trong lần chạy dạng script.
4. Snapshot mọi đường dẫn mà lần đặt lại có thể xoá hoặc ghi đè, rồi xác minh
   từng snapshot. Snapshot xác minh thất bại sẽ được chụp lại một lần.
5. Emit Kit.
6. Quét các tệp còn sót trong reset root. Tệp đã thay đổi kể từ lúc dựng kế
   hoạch được giữ lại. Tệp cũ đã ghi nhận của Kit này bị xoá kể cả khi đã bị
   sửa, vì snapshot đã xác minh giữ nội dung của chúng.

Những gì lần đặt lại không động tới:

- Runtime root dùng chung, như `.claude` hoặc `~/.codex`, chỉ thay đổi qua các
  tệp mà Kit này đã ghi nhận, giống như với `--force`.
- Các Kit khác, các runtime khác và bản cài project hoặc global còn lại không bị
  đặt lại.
- Link, junction, reparse point và tệp đặc biệt trong reset root được giữ và
  không bao giờ bị đi theo.
- Lựa chọn Skill trước đó không được kế thừa. Toàn bộ Kit được cài trừ khi bạn
  truyền `--skills`, `--exclude-skills` hoặc `--select-skills`.

Với Codex, bảng `[agents.<slug>]` trỏ tới tệp Agent đã bị xoá sẽ được dọn, nên
không còn mục `config_file` treo.

### Đồng ý và rủi ro an toàn

| Lần chạy | Kế hoạch không có rủi ro | Kế hoạch có rủi ro |
| --- | --- | --- |
| TTY | Một prompt `Reset this target? [y/N]`; `--yes` bỏ qua prompt. | Một prompt nêu tên các rủi ro, kể cả khi có `--yes`; `--yes --accept-risks <token>` bỏ qua prompt. |
| Script, `--json` hoặc `--no-interactive` | `--yes` cho phép tiếp tục. Nếu thiếu, lệnh in kế hoạch và lệnh chạy lại chính xác, rồi thoát `3`. | Chỉ `--yes --accept-risks <token>` cho phép tiếp tục. Nếu không, lệnh in kế hoạch, risk token và lệnh chạy lại chính xác, rồi thoát `3`. |

Riêng `--yes` không bao giờ chấp nhận rủi ro. Kế hoạch liệt kê một rủi ro cho
mỗi kiểm tra mà nó không chứng minh được:

- `unproven-ownership`: reset root đang có dữ liệu nhưng không có install
  manifest, hoặc manifest không đọc được.
- `other-kit-ownership`: install manifest của reset root ghi tên Kit khác.
- `snapshot-unverified`: recovery snapshot xác minh thất bại hai lần. Không có
  gì bị đặt lại cho tới khi bạn chấp nhận rủi ro này.

Risk token bao trùm đúng loại rủi ro, đường dẫn và tệp của kế hoạch đó cho Kit
và target đó. Với rủi ro `other-kit-ownership`, token còn bao trùm Kit sở hữu
root, nên việc chấp nhận bản ghi của một Kit không bao giờ bao trùm bản ghi của
Kit khác. Rủi ro, tệp hoặc Kit sở hữu mới sẽ đổi token. Nếu kế hoạch dưới khoá
có ít rủi ro hơn những gì bạn đã chấp nhận, lần đặt lại vẫn tiếp tục. Token
truyền cho kế hoạch không có rủi ro sẽ bị bỏ qua kèm thông báo. Token đã chấp nhận
snapshot chưa xác minh sẽ tiếp tục chấp nhận điều đó cho target ấy, nên đừng lưu
lại cho các lần chạy sau. `--accept-risks` mà không có `--fresh` thoát `2`.

Với `--json`, lần chạy bị dừng ghi envelope có `kind=kit.init_fresh_plan` và
`status: "confirmation-required"`. Data gồm `reason` (`not-confirmed`,
`risks-not-accepted`, `risks-changed` hoặc `snapshot-unverified`),
`resetRoots`, `notReset`, `unrecordedPaths`, `modifiedRecordedPaths`,
`modifiedOutsidePaths`, `keptLinks`, `risks`, `riskToken`, `confirmWith` và
`command`. Mỗi mục trong `risks` có `kind`, `path`, `detail`, `effect` và
`files`, thêm `owner` với rủi ro `other-kit-ownership`. Đầu ra cho người dùng
giới hạn mỗi danh sách đường dẫn ở 25 mục; kế hoạch JSON mang đầy đủ danh sách.

### Điều chỉnh tự động

- `pi`, `grok`, `omp` và `dsh` giữ đầu ra Kit và tệp runtime trong cùng một thư
  mục, nên không có ranh giới chỉ thuộc Kit. Yêu cầu fresh ở đó chạy refresh
  `--force` có snapshot thay thế, in một thông báo và giữ tệp tuỳ chỉnh.
- Reset root đi qua link hoặc reparse point cũng chuyển sang refresh `--force`
  có snapshot kèm thông báo.
- Bản cài Claude Code dạng plugin được đặt lại tại chỗ ở plugin mode, kể cả khi
  bỏ `--switch-to-plugin`.
- Bản cài Codex vẫn dùng bố cục Skill cũ được migrate trước bằng refresh
  `--force` có snapshot, rồi được đặt lại trong cùng lệnh.

### Các trường hợp bị từ chối

Các trường hợp sau thoát `2` trước khi lần đặt lại động tới bất cứ thứ gì:

- `--fresh` cùng `--force`, `--no-backup`, `--build-only` hoặc `--out`.
- Nhiều hơn một target.
- Target chỉ để export như `portable`.

Các trường hợp sau thoát `1` trước mọi thay đổi:

- Đang chờ chuyển từ native sang plugin. Hoàn tất bằng
  `ak kit init <kit> --switch-to-plugin`, rồi chạy `--fresh`.
- Đang chờ một legacy migration transition. Chạy `ak migrate rollback` trước.
- Bằng chứng ownership đã ghi nhận không đọc được.
- Claude home global không thuộc AgentKit. Chạy `ak kit init <kit> --global` để
  thiết lập ownership trước.
- Ranh giới mơ hồ, như runtime root nằm trong reset root, hoặc reset root không
  phải thư mục.
- Không chụp được snapshot.

Route project trỏ vào bản cài cấp người dùng, chẳng hạn thư mục project chính là
thư mục home của bạn, thoát `6` trước khi kế hoạch được lập. Chạy lại với
`--global` hoặc từ thư mục project khác.

### Đầu ra khôi phục

Sau khi đặt lại, đầu ra cho người dùng báo từng reset root cùng số tệp tuỳ chỉnh
hoặc chưa ghi nhận và tệp cũ đã sửa bị xoá, từng root dùng chung không bị đặt
lại, và từng snapshot trước khi đặt lại:

```text
[i] Fresh reset: <reset-root> now holds only engineer output (removed 3 custom/unrecorded and 1 modified stale file(s))
[i] Pre-reset target saved (verified <id>). Roll back: <restore-command>
```

Snapshot ngoài phạm vi restore báo `Manual recovery data: <path>` thay cho lệnh
restore. Snapshot chưa xác minh đã được chấp nhận được gắn nhãn
`UNVERIFIED, may be incomplete`. Nếu không có gì để đặt lại, đầu ra nói rõ điều
đó và không liệt kê snapshot.

Với `--json`, `data.fresh` gồm `resetRoots`, `notReset`, `snapshots` (mỗi mục có
`id`, `roots`, `verify_command`, và `restore_command` hoặc `manual_data_path`,
thêm `unverified` khi đã được chấp nhận), `snapshotVerified`,
`removedUnrecorded`, `removedStaleModified` và `reason`. Trường cũ
`forceSnapshot` ở cấp trên chỉ nêu snapshot đã xác minh, nên nó trống khi
snapshot duy nhất là snapshot chưa xác minh đã được chấp nhận. Nếu lần chạy thất bại
sau khi đã chụp snapshot, lỗi nêu từng snapshot cùng cách xác minh và restore.

Khi `ak kit init` chuyển tiếp sang CLI đã cập nhật trước, lệnh tiếp nối mang
`--fresh` và mọi token `--accept-risks` đã chấp nhận, không bao giờ mang
`--force`. Desktop, `ak update` và `ak doctor` không có fresh mode.

### `--fresh` khác `--force` thế nào

| | `--force` | `--fresh` |
| --- | --- | --- |
| Tệp tuỳ chỉnh hoặc chưa ghi nhận trong lifecycle root của Kit | Giữ lại | Xoá |
| Tệp đã ghi nhận của Kit này có chỉnh sửa cục bộ | Chỉ ghi đè khi trùng đường dẫn; tệp cũ đã sửa được giữ | Bỏ chỉnh sửa; tệp cũ đã sửa bị xoá |
| Recovery snapshot | Chụp trừ khi có `--no-backup` | Luôn chụp và xác minh; `--no-backup` bị từ chối |
| Target | Một hoặc nhiều | Đúng một |
| Đồng ý | Install preview; lần chạy dạng script có thể tiếp tục mà không cần `--yes` | Kế hoạch cùng một lần xác nhận; lần chạy dạng script cần `--yes` và mọi risk token |

Hai cờ này loại trừ lẫn nhau.

## Đọc đầu ra dành cho người dùng và JSON

Ở chế độ hiển thị cho người dùng, tiến trình, preview destination và prompt xác
nhận xuất hiện trên stderr. Phần tổng hợp kết quả cuối cùng xuất hiện trên stdout
và báo Kit, đường dẫn đầu ra, số tệp, install mode, scope, tổng hợp Hook, cảnh
báo cùng thông tin khôi phục liên quan.

Với `--json`, stdout chứa một envelope thành công có phiên bản với
`kind=kit.init` và kết quả lệnh dưới `data`. Trừ khi đặt `--quiet`, stderr còn
nhận các bản ghi trạng thái thô với `status=preview` trước khi ghi và
`status=complete` sau khi ghi. Hãy xử lý stdout và stderr riêng biệt.

Dữ liệu thành công có thể bao gồm Kit và target đã chọn, mode, install mode,
scope, thư mục đầu ra, số lượng tệp và Skill, tổng hợp Hook đã cài, cảnh báo,
trạng thái cấu hình project, chuyển mode và các trường recovery snapshot có
giới hạn. Dữ liệu projection Hook còn có thể chứa `hooksDropped`,
`droppedHookSummaries`, `hookMatchersNarrowed` và `narrowedHookSummaries`; giá
trị zero hoặc nil bị lược bỏ.

Lỗi thực thi dành cho người dùng và JSON hiển thị lý do cần để khôi phục theo
mặc định, gồm lỗi từ bước kiểm tra đối số của lệnh. Các dạng bí mật đã biết
và query string của URL được che, còn đường dẫn vẫn hiển thị.
`--verbose` có thể lộ lỗi gốc thô; hãy kiểm tra trước khi chia sẻ.

## Kết quả và mã thoát

| Mã thoát | Ý nghĩa | Bạn nên làm gì |
| --- | --- | --- |
| `0` | Route build hoặc cài đặt đã chọn hoàn tất. | Xác minh target, scope, mode, tệp và cảnh báo được báo cáo. |
| `1` | Xảy ra lỗi runtime, kiểm tra dữ liệu, xác thực, quyền sử dụng, nguồn Kit, quá trình tạo đầu ra hoặc ghi dữ liệu; thao tác từ chối trên TTY hiện cũng dùng mã này. | Đọc lỗi và trường khôi phục trước khi thử lại. |
| `2` | Cờ, argument hoặc tổ hợp cờ không hợp lệ. | Sửa route hoặc cờ lựa chọn. |
| `3` | Lệnh bị ngắt hoặc huỷ qua đường xử lý huỷ dùng chung, hoặc lần đặt lại `--fresh` chưa chạy vì cần xác nhận hoặc cần chấp nhận các rủi ro đã liệt kê. | Kiểm tra trạng thái hiện tại và mọi đầu ra khôi phục trước khi thử lại. Với `--fresh`, xem kế hoạch rồi chạy lệnh đã in ra. |
| `4` | Một thao tác vòng đời Kit khác đang giữ khoá thay đổi. | Đợi thao tác đó hoàn tất rồi thử lại sau vài giây. |
| `5` | Không tìm thấy Kit trong thư mục Kit cục bộ đã chọn. | Kiểm tra tên Kit và nguồn cục bộ rõ ràng. |
| `6` | Target đã tồn tại và không thể thay thế nếu thiếu `--force`, hoặc route project trỏ vào bản cài cấp người dùng. | Xác minh ownership và route; chỉ dùng `--force` sau khi xem lại phạm vi ghi đè. Với route cấp người dùng, chạy lại với `--global` hoặc từ thư mục project khác. |

Ý nghĩa mã thoát phụ thuộc từng lệnh. Đặc biệt, đừng diễn giải việc từ chối trên
TTY theo cam kết mã thoát dùng chung `3`.

## Khôi phục sau bản cài thất bại hoặc buộc ghi đè

Khi đầu ra có recovery snapshot, hãy kiểm tra snapshot trước khi thay đổi thêm
tệp:

```bash
ak backups show <id>
ak backups verify <id>
```

Một số snapshot nằm dưới restore root do AgentKit quản lý có thể được áp dụng
bằng `ak backups restore <id>`. Ngược lại, bản cài buộc ghi đè trong project có
thể báo một thư mục dữ liệu snapshot để khôi phục thủ công vì đầu ra đó nằm ngoài
restore scope thông thường. Hãy làm theo phương thức khôi phục trong kết quả;
đừng giả định mọi snapshot đều dùng cùng một lệnh restore.

Sau khi khôi phục hoặc cài đặt, hãy mở lại runtime đích và gọi một Skill đã cài.
Nếu runtime không tìm thấy Skill, hãy kiểm tra target, project scope hay user
scope, và Claude native hay plugin mode trước khi cài lại.

## Đọc kết quả chiếu Hook

Phần tổng hợp thành công báo các Hook event và script đã cài khi có. Disclosure
projection Hook dùng hai dòng riêng:

```text
Hook groups not projected: <count> group(s) - see warnings
Hook matchers narrowed (some tool matches unsupported on this target): <count> matcher(s) - see warnings
```

Sau đó, lệnh in phần tổng hợp nêu rõ hành động cho từng drop hoặc narrow. Full
drop gỡ group; narrow giữ handler trên matcher atom được hỗ trợ.

Với Codex, Engineer có một group task-state `PostToolUse` bị drop hoàn toàn và
hai matcher dùng chung bị narrow. Marketing không có full drop và có ba narrow.
Cài đặt vẫn thành công: đây là giới hạn target, không phải Hook đã được sửa hoặc
lỗi cài đặt nghiêm trọng.
