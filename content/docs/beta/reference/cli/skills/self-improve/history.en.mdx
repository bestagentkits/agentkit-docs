Use `ak skills self-improve history` to see what the session-end Hook
recorded. It lists stored events whatever the current consent, so it still
works after you turn recording off. The command is read-only.

## Usage

```bash
ak skills self-improve history [--skill <id>] [--limit <n>] [flags]
```

```bash
ak skills self-improve history
ak skills self-improve history --skill ak-cook --limit 10 --json
```

## Options

| Flag | Default | Description |
| --- | --- | --- |
| `--skill <id>` | All skills | Only events of this skill id. |
| `--limit <n>` | `50` | Maximum events to list, from 1 to 5000. |

Shared flags are described in [CLI conventions](../cli-conventions).

## What it does

The command reads `AGENTKIT_HOME/state/self-improve/events.jsonl` and lists
the events newest first, including clean observations. It writes nothing, runs
no model, script, or network call, and skips the background update check.

## Output

Each text line shows the time, event id, runtime, skill id, and the signal
type, error class, and strength.

JSON uses `kind=skills.self_improve.history` with these fields under `data`:

```text
events[], total
events[]: schema_version, event_id, recorded_at, runtime, hook_event,
          session_ref, project_ref, skill, signal, fingerprint, evidence_refs[]
skill: id, digest
signal: type, strength, error_class
evidence_refs[]: kind, line, tool
```

`total` counts every matching event before `--limit` is applied.

## Exit behavior

| Exit | Meaning |
| --- | --- |
| `0` | Success, including an empty store. |
| `1` | The AgentKit home could not be resolved (`self_improve.home_unresolved`), or the event store could not be read (`self_improve.store_failed`). |
| `2` | Invalid flags or arguments, such as a `--limit` out of range (`self_improve.invalid_input`). |
| `4` | Another writer held the event store lock (`self_improve.store_busy`). |
