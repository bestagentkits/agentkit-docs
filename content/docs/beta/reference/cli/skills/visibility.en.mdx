---
title: ak skills visibility
description: Read or change who can see a skill you published on SkillX. Narrowing works with the linked account; widening needs dashboard approval.
---

Use `ak skills visibility` to read or change the visibility of a skill package
you published with [`ak skills publish`](./publish).

## Usage

```bash
ak skills visibility @<handle>/<slug> [--set public|unlisted|private] [--json]
```

Without `--set` the command only reads and prints the current visibility.

## Options

| Flag | Default | Description |
| --- | --- | --- |
| `--set <level>` | Read only | New visibility: `public`, `unlisted` or `private`. |
| `--json` | Off | Write one JSON envelope instead of human output. |

Shared flags are described in [CLI conventions](../cli-conventions).

## Narrowing and widening

- **Narrowing** (for example `public` to `unlisted`, or to `private`) works with
  the token from your linked agentkit.best account and applies at once.
- **Widening** (for example `private` to `public`) is never applied by the CLI.
  SkillX asks you to approve it on the SkillX dashboard, and the command exits
  `7` until you do. Run the command again after approving.

## Requirements

SkillX must be on, after `ak update --ssot` or with `AGENTKIT_SKILLX=1`. The
command uses your linked agentkit.best account first and falls back to
`SKILLX_TOKEN`.

## Exit behavior

| Exit | Meaning |
| --- | --- |
| `0` | Read, or changed. |
| `1` | Command failure: SkillX offline, or the linked account or `SKILLX_TOKEN` missing, revoked or expired. |
| `2` | SkillX disabled, or invalid flags, name or level. |
| `5` | The package was not found. |
| `6` | The change conflicts with the current state of the package on SkillX. |
| `7` | Widening needs approval on the SkillX dashboard. |
