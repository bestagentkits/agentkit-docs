---
title: ak skills evolution
description: Review, evaluate, apply, and roll back skill evolution candidates that ak skills improve recorded.
---

Use `ak skills evolution` to work with candidate records that
[`ak skills improve`](../cli/ak_skills_improve) wrote with `--candidate`. Each candidate pins
its evidence, skill, base, prior overlay, and overlay in its ID, and recording
never applies it. Running the group command itself prints help and exits `0`.

## Usage

```bash
ak skills evolution <command>
```

The group accepts no positional arguments and has no flags of its own.

## Subcommands

| Command | Outcome | Disk effect |
| --- | --- | --- |
| `ak skills evolution list` | List every verified candidate record. | Read-only. |
| `ak skills evolution show <candidateId>` | Show one candidate: diff, findings, blast radius, slots. | Read-only. |
| `ak skills evolution evaluate <candidateId>` | Re-run the offline evaluation. | Replaces the evaluation slot unless `--dry-run`. |
| `ak skills evolution apply <candidateId>` | Preview, or with `--yes` apply, the candidate into a personal kit. | Writes personal kit files and a rollback record with `--yes`. |
| `ak skills evolution rollback <candidateId>` | Undo an apply from its rollback record. | Restores personal kit files unless `--dry-run`. |

`list`, `show`, and every preview are read-only. `evaluate`, `apply --yes`, and
`rollback` write under the kit lifecycle lock. Publishing a personal kit stays a
separate, explicit [`ak skills kit`](../cli/ak_skills_kit) `publish <name> --private`.

## Candidate references

`show`, `evaluate`, `apply`, and `rollback` take the full candidate ID, its hex
part, or a unique prefix of at least 8 hex characters. A shorter prefix exits
`2`; a prefix that matches no record or more than one exits `5` with
`evolve.candidate_not_found`.

## Output

JSON kinds are `skills.evolution.list`, `.show`, `.evaluate`, `.apply`, and
`.rollback`; see each page for its fields. Candidate records live under
`AGENTKIT_HOME/state/skill-evolve/candidates/<id>/` and are verified against
their ID before they are shown.

## Exit behavior

| Exit | Meaning |
| --- | --- |
| `0` | Success, including an empty candidate store or a preview. |
| `1` | The candidate store could not be read, or a record failed verification (`store.corrupt`). `list` reports an unverified record and still exits `0`. |
| `2` | Invalid flags or arguments, or a candidate reference that is not an ID or a prefix of at least 8 hex characters. |
| `5` | No recorded candidate matches the reference, or a prefix matches more than one. |

`evaluate`, `apply`, and `rollback` add exits `4`, `6`, and `7`; see each page.
