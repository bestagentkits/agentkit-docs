---
title: ak skills kit init
description: Create a personal kit manifest that extends exactly one kit version and declares no overlay or fork.
---

Use `ak skills kit init` to create the personal kit `local/<name>` under
`AGENTKIT_HOME/kits/personal/<name>`. The new `personal-kit.yaml` extends one
kit version and declares no overlay or fork. Add overlays and forks by editing
the manifest, or a brand-new skill with
[`ak skills kit new-skill`](./index#add-a-new-skill), then preview with [`ak skills kit inspect`](./inspect). The
command never projects or applies.

## Usage

```bash
ak skills kit init <name> --extends <kit>[@<version>] [flags]
```

```bash
ak skills kit init mine --extends engineer --dry-run
ak skills kit init mine --extends engineer@installed
ak skills kit init mine --extends engineer@<version> --kits-dir ./kits --json
```

## Options

| Flag | Default | Description |
| --- | --- | --- |
| `--extends <kit>[@<version>]` | required | Kit to extend, as `<kit>`, `<kit>@installed` or `<kit>@<version>`. See [Choose the kit version](#choose-the-kit-version). |
| `--kits-dir <dir>` | `$AGENTKIT_KITS_DIR`, else `./kits`, else the cached installed build of the extended kit | Foundation kits directory. |
| `--dry-run` | `false` | Print the manifest and write nothing. |

Shared flags are described in [CLI conventions](../cli-conventions).

## Choose the kit version

The kit version must resolve offline, from the foundation kits directory or
from the cached build of a kit you installed with `ak kit init <kit> --global`.

| `--extends` | Version it pins |
| --- | --- |
| `<kit>` | The `kit.yaml` version in the foundation kits directory; if that directory does not hold the kit, the installed version. |
| `<kit>@installed` | The installed version, so you do not have to look it up; if no install is recorded, the version in the foundation kits directory. |
| `<kit>@<version>` | Exactly that version. |

The installed version is the highest kit version that a remote global install
of the kit recorded across your runtimes. With a standard install you need
neither `--kits-dir` nor `AGENTKIT_KITS_DIR`: `--extends engineer` or
`--extends engineer@installed` finds the installed build. The cached installed
build is used only when neither `--kits-dir` nor `AGENTKIT_KITS_DIR` is set;
setting either one turns that fallback off.

When the kit or its version cannot be found, the command exits `5` and names
the next step. Depending on the case, the message names the foundation kits
directory it searched and where that directory came from, says whether it also
searched the cached installed builds, and gives the installed version with the
`--extends` value that pins it. To fix it, run `ak kit init <kit> --global` to
install and cache the kit, point `--kits-dir` or `AGENTKIT_KITS_DIR` at a
directory that holds `<kit>/kit.yaml`, or drop `--kits-dir` and unset
`AGENTKIT_KITS_DIR` so `--extends <kit>@installed` resolves from the cached
installed build.

## Requirements

Without `--dry-run` the skill store must be on, after `ak update --ssot` or
with `AGENTKIT_SKILL_STORE=1`; with it off the command exits `2`. The command
only touches `AGENTKIT_HOME` and follows its global scope from any directory.
`--dry-run` works offline for every user.

## What it writes

Under the kit lifecycle lock and after store recovery, the command writes
`AGENTKIT_HOME/kits/personal/<name>/personal-kit.yaml` (mode `0644`) in one
journaled transaction that requires it to be absent. An existing directory of
that name is refused, whatever it holds, and nothing is overwritten.

## Output

The text output is one line: `created` (or `would create` on a dry run), the
kit, the version it extends, its skill count and the manifest path.

JSON uses `kind=skills.kit.init` with these fields under `data`:

```text
dryRun, personalKit, kit, version, path, manifest, skills
```

`manifest` is the YAML text of the new manifest and `skills` the number of
skills the kit composes.

## Exit behavior

| Exit | Meaning |
| --- | --- |
| `0` | The manifest was written, or the dry run finished. |
| `1` | Command failure, such as a path too long or a recovery that is required. |
| `2` | The skill store disabled, invalid flags or arguments, or a malformed manifest. |
| `4` | Another AgentKit operation holds the kit lifecycle lock. |
| `5` | The kit version or a skill it ships was not found. |
| `6` | A directory of that name already exists. |
| `7` | Revoked foundation. |
