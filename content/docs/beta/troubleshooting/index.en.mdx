## Safe diagnostic order

Run read-only checks before a recovery command:

```bash
ak --version
ak doctor --json
```

`ak doctor` checks installation and runtime health. By default it exits `0` even
when the report is unhealthy; inspect the `healthy` field. Use
`ak doctor --exit-on-fail` only when a script needs exit `1` for failing checks.

For a Claude Code install, `ak audit --json` checks recorded Kit content for
drift. It exits `0` when every audited Kit matches its manifest and `1` when it
finds drift or cannot complete the audit. An invalid Kit name exits `2`.

## Share diagnostics safely

Create a redacted support bundle instead of sending raw configuration or
environment files:

```bash
ak diagnostics export --json > agentkit-diagnostics.json
```

The export runs `ak doctor --json`, removes known secrets, email addresses, and
local path prefixes, and writes JSON to standard output. Exit `1` means the
doctor run or encoding failed; invalid flags exit `2`.

Review the exported file before sharing it. Never send API keys, license keys,
provider configuration, private keys, raw environment files, or session
transcripts.

## Keep recovery narrow

Do not delete `~/.agentkit`, `~/.claude`, `~/.codex`, or a project's runtime
directory to troubleshoot. Do not use `--force` as a routine retry. First record
the failing command, its exit code, the current directory, the target runtime,
and whether the install was project-scoped or global.

See the [CLI reference](../reference/cli) for the complete command and flag
surface.
