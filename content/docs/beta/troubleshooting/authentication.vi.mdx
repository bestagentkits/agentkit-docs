Dùng trang này khi đăng nhập thất bại, hiển thị sai tài khoản hoặc đã đăng nhập
nhưng không thể cài Kit.

## Kiểm tra danh tính trước quyền sử dụng

```bash
ak whoami --json
ak licenses --json
```

Hai lệnh thực hiện cùng một truy vấn entitlement hiện hành. `ak whoami` nhấn
mạnh tài khoản đang hoạt động; `ak licenses` trình bày cùng các grant theo từng
Kit với wording tập trung vào Kit. Danh tính tài khoản và grant của Kit vẫn là
hai fact riêng cần xác minh.

Kết quả chưa authentication từ `ak whoami --json` không phải lỗi lệnh: lệnh báo
`data.authenticated: false` và thoát `0`. Hãy đọc payload thay vì chỉ dựa vào mã
thoát. Nếu tài khoản đúng nhưng Kit không có trong `ak licenses`, cài lại không
thể thêm entitlement; hãy dùng tài khoản đã nhận Kit hoặc liên hệ hỗ trợ.

## Đăng nhập lại

Đăng nhập bằng email bắt đầu luồng OTP:

```bash
ak login --email you@example.com
```

Với user API key từ web profile:

```bash
ak login --api-key ak_live_... --no-interactive
```

Không bao giờ đặt API key thật vào shell history, source control, ảnh chụp hoặc
gói hỗ trợ. Đăng nhập bằng API key lưu private key cục bộ để xác thực lại; hãy
bảo vệ khóa đó như một credential.

Nếu CLI session cục bộ đã cũ, chỉ xóa session đó rồi đăng nhập lại:

```bash
ak logout
ak login --email you@example.com
ak whoami --json
ak licenses --json
```

`ak logout` idempotent và thoát `0` khi không có CLI session. Lệnh xóa
credential CLI cục bộ trước nhưng giữ nguyên paid App device session. Với
session email có thể gia hạn, việc thu hồi từ xa là best-effort; registry không
truy cập được không khiến CLI vẫn đăng nhập cục bộ.

Session cũ không có credential có thể gia hạn yêu cầu bạn đăng nhập lại. CLI nhận
ra tình trạng này ngay cả khi lỗi khác bọc lỗi authentication và thêm hướng dẫn
đăng nhập dành cho người dùng. CLI không tự thử lại thao tác hay fallback sang
đăng nhập bằng API key; hãy đăng nhập rồi tự chạy lại lệnh. Trong quá trình cập
nhật, lỗi gốc vẫn được truyền rõ ràng cùng hướng dẫn thay vì bị che mất.

## Lỗi đăng nhập và tạo API key

Từ CLI v2.18.1, `ak login --api-key` và việc tạo API key tại
`/account/api-keys` trả về thông báo lỗi cụ thể thay vì lỗi chung chung. Đối
chiếu với trường hợp bên dưới; với auth code mà CLI chưa xử lý riêng, CLI sẽ
dùng lại thông báo do server gửi về.

**Key hợp lệ nhưng tài khoản không có Kit Engineer/Marketing** (ví dụ tài
khoản chỉ có AgentKit App license). Server trả về `403 no_kit_entitlement`.
CLI báo key hợp lệ nhưng tài khoản không có Kit, và trỏ đến
`ak login --license-key`. Lấy license key từ `/account/licenses`:

```bash
ak login --license-key ak_license_... --no-interactive
```

**Key không xác định, đã thu hồi hoặc hết hạn.** Server trả về
`401 invalid_api_key` ("API key invalid or revoked"). Tạo hoặc xoay key mới
tại `/account/api-keys`, sau đó thử lại:

```bash
ak login --api-key ak_live_... --no-interactive
```

**Lỗi tra cứu phía server.** Server trả về `500`. Đây không phải vấn đề
credential — hãy thử lại với cùng key thay vì xoay key. Nếu vẫn tiếp tục lỗi,
làm theo [Nếu vẫn thất bại](#nếu-vẫn-thất-bại) bên dưới.

**Tạo key tại `/account/api-keys` trên tài khoản chỉ có App license.** Chỉ
chủ sở hữu Kit mới tạo được user API key: mua trực tiếp, seat trong team, hoặc
được cấp qua waitlist trả phí. Tài khoản chỉ có AgentKit App license sẽ thấy
"Kit License Required" và API trả về `403 APP_LICENSE_NOT_ELIGIBLE`. Hãy đăng
nhập App bằng license key thay vào đó:

```bash
ak login --license-key ak_license_... --no-interactive
```

Xem [API key hay license key](../reference/cli/login#api-key-hay-license-key)
để biết nên dùng credential nào.

## Kích hoạt App là kiểm tra khác

`ak login --license-key ak_license_... --no-interactive` kích hoạt App device session. Nó không
thay thế truy vấn entitlement hiện hành mà `ak licenses` dùng cho Kit. App
license hợp lệ, đăng nhập CLI thành công và quyền dùng paid Kit là các trạng
thái tài khoản có liên quan, nhưng trạng thái này không chứng minh trạng thái
khác.

## Lỗi mạng hoặc registry

Chạy kiểm tra sức khỏe có dùng mạng rồi so sánh với chế độ offline:

```bash
ak doctor --json
ak doctor --offline --json
```

Nếu chỉ lần chạy có mạng thất bại, hãy kiểm tra proxy, DNS, TLS và khả năng truy
cập registry. Không chuyển kênh hoặc ghi đè registry như cách sửa đăng nhập
thông thường. Lỗi stored session hoặc truy vấn registry thoát `1`; flag không
hợp lệ thoát `2`.

## Nếu vẫn thất bại

Export bằng chứng đã che dữ liệu nhạy cảm:

```bash
ak diagnostics export --json > agentkit-diagnostics.json
```

Xem lại tệp trước khi chia sẻ. Không đính kèm session file, OTP, API key hoặc
license key.
