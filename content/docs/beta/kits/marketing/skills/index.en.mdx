title: Choose a Marketing Skill
description: Start from a marketing outcome, compare focused Marketing workflows, and open the Skill guide that matches the work.
---

Marketing Skills are outcome-led workflows for research, planning, conversion,
content, creative production, and project operations. Start with the decision or
deliverable you need, then read that Skill's guide before invoking it. The guide
defines its required evidence, review gates, provider boundaries, and runtime
notes.

## Invoke a Skill

Claude Code and Cursor use the slash form; Codex uses the dollar-prefixed form.
For example:

```text
/ak:marketing-research "Compare the current market evidence for this segment"
```

```text
$ak:marketing-research "Compare the current market evidence for this segment"
```

Replace the Skill name and request with the workflow you choose. Publication,
account access, provider calls, spend, and external changes still require the
authority described by the individual guide. Runtime projections can also
differ; compare [Runtime adapters](../../../concepts/runtime-adapters).

## Start here

| Outcome | Suggested path |
| --- | --- |
| Build a strategy where evidence is still missing | Start with [`ak:marketing-research`](./marketing-research), then use [`ak:marketing-planning`](./marketing-planning) after the evidence and decisions are ready. |
| Prepare a product or feature launch | Use [`ak:launch-strategy`](./launch-strategy) for the phased launch, then [`ak:campaign`](./campaign) for a reviewable campaign plan or analysis. |
| Find and test a conversion problem | Use [`ak:funnel`](./funnel) to map the journey, choose the relevant CRO Skill, and use [`ak:ab-test-setup`](./ab-test-setup) when the hypothesis is evidence-backed. |
| Establish a content program | Use [`ak:content-marketing`](./content-marketing) for strategy and briefs, [`ak:write`](./write) for bounded copy work, then choose the relevant channel Skill. |

## Chain Skills into a workflow

Each Skill invocation is a separate, reviewable workflow. Pass the prior
Skill's approved evidence, decisions, artifacts, and unresolved questions into
the next request. A suggested chain does not grant publication, account,
provider, spending, or production authority. Use [`ak:handoff`](./handoff) when
another session or Kit takes ownership.

| Goal | Suggested chain |
| --- | --- |
| Move from evidence to a marketing strategy | [`ak:marketing-research`](./marketing-research) → [`ak:competitor`](./competitor) and [`ak:persona`](./persona) → [`ak:marketing-planning`](./marketing-planning) |
| Plan and measure a launch | [`ak:marketing-research`](./marketing-research) → [`ak:pricing-strategy`](./pricing-strategy) → [`ak:launch-strategy`](./launch-strategy) → [`ak:campaign`](./campaign) → [`ak:analytics`](./analytics) |
| Build a content program | [`ak:brand`](./brand) and [`ak:persona`](./persona) → [`ak:content-marketing`](./content-marketing) → [`ak:write`](./write) → [`ak:seo`](./seo), [`ak:email`](./email), or [`ak:social`](./social) → [`ak:analytics`](./analytics) |
| Improve a conversion step | [`ak:analytics`](./analytics) → [`ak:funnel`](./funnel) → [`ak:form-cro`](./form-cro) or [`ak:onboarding-cro`](./onboarding-cro) → [`ak:ab-test-setup`](./ab-test-setup) → [`ak:analytics`](./analytics) |
| Produce a reviewable creative asset | [`ak:brand`](./brand) → [`ak:design`](./design) → the selected creative Skill → [`ak:preview`](./preview) → [`ak:handoff`](./handoff) |
| Hand a campaign requirement to engineering | [`ak:marketing-planning`](./marketing-planning) → Marketing [`ak:handoff`](./handoff) → Engineer [`ak:plan`](../../engineer/skills/plan) → [`ak:cook`](../../engineer/skills/cook) → [`ak:test`](../../engineer/skills/test) → Engineer [`ak:handoff`](../../engineer/skills/handoff) back to Marketing |

Stop the chain when evidence is missing, a review rejects an artifact, or the
next step requires unavailable authority. Resume from that prerequisite instead
of filling the gap with assumptions.

## Choose by outcome

### Research and choose direction

- [`ak:marketing-research`](./marketing-research) produces a dated,
  attributable report for a bounded market question.
- [`ak:competitor`](./competitor) separates sourced competitor facts from
  inferences in analyses, battlecards, or comparison drafts.
- [`ak:persona`](./persona) keeps observed behavior, supplied facts,
  hypotheses, and sensitive data distinct when working with personas.
- [`ak:brand`](./brand) turns approved brand inputs into reviewable guidelines,
  tokens, messaging rules, and asset checks.
- [`ak:marketing-planning`](./marketing-planning) creates a marketing decision
  artifact with phases, owners, measures, risks, and approvals.
- [`ak:pricing-strategy`](./pricing-strategy) develops evidence-led packaging
  and pricing options without treating them as approved prices.

### Plan acquisition and launches

- [`ak:campaign`](./campaign) plans or analyzes campaigns while keeping spend
  and launch actions behind approval gates.
- [`ak:launch-strategy`](./launch-strategy) creates a phased launch plan with
  channel roles, assets, measurement, and follow-through.
- [`ak:paid-ads`](./paid-ads) prepares paid-media strategy, audiences, copy,
  creative tests, and measurement without assuming account access.
- [`ak:affiliate-marketing`](./affiliate-marketing) designs partner economics,
  recruitment, compliance, fraud controls, and measurement.
- [`ak:referral-program-building`](./referral-program-building) designs rewards,
  tracking, fraud controls, messages, and measurement for a referral program.

### Improve conversion and measurement

- [`ak:funnel`](./funnel) maps stages and metrics or prioritizes observed
  drop-off and test opportunities.
- [`ak:form-cro`](./form-cro) reviews non-signup form friction, data necessity,
  accessibility, measurement, and test hypotheses.
- [`ak:onboarding-cro`](./onboarding-cro) audits post-signup activation and
  designs an evidence-led onboarding flow and experiments.
- [`ak:ab-test-setup`](./ab-test-setup) turns an evidence-backed hypothesis into
  a test plan with metrics, assumptions, guardrails, and decision rules.
- [`ak:analytics`](./analytics) turns approved marketing data into a KPI,
  attribution, experiment, funnel, or recurring performance report.

### Create and distribute content

- [`ak:content-marketing`](./content-marketing) develops a content strategy,
  calendar, audit, or brief without treating the plan as publication authority.
- [`ak:write`](./write) routes bounded copy work while preserving brand and
  evidence inputs and keeping publication separate.
- [`ak:seo`](./seo) covers audits, keyword research, and pSEO artifacts while
  separating provider queries and live search changes.
- [`ak:email`](./email) creates email drafts, flows, and sequence artifacts while
  keeping consent, compliance, deliverability, and sending separate.
- [`ak:social`](./social) creates platform-aware drafts and schedule artifacts
  without assuming credentials or publishing authority.
- [`ak:youtube`](./youtube) repurposes an authorized YouTube video into a blog
  post, infographic pack, or social-content draft.

### Produce branded experiences

- [`ak:design`](./design) routes an approved brief to the relevant visual
  deliverable workflow.
- [`ak:logo-design`](./logo-design) explores raster logo directions while
  keeping trademark, vector production, and launch decisions separate.
- [`ak:banner-design`](./banner-design) creates reviewable banner variants while
  keeping placement, spend, and publication separately approved.
- [`ak:youtube-thumbnail-design`](./youtube-thumbnail-design) generates branded
  thumbnail variants for review before upload.
- [`ak:video`](./video) prepares scripts, storyboards, or generated video packs
  with provider, rights, rendering, and publication gates.
- [`ak:frontend-design`](./frontend-design) implements an approved UI brief or
  visual reference with responsive, accessibility, and review gates.

### Operate reusable work

- [`ak:assets-organizing`](./assets-organizing) applies reviewable names and
  paths while preventing accidental moves, overwrites, or deletions.
- [`ak:preview`](./preview) opens project content or creates visual explanations
  while controlling file, browser, server, network, and Git effects.
- [`ak:handoff`](./handoff) creates a concise, redacted continuation record for
  a fresh session.
- [`ak:docs`](./docs) creates, updates, or summarizes the smallest useful
  documentation route for a marketing project.
- [`ak:slides`](./slides) builds a responsive HTML presentation from an approved
  narrative and evidence set without publishing it.

## Keep the Kit boundary visible

Some names, including `ak:ask`, `ak:plan`, `ak:cook`, `ak:design`, and
`ak:preview`, also appear in Engineer Kit. A shared name does not mean the two
Kits ship the same workflow. Use the guide under the Kit you installed and keep
that Kit's inputs, gates, and runtime notes attached to the task.

Skills are only one layer of Marketing Kit. Review [Marketing
Agents](../agents) for specialist roles, [Hooks and runtime](../hooks) for
projected automation, and [Lifecycle and recovery](../lifecycle) for refresh,
uninstall, and ownership behavior. Use [Installing
kits](../../../guides/installing-kits) to choose target, scope, delivery mode,
and installed Skill selection, or return to the [Marketing Kit
overview](../../marketing).
