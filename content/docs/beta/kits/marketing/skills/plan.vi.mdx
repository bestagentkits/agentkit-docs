Dùng `ak:plan` để biến requirement marketing hoặc kỹ thuật đã xác định thành
plan file bền vững để review. Variant do Marketing sở hữu có thể tạo plan fast,
researched, parallel, two-approach, sửa CI và conversion-rate-optimization. Nó
cũng có thể validate plan hoặc đổi khả năng hiển thị trong index sau xác nhận.
Skill không triển khai plan.

Đây không phải workflow planning cùng tên của Engineer Kit. Source, subcommand,
file shape, route CRO và giới hạn dependency riêng của Skill này được áp dụng.

## Chọn ak:plan cho handoff bền vững

### Dùng ak:plan khi

- Website marketing, analytics, automation, content system hoặc thay đổi hỗ trợ
  campaign cần instruction implementation theo phase.
- Bạn muốn CRO plan dựa trên issue, content đã duyệt hoặc trang đã kiểm tra.
- Bạn cần so sánh hai cách implementation hoặc xác định phase song song với
  file ownership độc quyền.
- Bạn cần plan cho GitHub Actions failure sau khi thu thập URL và log của run.
- Bạn muốn validate giả định trong plan hiện có trước khi code.

### Chọn workflow khác khi

- Outcome hoặc hướng đi chưa thống nhất. Dùng [`ak:brainstorm`](./brainstorm).
- Bạn chỉ cần tư vấn kỹ thuật. Dùng [`ak:ask`](./ask).
- Bạn muốn thực thi technical plan đã chấp nhận. Dùng [`ak:cook`](./cook).
- Bạn có defect cụ thể cần chẩn đoán và sửa. Dùng [`ak:fix`](./fix).
- Bạn cần chiến lược marketing rộng thay vì implementation hoặc CRO plan. Dùng
  domain planning Skill phù hợp trong [Marketing Kit](../../marketing).

## Chuẩn bị input và quyền planning

Trước khi gọi Skill:

- Hoàn thành [Làm quen](../../../getting-started/onboarding) và xác nhận bản cài
  Marketing Kit, runtime cùng scope.
- Cung cấp outcome, constraint, non-goal và success criteria quan sát được.
- Mở project liên quan và cho phép Skill đọc repository instruction, tài liệu,
  source, test cùng plan hiện có.
- Quyết định có cho phép tạo plan file local hay không. Planning không chỉ đọc:
  mode tạo sẽ ghi plan directory và phase file.
- Với `ci`, cung cấp GitHub Actions URL và bảo đảm `gh` đã cài, authorized nếu
  cần truy cập log.
- Với bằng chứng CRO từ URL, screenshot, video hoặc provider, duyệt riêng quyền
  browser, network hay multimodal cần thiết.

| Runtime | Cách gọi | Ranh giới khả dụng |
| --- | --- | --- |
| Claude Code | `/ak:plan ...` | Hỗ trợ delivery native và plugin rõ ràng; planning surface được route cũng phải khả dụng. |
| Cursor | `/ak:plan ...` | Cách gọi slash đã được người dùng xác minh; không chứng minh mọi routed dependency đều khả dụng. |
| Codex | `$ak:plan ...` | Dùng discovery Skill native của Codex; routed SlashCommand và helper Skill có thể không map giống nhau. |

### Chọn đúng route

| Subcommand | Outcome | Ranh giới quan trọng |
| --- | --- | --- |
| Không có subcommand | Enhance task prompt rồi route tới fast hoặc hard plan theo độ phức tạp | Phải dừng sau review plan |
| `fast` | Tạo implementation plan từ bằng chứng repository, không có research stage | Vẫn đọc context project hiện tại và ghi plan file |
| `hard` | Thêm research và scouting có giới hạn trước khi tạo plan | Research phụ thuộc source khả dụng; breakable assumption cần failure signal cùng response điều chỉnh-hoặc-lập-lại-plan |
| `parallel` | Tạo phase, dependency graph, execution strategy và file-ownership matrix độc quyền | Plan không thực thi các phase |
| `two` | Tạo hai cách tiếp cận chi tiết cùng trade-off và recommendation | So sánh load-bearing assumption, điều kiện thất bại đầu tiên, worst plausible case và switching cost của mỗi hướng; không triển khai hướng nào |
| `cro` | Tạo conversion-optimization plan từ issue và bằng chứng đã kiểm tra | Không đảm bảo conversion uplift hay business result |
| `ci` | Phân tích bằng chứng GitHub Actions và lập plan sửa | Cần run URL cùng `gh` access dùng được để lấy log |
| `validate` | Interview về giả định, rủi ro, trade-off, kiến trúc và scope quan trọng | Cập nhật validation summary của plan nhưng không sửa phase file |
| `archive` | Tùy chọn ghi journal rồi đổi visibility của plan đã chọn trong AgentKit index sau xác nhận | Giữ `plan.md` và phase file canonical trên disk; không xóa |

Argument shape canonical là
`[archive|ci|cro|fast|hard|parallel|two|validate] [task]`.

## Hiểu các giai đoạn tạo plan

1. **Resolve plan context.** Nếu có active plan hoặc plan được gợi ý theo branch,
   Skill hỏi dùng hoặc activate thay vì âm thầm thay thế. Khi `fast` hoặc `hard`
   tạo plan mới, Skill tìm `set-active-plan.cjs` theo cách động vì path cài đặt
   thay đổi theo runtime, rồi đánh dấu directory mới là active.
2. **Làm rõ task.** Skill chỉ hỏi chi tiết cần thiết để tạo plan hữu ích.
3. **Tải route đã chọn.** Argument đầu chọn reference workflow tương ứng; nếu
   không có, Skill chọn fast hoặc hard theo độ phức tạp.
4. **Kiểm tra bằng chứng.** Route tạo đọc instruction project cùng tài liệu,
   source, test và plan liên quan. Route research thêm researcher có giới hạn;
   CRO có thể kiểm tra page hoặc media evidence đã cung cấp.
5. **Ghi plan.** Route tạo sinh `plan.md`, phase file và report theo route trong
   plan directory đã cấu hình.
6. **Review trước delivery.** Skill yêu cầu bạn kiểm tra plan và không bắt đầu
   implementation.

Plan dùng frontmatter gồm `title`, `description`, `status`, `priority`, `effort`,
`branch`, `tags` và `created`. Overview liên kết tới phase file; mỗi phase ghi
context, requirement, related file, implementation step, todo, success criteria,
risk, security consideration và next step. Trên route `hard`, risk dựa trên
breakable assumption còn ghi observable signal cho thấy assumption đã hỏng và
response điều chỉnh hoặc dừng để lập lại plan.

## Tách planning khỏi hành động bên ngoài

<Callout type="warn" title="Plan không phải phê duyệt hành động">
  `ak:plan` có thể ghi planning artifact local, cập nhật validation summary
  hoặc đổi visibility trong index qua `archive`. Nó không cấp quyền sửa code hay
  content, publish, launch campaign, thay provider account, liên hệ audience,
  spend, commit, push hoặc deploy.
</Callout>

Với CRO, hãy coi framework đóng gói là planning guidance. Xác minh claim, yêu
cầu privacy, accessibility, message match, tracking và experiment design bằng
bằng chứng cùng policy hiện tại. Không publish claim số liệu về uplift,
conversion, revenue hay thời gian từ heuristic chung.

Với `archive`, phải xác nhận trước khi đổi index visibility. Plan file canonical
vẫn ở repository. Xóa vật lý là thao tác riêng, rõ ràng của người dùng và không
thuộc route archive của Skill này.

## Review plan và bằng chứng

Kết quả hữu ích nên có:

- `plan.md` ngắn với objective, status, priority, effort, branch, tag, phase link
  và progress.
- Phase file gồm requirement, related file, implementation step, success
  criteria, risk, security consideration và next step.
- Artifact research, scout hoặc report chỉ khi route đã chọn cần.
- Với `parallel`, dependency graph và file ownership không chồng lấn.
- Với `two`, hai cách tiếp cận khả thi khác biệt, load-bearing assumption, điều
  kiện thất bại đầu tiên, worst plausible case, switching cost cùng
  recommendation ưu tiên khả năng đảo hướng khi thiếu bằng chứng quan trọng.
- Với `validate`, quyết định đã xác nhận và item cần revise plan.
- Câu hỏi chưa giải quyết được đặt cuối cùng.

Trước khi chuyển plan cho `ak:cook`, xác minh path và contract khớp project hiện
tại, success criteria quan sát được, external effect được nêu thành phê duyệt và
không có private data hay claim hiệu suất không được hỗ trợ.

## Xử lý sự cố planning

| Triệu chứng | Bước tiếp theo an toàn |
| --- | --- |
| Runtime không tìm thấy `ak:plan` | Xác nhận target và scope, khởi động lại runtime, rồi làm theo [Runtime không tìm thấy Skill hoặc Agent](../../../troubleshooting/runtime-cannot-find-skill-or-agent). |
| Skill báo active hoặc suggested plan | Review path chính xác và chọn tiếp tục, activate hoặc tạo plan mới. |
| Routed surface `/plan:fast` hoặc `/plan:hard` không khả dụng | Dừng và báo dependency thiếu. Marketing Kit không export command catalog nên chỉ cài `ak:plan` không chứng minh mọi SlashCommand nội bộ chạy được trên mọi runtime. |
| `ci` không đọc được run | Xác minh URL hoặc run ID, bản cài `gh`, authorization, repository access và network. Không dựng chẩn đoán từ log thiếu. |
| Bằng chứng CRO chưa đủ | Đánh dấu giả định và data gap hoặc thu thập screenshot, content, URL evidence hay metric đã duyệt trước khi hoàn tất plan. |
| Plan file được ghi sai nơi | Dừng, kiểm tra Plan Context cùng naming path đã cấu hình và không di chuyển hay xóa tệp không liên quan. |
| `archive` không dùng được `ak plan` | Giữ nguyên plan file, báo index change bị bỏ qua và không tạo archive directory tùy ý. |

## Biết giới hạn hiện tại

- Một số route phụ thuộc Plan Context được inject, `planning` Skill, routed
  SlashCommand, Agent hoặc tool. Projection `ak:plan` không đảm bảo những
  dependency đó khả dụng giống nhau trên mọi runtime.
- Package không export Marketing command catalog; tham chiếu `/plan:*` là
  dependency workflow nội bộ, không phải command Marketing công khai bổ sung.
- Research và CRO planning bị giới hạn bởi dữ liệu được duyệt, nguồn hiện tại
  và browser hay provider access khả dụng.
- Plan không đảm bảo conversion, revenue, performance, chất lượng
  implementation, provider behavior hay delivery date.

Chỉ tiếp tục với [`ak:cook`](./cook) sau khi duyệt technical plan hoặc quay lại
[Tổng quan Marketing Kit](../../marketing) cho domain workflow.
