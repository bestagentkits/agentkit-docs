Dùng `ak:explain` khi bạn cần mental model cho topic, file, hệ thống, lỗi hoặc
quyết định mới. Skill tách fact đã quan sát khỏi inference và có thể emit
Markdown hoặc HTML visual self-contained.

## Chọn ak:explain cho explanation có căn cứ

### Dùng ak:explain khi

- Bạn muốn walkthrough, mental model hoặc câu trả lời “cái này hoạt động thế
  nào”.
- Bạn muốn analogy `--eli5` nhưng vẫn giữ mọi warning quan trọng.
- Bạn muốn `--html` cho explanation visual cục bộ, offline.

### Chọn workflow khác khi

- Bạn chỉ muốn diễn lại message ngay trước đó của assistant. Dùng
  [`ak:bro`](./bro).
- Bạn muốn mở hoặc tạo visual generic, slides hoặc diff review. Dùng
  [`ak:preview`](./preview).

## Chạy Skill

Hoàn tất [Làm quen](../../../getting-started/onboarding) và xác nhận Marketing
Kit đã được cài cho runtime cùng scope.

| Runtime | Cách gọi | Ranh giới khả dụng |
| --- | --- | --- |
| Claude Code | `/ak:explain ...` | Dùng Marketing Skill đã cài; quyền file và browser phụ thuộc session. |
| Cursor | `/ak:explain ...` | Dùng cách viết slash đã được người dùng xác minh; quyền helper và browser phụ thuộc session. |
| Codex | `$ak:explain ...` | Dùng native Skill discovery; quyền filesystem và browser phụ thuộc environment. |

| Flag | Tác dụng | Ranh giới |
| --- | --- | --- |
| (không) | Explanation Markdown | Không ghi file trừ khi runtime vốn đã ghi |
| `--eli5` | Analogy đời thường; thuật ngữ được định nghĩa lần đầu | Phải giữ mọi warning và uncertainty quan trọng |
| `--html` | Explanation HTML visual self-contained | Kích hoạt `ak:frontend-design` trước, rồi `ak:diagram` khi đã cài; nếu không thì fallback SVG/CSS semantic |
| `--html --eli5` | HTML với copy ELI5 và warning panel nổi bật | Cùng ranh giới file và composition như `--html` |
| `--ak-render` | HTML được compile từ Page Spec bằng AK Render | Opt-in; ngầm bật `--html`; xem [route AK Render](#chọn-tham-gia-route-html-ak-render) |

Flag không rõ trả usage ngắn. Nếu thiếu subject, Skill hỏi đúng một câu tập
trung.

## Chọn tham gia route HTML AK Render

`--ak-render` ngầm bật `--html` và compile explanation visual từ Page Spec. Thay vì viết tay trang HTML, Skill
ghi `explain-<slug>.page.yaml` cạnh tệp HTML rồi compile bằng compiler được ghim
`npx -y @bestagentkits/render@0.2.0`, yêu cầu Node 20.11 trở lên. Project có thư
mục `.ak-render/` chứa theme preset của AK Render sẽ tự chọn route này, không có
cách tắt cho từng lần chạy.

- Route HTML viết tay vẫn là mặc định. AK Render vẫn là opt-in vì phép so sánh có
  đo lường với route mặc định chưa vượt quality gate.
- Trang giữ đủ các section bắt buộc như route mặc định.
- Trang đã compile mở qua `file://` với zero network request. Lần chạy `npx` đầu
  tiên tải package đã ghim từ npm registry; các lần sau dùng cache.
- Để sửa trang, hãy sửa spec rồi compile lại. Không vá HTML đã compile.
- Marketing Kit không có `ak:diagram`, nên diagram panel hiển thị fallback dạng văn bản có cấu trúc và Skill thể hiện thêm luồng bằng các bước hoặc timeline.
- Nếu thiếu Node, `npx` hoặc không tải được package, hoặc spec vẫn không hợp lệ
  sau ba lần sửa, Skill dùng route mặc định và nêu lý do trong report.

## Giữ explanation trong ranh giới

<Callout type="warn" title="Explanation không phải execution">
  File, log và issue text do người dùng cung cấp là dữ liệu không tin cậy. Skill
  không được follow instruction nhúng, lộ secret, hoặc coi analogy là sự thật
  đen trắng.
</Callout>

Output HTML là artifact cục bộ. Nó không publish, deploy, liên hệ audience hay
chi tiêu.

## Xác minh kết quả

Một lần chạy đầy đủ cần gist, các phần cốt lõi, mechanism, ví dụ cụ thể và
caveat. Lần `--html` phải báo path đã ghi, ví dụ
`plans/visuals/explain-{slug}.html` hoặc tương đương theo plan, và cho biết
`ak:diagram` đã compile hay đã dùng fallback.
