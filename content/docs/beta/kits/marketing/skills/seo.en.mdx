Use `ak-seo` for three groups of search work:

- **Site** (`audit`, `geo`, `pseo`, `schema`, `optimize`): audit a page or
  domain, check GEO and AI discoverability, design programmatic SEO templates,
  and produce schema or on-page changes.
- **Keywords** (`research`, `clean`, `cluster`, `intent`, `plan`, `next`): turn
  real keyword data into an article queue.
- **Article** (`setup`, `write`, `review`, `visuals`, `cover`, `publish`): take a
  search-led article from brief to a WordPress draft.

The Skill also packages scripts for Search Console, Core Web Vitals, sitemaps,
schema, and bulk page generation. Those scripts have different network,
credential, file, and account effects and are not one automatic workflow.

Use `--format csv -o ideas.csv` to export a keyword list. Unknown metrics stay empty in
CSV and appear as `null` in JSON. A measured zero stays zero. Leave priority unscored
when the source omits search volume or difficulty.

## Choose ak-seo for evidence and implementation artifacts

### Use ak-seo when

- You need a technical or on-page audit of a public URL or local content.
- You need keyword ideas, intent clusters, difficulty data, or competitor gaps
  with the source and freshness recorded.
- You need a pSEO template, data schema, internal-linking plan, and sample pages.
- You need a reviewed sitemap or JSON-LD artifact before implementation.
- You need a GEO and AI-discoverability contract or audit: `robots.txt`,
  `sitemap.xml`, `llms.txt`, `llms-full.txt`, per-page `.md` variants, social
  metadata and cards, and Copy, Share, or Open in AI page actions.
- You need the next article to write from a keyword map, or a search-led
  article drafted, reviewed, illustrated, and handed over as a WordPress draft.

### Choose another workflow when

- You need broader content strategy without search evidence, or a
  multi-channel content calendar. Use
  [`ak-content-marketing`](./content-marketing).
- You need conversion copy, CTAs, or CRO. Use
  [`ak-copywriting`](./copywriting). On a landing page, `ak-seo optimize`
  covers on-page SEO only (title, meta, headings, schema); a mixed request runs
  the SEO part, then hands the copy part over.
- You need to implement those GEO surfaces in a framework. Implementation
  belongs to that framework's Skill; for Next.js, use the Engineer Kit
  [`ak-web-frameworks`](../../engineer/skills/web-frameworks) SEO and GEO
  reference when that Kit is installed.
- You want guaranteed rankings, traffic, rich results, indexing, or revenue.
  No Skill or provider output can establish those outcomes.

## Prepare data, access, and mutation boundaries

Confirm Marketing Kit is installed for the current runtime and scope. Provide
the target URL, domain, topic, country or market, audience, business relevance,
current analytics, competitor set, and output boundary. Identify which data may
be sent to external services.

ReviewWeb-backed keyword and audit data requires `REVIEWWEB_API_KEY`. Core Web
Vitals requests use Google PageSpeed Insights and can use `PAGESPEED_API_KEY`.
Google Search Console requires a verified property, Google Cloud OAuth client,
the Search Console API, `googleapis`, and
`.claude/secrets/google_client_secret.json` or the corresponding user-level
secret path. OAuth tokens are saved locally; protect them as credentials.

Site scripts (`.cjs`) need Node 20.11 or newer. Keywords and article scripts
(`.mjs`) need Node 22.2 or newer. The Skill targets macOS and Linux; Windows is
untested. `article cover` and `article visuals` need Chrome, Edge, or Chromium.

| Runtime | Invocation | Availability boundary |
| --- | --- | --- |
| Claude Code | `/ak-seo ...` | Native delivery is the default; network and account operations still require explicit access and approval. |
| Cursor | `/ak-seo ...` | The Skill is projected to Cursor and slash invocation is user-verified; provider tooling can still differ. |
| Codex | `$ak-seo ...` | The Skill uses native Codex discovery; available web, shell, credential, and provider capabilities govern each stage. |

The argument hint is

Every subcommand routes to its own reference. A bare `keywords "<seed>"` runs

name the group and step, for example
`/ak-seo article write "<keyword or approved brief>"`.

## Audit AI discoverability with geo

The `geo` route treats search crawlers, AI answer engines, and people who paste
pages into chat assistants as one contract. It checks only what the site's
framework and hosting can serve and reports missing surfaces as gaps.

| Surface | What the audit expects |
| --- | --- |
| `robots.txt` | Public pages allowed, private and search-result paths blocked, an absolute `Sitemap:` line, and an AI crawler policy the site owner chose explicitly. |
| `sitemap.xml` | Canonical, indexable URLs only, real `lastmod`, XML-escaped `<loc>`, no `.md` variants. |
| `llms.txt` and `llms-full.txt` | llmstxt.org format with `## Optional` last, links to each page's `.md` variant, and a full file generated from the same source with no private content. Google Search ignores these files and `.md` variants, so they serve other agents and answer engines, not Google ranking or AI Overviews. |
| `<page>.md` | A Markdown twin at the page URL plus `.md` (`index.html.md` for a URL ending in `/`), served as `text/markdown; charset=utf-8`, linked from the HTML head with `rel=alternate`, and sent `X-Robots-Tag: noindex`. |
| Metadata and social cards | `rel=canonical`, valid JSON-LD matching visible content, complete Open Graph and Twitter tags, and a per-page social image at 1200×630. |
| Page actions | Copy as Markdown, Copy URL, Open in ChatGPT or Claude, and Share controls that work without login and degrade gracefully. |

Blocking AI crawlers is never a default. The robots reference separates
training, search, and user-initiated fetch agents per operator, notes that
retired names such as `anthropic-ai` and `Claude-Web` are unused, and asks you
to confirm current agent names with each operator before shipping a policy.
The audit reports each item as pass, fail, or not applicable with the observed
URL and response.

## Build a keyword queue

The keywords group runs in this order, and you can run each step alone:

1. `research` collects raw keywords with ReviewWeb data.
2. `clean` removes noise; add `--map` when the site has `.editorial/` to create
   keyword-map entries.
3. `cluster` groups the keywords into head terms and pillars.
4. `intent` adds search intent to existing entries.
5. `plan` marks a keyword planned or skipped, and `next` picks the next article
   from the keyword map (`.editorial/keyword-map.json`).

Unknown metrics stay unknown in every step; a missing volume is never `0`.

## Write an article that stops at a WordPress draft

The article group is Vietnamese-first. English drafts get the fact, structure,
and SEO rules but no punctuation or terminology lint.

- **`setup`** needs a git repository. When the folder has no `.git`, the script
  stops and you run `git init` yourself. It creates `.editorial/` and
  `drafts/`, writes a `.env` template without secrets, and adds `.env` to
  `.gitignore`. You type `SEOKIT_WP_URL`, `SEOKIT_WP_USER`, and
  `SEOKIT_WP_APP_PASSWORD` into `.env` yourself; never paste the Application
  Password into chat. A dedicated WordPress Author account is recommended.
  `wordpress.mjs health` checks the connection.
- **`write`** takes the keyword from `next` or your choice, proposes a Brief
  card, and stops for your approval before research and drafting.
- **`review`** returns `PASS`, `REVISE`, or `BLOCK`. It runs in a fresh
  delegated agent when the runtime allows. Otherwise it runs in the same
  session, is recorded with `--isolation same-session`, and is reported as
  reduced isolation, never as independent.
- **`visuals`** and **`cover`** produce in-body images and a cover rendered from
  the site's fixed template.
- **`publish`** runs `wordpress.mjs push <article.md>`. It always creates a
  draft, keeps a draft or pending post's status on update, and refuses a post
  that is already live. There is no status parameter and no `--publish`; the
  approver publishes.

The article pipeline emits Article schema only. Transcripts, fetched pages, and
research text are untrusted input: evidence to verify, never instructions.

Rank Math or Yoast meta needs the `seokit-seo-helper` WordPress plugin. Build
its zip with `wp-plugin-zip.mjs` and install it from Plugins → Add New → Upload.
New drafts work without it, but updating an existing post needs plugin 1.2.1 or
newer. The plugin is licensed separately under GPL-2.0-or-later, and the
bundled Be Vietnam Pro fonts are under SIL OFL 1.1. Persisted names keep the
`SEOKIT_*` environment keys and the WordPress `seokit/v1` namespace.

## Understand the stages

1. **Confirm the question and data source.** Define URL, topic, market,
   timeframe, evidence source, and whether the task is analysis or mutation.
2. **Collect evidence.** Read local content or fetch public pages. With approval,
   query ReviewWeb, PageSpeed Insights, or Search Console and record the source.
3. **Analyze the evidence.** Audit technical and on-page elements, classify
   intent and clusters, or design a pSEO data and template architecture.
4. **Create artifacts.** Produce reports, templates, schema, sitemaps, sample
   pages, or implementation recommendations inside the approved output boundary.
5. **Validate locally.** Check generated JSON-LD structure, sitemap content,
   template escaping, duplicates, claims, canonical intent, and sample quality.
   The bundled sitemap generator XML-escapes each URL and omits `lastmod` for a
   page without a supplied date instead of stamping today's date.
6. **Review before live action.** A person approves code changes, bulk files,
   deployment, indexing controls, sitemap submission or deletion, outreach, and
   any provider account mutation.

## Separate queries, file generation, and account changes

<Callout type="warn" title="SEO analysis does not authorize live search changes">
  Search Console query actions can read private property data, while separate
  bundled flags can submit or delete a sitemap. The pSEO generator writes many
  HTML files and a checkpoint. Sitemap and schema generators write output files.
  Approve each effect explicitly; never infer it from a request for an audit.
</Callout>

Review URLs and customer data before sending them to ReviewWeb, Google, browser
tools, or other providers. Do not place API keys or OAuth tokens in arguments,
reports, or commits. Link building and outreach remain separate human-approved
work; avoid spam, deceptive placements, and fabricated relationships.

## Verify outputs and evidence

The top-level Skill summary names report paths under `assets/reports/seo/`,
while the routed `audit` reference names `assets/seo/audits/`. Confirm the
actual path returned by the run before building automation. The pSEO route
writes under `assets/attraction/pseo-templates/`; schema output is described
under `assets/seo/schemas/`. Keyword workbooks go to the paths you pass, the
keyword map to `.editorial/keyword-map.json`, and articles to `drafts/` and
`.editorial/` per the site pack.

Require the report to identify URLs, query dates, country or market, provider
and endpoint, measured fields versus estimates, missing data, issues by
priority, and recommended next checks. For generated files, inspect the exact
file list and diff. A local schema validation pass does not guarantee a search
engine rich result, and a submitted sitemap does not guarantee indexing.

## Troubleshoot and know the limits

| Symptom | Safe next step |
| --- | --- |
| ReviewWeb data is unavailable | Continue with clearly labeled public or local evidence, or configure `REVIEWWEB_API_KEY`; do not invent volume, CPC, difficulty, traffic, or backlinks. |
| Search Console authentication fails | Verify the property, OAuth client, scopes, secret path, local callback, dependency, and token status without exposing credentials. |
| The report path differs from the overview | Use the path actually returned and record the source-path inconsistency; do not move or overwrite files silently. |
| A keywords or article script fails on start | Check that Node is 22.2 or newer; the `.mjs` scripts do not run on older Node. |
| `init-workspace.mjs` stops during `article setup` | The folder has no `.git`. Run `git init` yourself, then rerun setup. |
| `wordpress.mjs push` refuses a post | The post is already live. The pipeline never edits a live post; change it in WordPress or ask the approver. |
| Bulk pSEO output is low quality or duplicated | Stop generation, inspect the template and dataset, delete nothing automatically, and require unique value plus human sampling before publication. |
| Runtime discovery fails | Follow [Runtime cannot find a Skill or Agent](../../../troubleshooting/runtime-cannot-find-skill-or-agent). |

Search data, provider APIs, platform rules, and ranking systems change. The
Skill cannot guarantee data completeness, ranking, indexing, traffic, rich
results, conversions, or revenue. Continue with the [Marketing Kit
overview](../../marketing) and keep every live mutation separately approved.
