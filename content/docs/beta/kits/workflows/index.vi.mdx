Workflow hữu ích khi một Skill không thể sở hữu an toàn toàn bộ kết quả. Hãy bắt
đầu từ tình huống hiện tại, chọn chuỗi ngắn nhất tạo ra bằng chứng cần thiết và
dừng ở mọi human gate hoặc authority gate.

## Dùng cấu trúc năm giai đoạn

Phần lớn chuỗi đáng tin cậy theo cấu trúc:

```text
understand → decide → execute → verify → deliver
```

Rút gọn giai đoạn khi task nhỏ. Một thay đổi một file với acceptance criteria
rõ có thể chỉ cần `ak:cook --fast`; thay đổi authentication hoặc payment vẫn
cần planning, security, testing và review riêng.

## Chọn theo tình huống

| Bạn đang có gì | Bắt đầu tại đây | Recipe thực dụng |
| --- | --- | --- |
| Feature, refactor hoặc UI change đã rõ | [Software delivery](./software-delivery) | brainstorm khi cần → plan → cook → test → code-review |
| Requirement chưa rõ hoặc quyết định thiết kế ảnh hưởng lớn | [Planning và research](./software-delivery#planning-and-research) | scout/research → brainstorm → plan có gate → approval |
| Reproduction, error, test lỗi hoặc behavior flaky | [Debug và fix](./software-delivery#debug-and-fix) | debug → fix theo nguyên nhân → regression test → review |
| Local branch hoặc PR đã sẵn sàng review | [Review và ship](./software-delivery#review-and-ship) | review pending/PR → fix loop → test → ship đã cấp quyền |
| Auth, payment, public API, secret hoặc infrastructure change | [Delivery rủi ro cao](./software-delivery#high-risk-delivery) | domain Skill → plan có gate → implementation → security → review độc lập |
| Screenshot, design brief, React UI hoặc performance issue | [Frontend delivery](./software-delivery#frontend-delivery) | design → implementation → browser evidence → review |
| Có từ ba workstream độc lập | [Parallel delivery](./software-delivery#parallel-delivery) | plan song song → ownership cô lập → integration → verification độc lập |
| Launch, funnel, campaign hoặc content program | [Marketing growth](./marketing-growth) | evidence → plan → production có scope → measurement |
| Product delivery và launch phải khớp nhau | [Launch sản phẩm cross-Kit](./cross-kit-product-launch) | Marketing brief → Engineer evidence → đối chiếu launch |

Nếu chưa xác định được row, dùng
[ak:agentkit](../engineer/skills/agentkit) với outcome, constraint và authority
boundary. Khi route đã rõ, hãy gọi thẳng Skill sở hữu bước đó.

## Gọi từng bước

Claude Code và Cursor dùng `/ak:<skill>`. Codex dùng `$ak:<skill>` khi Skill đó
có trên Codex adapter.

```text
/ak:plan --hard "Thêm offline draft recovery; giữ document format; dừng trước implementation"
```

```text
$ak:plan --hard "Thêm offline draft recovery; giữ document format; dừng trước implementation"
```

Đừng dán cả chuỗi thành một prompt. Review output của từng bước rồi chuyển
artifact đã duyệt và constraint còn lại cho Skill tiếp theo.

## Chuyển handoff thực dụng

Dùng contract gọn này giữa các bước:

```text
Goal và observable outcome:
Scope và non-goal đã duyệt:
Evidence và decision:
Artifact đã tạo (path hoặc link):
Check đã pass và fail:
Open risk hoặc question:
Authority cấp cho bước tiếp theo:
Gate tiếp theo và stop condition:
```

Dùng Engineer [ak:handoff](../engineer/skills/handoff) hoặc Marketing
[ak:handoff](../marketing/skills/handoff) khi session, owner, runtime hoặc Kit
khác tiếp tục công việc.

## Phân biệt `ak:advise` và `--advice`

| Surface | Dùng khi | Không làm gì |
| --- | --- | --- |
| [ak:advise](../engineer/skills/advise) | Interview và reframe bài toán mơ hồ trước planning | Không implement hoặc approve công việc. |
| `--advice` trên workflow Skill hỗ trợ | Thêm advisory checkpoint trong brainstorm, plan, cook, fix hoặc vibe | Không bỏ review, safety hay authority gate. |

Với feature ảnh hưởng lớn, một chuỗi có advice thực dụng là:

```text
/ak:advise "Reframe bài toán và xác định decision cần chốt"
/ak:plan --hard "<accepted outcome>" --advice
# Review plan đã tạo.
/ak:cook @<plan-path> --tdd --advice
/ak:test
/ak:code-review --pending
```

Bỏ standalone advisory interview khi requirement đã rõ. Chỉ dùng `--advice`
cho rủi ro cao hơn hoặc decision khó, không stack vào mọi edit nhỏ.

## Tránh lỗi Workflow phổ biến

| Tránh | Nên làm |
| --- | --- |
| Chuỗi năm Skill cho edit nhỏ | Một request `ak:cook --fast` với acceptance check rõ |
| Bắt đầu implement khi plan còn decision chưa giải quyết | Giải quyết hoặc defer rõ decision rồi duyệt plan |
| Coi test lỗi là quyền làm yếu criteria | Trả evidence về bước implementation hoặc fix |
| Chạy `ak:ship` trước review và test | Hoàn tất review/verification gate trước |
| Route tới Skill không có | Kiểm tra Kit inventory hoặc dùng `ak:agentkit`/`ak:find-skills` |
| Tiếp tục sau cùng một failure hai lần | Escalate sang debug tập trung với evidence đã capture |

Tiếp tục từ gate lỗi với evidence mới. Chỉ restart toàn bộ workflow khi outcome,
hướng chính hoặc acceptance criteria đã thay đổi.
