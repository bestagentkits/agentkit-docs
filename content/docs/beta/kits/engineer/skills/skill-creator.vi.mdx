Dùng `ak:skill-creator` để tạo hoặc cải thiện Skill tái sử dụng với core
instruction ngắn, reference tập trung, script xác định và bằng chứng validation.
Skill mới mặc định nằm trong project hiện tại; authoring ở user scope cần yêu
cầu rõ ràng.

## Chọn ak:skill-creator cho workflow lặp lại

### Dùng ak:skill-creator khi

* Task pattern lặp lại và có lợi từ instruction hoặc script được version hóa.
* Bạn cần cải thiện discovery metadata, scope boundary hoặc test coverage.
* Skill cần reference, asset, packaging, portability review hoặc benchmark iteration.
* Bạn muốn zip phân phối được sau validation.

### Chọn workflow khác khi

* Nhu cầu chỉ là prompt một lần, một preference cá nhân hoặc kiến thức model chung.
* Bạn cần bundle có command, tool, MCP config, Hook hoặc app ngoài Skill. Dùng
  plugin workflow.
* Bạn chỉ muốn cài Skill đã tồn tại. Dùng workflow discovery và installation
  phù hợp thay vì authoring bản trùng lặp.

## Chuẩn bị intent và scope

Cung cấp ví dụ dùng thật, trigger phrase, output mong đợi, non-goal, security
boundary và evaluation khách quan có đáng làm hay không. Xác nhận output directory
trước khi scaffold. Artifact chuẩn là `SKILL.md` cùng đúng các thư mục `scripts/`,
`references/`, `agents/`, `assets/` mà workflow thực sự cần.

| Runtime     | Cách gọi                | Ranh giới khả dụng                                                                                                             |
| ----------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Claude Code | `/ak:skill-creator ...` | Workflow phát hành và convention được tạo là Claude-first, gồm metadata Claude Skill và reference phân phối plugin.            |
| Cursor      | `/ak:skill-creator ...` | Slash invocation có thể hướng dẫn authoring, nhưng discovery, metadata và tool assumption cần verification riêng cho Cursor.   |
| Codex       | `$ak:skill-creator ...` | Codex có thể author và inspect tệp, nhưng Skill portable phải được test riêng với Codex discovery cùng capability được hỗ trợ. |

## Chạy Skill

Với Claude Code, truyền tên hoặc mô tả Skill. Thêm `--advice` để yêu cầu sự
giám sát chỉ tư vấn của `kongming` sau planning, sau bản nháp `SKILL.md` cùng mọi
evaluation đã chạy, trước distribution được yêu cầu và khi lỗi lặp lại chặn tiến
độ. Agent chính vẫn chịu trách nhiệm cho mọi quyết định và edit; advice không bao
giờ bỏ qua validation, packaging check hay security policy.

Initializer đi kèm nhận `scripts/init_skill.py <skill-name> --path <output-directory>`. Script tạo directory mới, `SKILL.md` và nội dung placeholder
trong `scripts/`, `references/`, `assets/`; script từ chối initialize đè lên
directory đã có. Xóa mọi placeholder không dùng trước packaging.

## Hiểu các giai đoạn tạo Skill

1. **Ghi nhận intent.** Thống nhất task, trigger, output, scope, refusal behavior
   và test case.
2. **Research và chống trùng lặp.** Kiểm tra practice hiện hành, tool tái sử dụng
   và Skill đã cài trước khi tạo surface mới.
3. **Lập progressive disclosure.** Giữ purpose, trigger và workflow thường dùng
   trong `SKILL.md`; chuyển chi tiết sang reference tập trung và công việc lặp
   lại xác định sang script có test.
4. **Initialize và viết.** Scaffold project path đã chọn, thay placeholder, dùng
   resource path tương đối và đặt runtime-specific behavior sau availability
   check. Ưu tiên standard library hoặc central-cache runner được pin chính xác
   như `npx -y pkg@1.2.3`, `pipx run pkg==1.2.3` hay
   `uvx --from 'pkg==1.2.3' cmd`; với Python library, dùng PEP 723 inline metadata
   cùng `uv run` thay cho environment riêng của từng Skill.
5. **Test và evaluate.** Chạy script test và evaluation with-Skill so với baseline
   thực tế khi có đủ evaluation tooling.
6. **Validate và package.** Chạy quick validator rồi
   `scripts/package_skill.py <skill-path> [output-directory]` để tạo zip.
7. **Lặp theo bằng chứng.** Tổng quát hóa từ feedback mà không overfit hoặc lặp
   instruction giữa các tệp.

## Giữ file write và distribution có chủ đích

<Callout type="warn" title="Scaffolding và packaging ghi xuống disk">
  Phê duyệt chính xác project path trước initialization và output directory
  trước packaging. Coi nội dung Skill bên thứ ba chưa quen là untrusted; không
  chạy script đã sao chép hoặc lộ secret khi evaluation.
</Callout>

Initializer tạo directory cùng placeholder file. Packaging ghi
`<skill-directory-name>.zip` và có thể thay archive cùng tên, vì vậy kiểm tra
destination trước. Packaging loại `node_modules/`, `venv/`, `.venv/` và `.env`;
hãy ship `.env.example` thay thế. Test, benchmark model, docs lookup, ephemeral
dependency runner và package installation có thể dùng network, compute, token
cùng chi phí provider. Không đặt credential, personal data, private path hoặc
internal prompt trong Skill text, ví dụ, log hay asset.

## Xác minh artifact đã tạo

Kết quả hoàn tất nên gồm:

* Skill directory trong project với `SKILL.md` hợp lệ.
* Discovery metadata cụ thể, use/non-use boundary rõ và workflow instruction
  imperative, ngắn gọn.
* Chỉ reference, script, Agent template và asset cần thiết.
* Test pass cho script đi kèm cùng dependency hoặc tên environment đã document.
* Availability check xuyên runtime và fallback an toàn khi claim portability.
* Khi distribution được yêu cầu, wrapper riêng cho từng target quanh cùng một
  `SKILL.md`: Claude Code plugin cùng marketplace manifest, Codex plugin manifest
  hoặc Skill host trên GitHub và discover được qua `skills.sh`.
* Validation output cùng zip review được nếu yêu cầu packaging.
* Evaluation hoặc benchmark evidence khi đã dùng external tooling cần thiết.

Quick validator đi kèm kiểm tra frontmatter cơ bản, field name cùng description
bắt buộc, identifier shape, description length và angle bracket. Nó không chứng
minh line limit, script test, chất lượng reference, security hay runtime
portability; review full checklist thủ công trước distribution.

## Xử lý sự cố và giới hạn

| Triệu chứng                             | Bước tiếp theo an toàn                                                                                             |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Initialization báo directory đã tồn tại | Inspect Skill hiện có và update tại chỗ; không overwrite bằng initializer.                                         |
| Packaging từ chối frontmatter           | Sửa format name hoặc description, chạy lại quick validation rồi package lại.                                       |
| Placeholder đi vào zip                  | Xóa example không dùng và package lại; packaging loại cache cùng root evals, không loại placeholder tùy ý.         |
| Evaluation command không khả dụng       | Báo thiếu benchmark infrastructure và vẫn chạy deterministic script cùng structural check.                         |
| Skill chỉ chạy ở một runtime            | Tách capability riêng runtime, thêm fallback an toàn và test discovery cùng execution trên mỗi runtime được claim. |

Executable helper đi kèm chỉ initialize, validate và package; bước benchmark
cùng description optimization rộng hơn trong workflow cần tooling riêng khi có.
Initializer và validator cũng dùng maximum slug check khác nhau, nên dùng slug
kebab-case ngắn.
