Dùng `ak:page-builder` để tích hợp page builder động vào project hiện tại, dùng
đúng stack, component và design system của project đó. Agent là operator chính.
Người vẫn có thể tùy biến trang qua editor accessible, responsive và thân thiện
với cảm ứng. Skill giao code chạy được, interface đã xác minh, và Skill operator
riêng của project được tạo qua `ak:skill-creator` đã cài.

`setup`, `update` và `operate` là argument của Skill, không phải subcommand CLI
`ak`.

## Chọn ak:page-builder cho hệ thống composition tái sử dụng

### Dùng ak:page-builder khi

- Bạn cần hệ thống composition trang tái sử dụng, đăng ký component, hoặc
  draft, preview, publishing và vận hành bằng agent trên builder hiện có.
- Bạn đang mở rộng builder với block, binding, layout hoặc contract giao diện
  mới.
- Thay đổi trang thường xuyên phải đi qua Skill operator của project, Skill đó
  chưa có, nên cần operate path của Skill này.

### Chọn workflow khác khi

- Request là thiết kế trang một lần. Dùng Skill design hoặc frontend phù hợp.
- Bạn chỉ cần wrapper CLI hoặc MCP generic quanh API hiện có. Dùng
  [`ak:mcp-builder`](./mcp-builder) hoặc [`ak:agentize`](./agentize).
- Bạn cần kế hoạch implementation trước khi đụng builder. Dùng
  [`ak:plan`](./plan), rồi quay lại đây.
- Bạn cần xác minh độc lập builder đã giao. Dùng [`ak:test`](./test).

## Chuẩn bị project và ranh giới thẩm quyền

Trước khi bắt đầu:

- Hoàn tất [Làm quen](../../../getting-started/onboarding) và xác nhận Engineer
  Kit đã được cài cho runtime và scope bạn đang dùng.
- Mở project có component và design system mà builder phải tái sử dụng.
- Nêu rõ draft, shared preview, publication, MCP hoặc HTTP surface có nằm trong
  scope hay không.
- Giữ publication, ghi production và gọi provider có credential sau phê duyệt
  rõ ràng.

| Runtime | Invocation | Ranh giới availability |
| --- | --- | --- |
| Claude Code | `/ak:page-builder ...` | Chạy như Engineer Skill đã cài, delivery native hoặc plugin tường minh. |
| Cursor | `/ak:page-builder ...` | Dùng spelling slash đã được người dùng xác minh; không thiết lập tool parity rộng hơn. |
| Codex | `$ak:page-builder ...` | Dùng discovery native của Codex; không suy ra parity cho mọi thành phần runtime Engineer. |

Suy ra `setup`, `update` hoặc `operate` từ request và project hiện có; argument
tường minh thắng. Tái sử dụng outcome, ràng buộc, non-goal và acceptance criteria
đã chấp nhận. Đọc repository trước khi hỏi lựa chọn mà source đã trả lời được.

<Callout type="info" title="Phạm vi mặc định khi tạo builder mới">
  Builder mới gồm khám phá và đăng ký component, props và binding cấu hình được,
  kéo-thả với kích thước widget nhỏ/vừa/lớn thích ứng, draft, shared preview,
  publication và giao diện agent. Đừng bịa product surface riêng mà stack project
  không hỗ trợ.
</Callout>

## Xác minh kết quả

- Builder dùng component hiện có của project, không tạo design system song song.
- Preview và publication là path tường minh và có cổng kiểm soát.
- Skill operator của project tồn tại, hoặc operate path được ghi là fallback tạm.
- Test hoặc kiểm tra interface phủ các contract đã chấp nhận.

Tiếp tục với [`ak:test`](./test) để xác minh độc lập và
[`ak:skill-creator`](./skill-creator) nếu Skill operator vẫn cần được author.
