title: Choose an Engineer Skill
description: Start from a software-delivery outcome, compare focused Engineer workflows, and open the Skill guide that matches the work.
---

Engineer Skills are outcome-led workflows for work such as planning a change,
implementing it, investigating a failure, or preparing a delivery. Start with
the outcome you need, then read that Skill's guide before invoking it. The guide
defines its inputs, review gates, runtime notes, and authority boundaries.

## Invoke a Skill

Claude Code and Cursor use the slash form; Codex uses the dollar-prefixed form
for Skills that its adapter projects. For example:

```text
/ak:brainstorm "Compare safe rollout approaches for this API change"
```

```text
$ak:brainstorm "Compare safe rollout approaches for this API change"
```

Replace the Skill name and request with the workflow you choose. Do not assume
that every runtime projects the same Agents, Hooks, or provider tools; check the
individual guide and [Runtime adapters](../../../concepts/runtime-adapters).

The Codex projection includes [`ak:team`](./team) as `$ak:team`. Discovery does
not guarantee that the current runtime exposes the complete live team lifecycle;
the workflow must stop rather than substitute ordinary subagents when required
creation, shared-work, messaging, waiting, shutdown, or cleanup capabilities are
unavailable.

## Start here

| Outcome | Suggested path |
| --- | --- |
| Turn incomplete intent into an implementation direction | Start with [`ak:brainstorm`](./brainstorm), then use [`ak:plan`](./plan) after the direction is settled. |
| Implement a clear task or approved plan | Use [`ak:cook`](./cook) and keep its review, test, and authority gates explicit. |
| Investigate and repair a concrete failure | Use [`ak:debug`](./debug) to establish the cause, [`ak:fix`](./fix) for a bounded repair, and [`ak:test`](./test) for independent validation. |
| Review and deliver completed work | Use [`ak:code-review`](./code-review) for production-risk review, then choose [`ak:ship`](./ship) only when the branch is ready for its delivery workflow. |

## Chain Skills into a workflow

Each Skill invocation is a separate, reviewable workflow. Carry the prior
Skill's decisions, evidence, artifacts, and unresolved questions into the next
request. Do not treat a suggested chain as authority to skip a gate, publish,
deploy, spend, or make another external change. Use [`ak:handoff`](./handoff)
when the chain continues in another session or Kit.

| Goal | Suggested chain |
| --- | --- |
| Take an unclear feature through delivery | [`ak:help`](./help) → [`ak:brainstorm`](./brainstorm) → [`ak:scout`](./scout) or [`ak:research`](./research) → [`ak:plan`](./plan) → [`ak:cook`](./cook) → [`ak:test`](./test) → [`ak:code-review`](./code-review) → [`ak:ship`](./ship) |
| Diagnose and repair a failure | [`ak:debug`](./debug) → [`ak:fix`](./fix) → [`ak:test`](./test) → [`ak:code-review`](./code-review) |
| Implement and verify an interface | [`ak:frontend-design`](./frontend-design) → [`ak:frontend-development`](./frontend-development) → [`ak:web-testing`](./web-testing) → [`ak:code-review`](./code-review) |
| Review a security finding before changing code | [`ak:security-scan`](./security-scan) → [`ak:security`](./security) → [`ak:plan`](./plan) → [`ak:cook`](./cook) → [`ak:test`](./test) |
| Deliver a launch request across Kits | Marketing [`ak:launch-strategy`](../../marketing/skills/launch-strategy) → Marketing [`ak:handoff`](../../marketing/skills/handoff) → Engineer [`ak:plan`](./plan) → [`ak:cook`](./cook) → [`ak:test`](./test) → Engineer [`ak:handoff`](./handoff) back to Marketing |

Continue with a detailed guide:

- [Feature delivery from discovery through shipping](./plan#run-a-feature-delivery-workflow)
- [Evidence-led bug diagnosis and repair](./debug#run-a-bug-repair-workflow)
- [UI design, implementation, browser verification, and review](./frontend-development#run-a-ui-delivery-workflow)
- [Cross-Kit product-launch handoff](./handoff#run-a-cross-kit-product-launch-handoff)

Stop the chain when an input is missing, a review rejects the result, or the
next step needs authority you do not have. Resume from the failed prerequisite;
do not silently continue with assumptions.

## Choose by outcome

### Frame and plan work

- [`ak:ask`](./ask) answers a focused technical question from current project
  evidence without starting implementation.
- [`ak:brainstorm`](./brainstorm) compares viable approaches and produces a
  bounded direction.
- [`ak:research`](./research) gathers current primary evidence for a technical
  question and preserves uncertainty.
- [`ak:plan`](./plan) produces a phased implementation roadmap with risks,
  dependencies, and completion checks.
- [`ak:issue-to-plan`](./issue-to-plan) audits a GitHub issue against the
  repository and stops at its decision gate before implementation.

### Build systems

- [`ak:cook`](./cook) implements a clear task or approved plan with testing and
  review in the workflow.
- [`ak:frontend-development`](./frontend-development) handles scoped React and
  TypeScript interface work using the project's existing conventions.
- [`ak:backend-development`](./backend-development) designs and verifies a
  bounded backend, API, or data-access change.
- [`ak:databases`](./databases) covers data structures, query behavior, and
  guarded migration or administration preparation.
- [`ak:devops`](./devops) prepares and verifies infrastructure, CI/CD, or GitOps
  work behind deployment and deletion gates.

### Diagnose and validate

- [`ak:debug`](./debug) builds an evidence chain to a root cause.
- [`ak:fix`](./fix) implements the smallest repair aligned with a proven cause.
- [`ak:test`](./test) runs code or UI validation and reports failures without
  starting fixes.
- [`ak:code-review`](./code-review) reviews a diff, pull request, commit,
  workspace, or codebase for production risk.
- [`ak:security-scan`](./security-scan) performs a read-only scan for secrets,
  dependency issues, and code patterns, then verifies likely matches.

### Design and explain

- [`ak:frontend-design`](./frontend-design) turns a brief or visual reference
  into an implemented interface with visual and accessibility gates.
- [`ak:ui-ux-pro-max`](./ui-ux-pro-max) develops bundled UI recommendations and
  persists approved design rules.
- [`ak:docs`](./docs) creates, reconciles, or summarizes the smallest useful
  project documentation route.
- [`ak:mermaidjs-v11`](./mermaidjs-v11) authors and verifies Mermaid v11
  diagrams for systems, processes, data, timelines, or journeys.
- [`ak:preview`](./preview) opens existing content or creates visual
  explanations, reviews, diagrams, slides, and recaps.
- [`ak:explain`](./explain) builds a grounded Markdown or HTML explanation of a
  topic, with optional `--eli5` wording.

### Deliver and preserve work

- [`ak:git`](./git) stages, commits, pushes, opens pull requests, or merges
  through explicit Git safety gates.
- [`ak:deploy`](./deploy) selects a supported host, deploys with explicit
  provider authority, verifies the URL, and records rollback guidance.
- [`ak:ship`](./ship) runs release gates and prepares a completed branch for a
  pull request.
- [`ak:handoff`](./handoff) records goals, decisions, evidence, blockers, and
  open state for a fresh session.
- [`ak:worktree`](./worktree) creates and audits isolated Git worktrees, with
  cleanup separated behind review.

### Extend the toolchain

- [`ak:use-mcp`](./use-mcp) discovers MCP tools, inspects their schemas, and
  keeps external effects controlled.
- [`ak:mcp-builder`](./mcp-builder) researches an API, designs agent-centered
  tools, implements an MCP server, and verifies it.
- [`ak:skill-creator`](./skill-creator) scopes, scaffolds, validates, evaluates,
  and packages a reusable Skill.
- [`ak:find-skills`](./find-skills) routes to an installed Skill or searches for
  a reviewed external package with approval before installation.
- [`ak:agent-browser`](./agent-browser) drives a local or cloud browser with
  explicit session boundaries and reviewable artifacts.

## Keep the Kit boundary visible

Some names, including `ak:ask`, `ak:plan`, `ak:cook`, and `ak:preview`, also
appear in Marketing Kit. A shared name does not mean the two Kits ship the same
workflow. Use the guide under the Kit you installed and keep that Kit's inputs,
gates, and runtime notes attached to the task.

Skills are only one layer of Engineer Kit. Review [Engineer
Agents](../agents) for specialist roles, [Hooks and runtime](../hooks) for
projected automation, and [Lifecycle and recovery](../lifecycle) for refresh,
uninstall, and ownership behavior. Use [Installing
kits](../../../guides/installing-kits) to choose target, scope, delivery mode,
and installed Skill selection, or return to the [Engineer Kit
overview](../../engineer).
