Dùng `ak:orchestrate` khi một outcome hưởng lợi từ staged dependency, parallel
work, runtime diversity hoặc arbiter độc lập. Mỗi worker là một session độc lập,
có thể resume, của runtime bạn đang dùng; runtime khác chỉ tham gia khi bạn
opt-in. Skill xác minh từng runtime cùng
control tại thời điểm chạy, isolate writer rủi ro, capture evidence có giới hạn
và từ chối đánh dấu công việc chưa được xác minh là hoàn tất. Skill sở hữu
routing và judgment; `ak orchestrate` sở hữu plan state xác định, giám sát
process và evidence quan sát được.

## Chọn ak:orchestrate cho job graph

### Dùng ak:orchestrate khi

- Nhiều job độc lập có thể chạy parallel với ownership riêng.
- Job sau phụ thuộc artifact hoặc check rõ từ job trước.
- Bạn cần route research, implementation, test và review theo capability cùng
  risk.
- Lần chạy dài cần durable state và resume behavior có giới hạn.
- Independent judgment pass nên hòa giải output mâu thuẫn.

### Chọn workflow khác khi

- Một agent có thể hoàn tất task mà không cần fan-out hay arbitration hữu ích.
- Teammate cần thảo luận trực tiếp liên tục và shared multi-session state. Dùng
  `ak:team` khi runtime hiện tại hỗ trợ.
- Bạn chỉ cần code map read-only nhanh. Dùng `ak:scout`.
- Bạn có một implementation plan đã chấp nhận. Dùng `ak:cook` trừ khi runtime
  diversity hoặc isolation là quan trọng.

## Chuẩn bị workspace và runtime

Trước khi bắt đầu:

- Hoàn thành [Làm quen](../../../getting-started/onboarding) và xác nhận
  Engineer Kit đã được cài cho runtime cùng scope đang dùng.
- Dùng Git repository khi có job cần worktree isolation.
- Xác định outcome, constraint, non-goal, acceptance evidence, allowed file và
  external-effect boundary.
- Bảo đảm từng candidate CLI runtime đã được cài và authenticated. Discovery
  không install, update, login hay đổi configuration.
- Không đưa credential và private data không liên quan vào prompt hay capture.

| Runtime | Cách gọi | Ranh giới khả dụng |
| --- | --- | --- |
| Claude Code | `/ak:orchestrate ...` | Skill khởi chạy session Claude Code độc lập cùng headless CLI đã xác minh của chính nó. Route và control chính xác được khám phá trong lần chạy này. |
| Cursor | `/ak:orchestrate ...` | Slash invocation theo cách gọi Engineer Skill do người dùng xác minh. Session chỉ đủ điều kiện khi surface Cursor hiện tại chứng minh dispatch cùng control cần thiết. |
| Codex | `$ak:orchestrate ...` | Native Skill discovery được hỗ trợ. Session cần surface cung cấp khả năng tạo session; nếu không, dùng verified Codex CLI route, runtime đã opt-in, hoặc trả kết quả blocked. |

Mặc định, candidate là session của runtime gọi Skill cùng headless CLI được giám
sát của chính runtime đó. Runtime khác chỉ được xét qua các opt-in trong
[Dispatch session trước](#dispatch-session-trước).

## Kiểm tra hỗ trợ nền tảng

`ak:orchestrate` không chỉ dành cho macOS. Chỉ việc giám sát process bên ngoài
bởi `ak orchestrate` mới yêu cầu Darwin.

| Capability | Darwin | Linux, Windows, nền tảng khác |
| --- | --- | --- |
| `probe`, `prepare`, `advance`, `accept`, `plan-status` | Có | Có |
| `events`, `output`, `diagnose` | Có | Có, nhưng chỉ cho run được ghi trên host có giám sát |
| Job `runtime: internal` (session của runtime hiện tại) | Có, khi live runtime khởi chạy được session | Có, khi live runtime khởi chạy được session |
| Job CLI và Pi được `ak orchestrate` giám sát | Có | Không: `advance` chuyển job sang `blocked` với error class `unsupported_platform` và thoát với mã `1`; job internal trong cùng run vẫn được dispatch |
| Check `verification:` thực thi được trong job spec | Có | Không: `accept` chuyển job sang `blocked` với error class `unsupported_platform`; hãy chuẩn bị run mới không có verification dạng lệnh |
| `start`, `status`, `resume`, `stop` cho supervisor run | Có | Không: help của từng lệnh nêu exit code cho nền tảng không được hỗ trợ |

Trên host không phải Darwin, Skill route job đủ điều kiện qua
session `runtime: internal`. Job cần process CLI hoặc Pi được giám sát được giữ ngoài
spec đã prepare và được báo blocked kèm lý do nền tảng. `verification:` do bạn
hoặc spec được cung cấp khai báo là acceptance constraint: job đó bị block, không
bao giờ được chuyển đổi. Chỉ trong spec do Skill tự soạn, Skill mới liệt kê check
command trong `checks:`, chạy chúng trong harness và ghi nhận là
harness-attested. Skill không bao giờ bypass supervision gate, launch process
không được giám sát để thay thế, hay advance lại job đã bị kẹt ở gate đó. Khi
cũng không có session nào của runtime hiện tại đủ điều kiện, lần chạy block và nêu lý do.

| Input hoặc tùy chọn | Hành vi | Ranh giới |
| --- | --- | --- |
| Free-form task | Chuyển accepted outcome thành durable job graph trước dispatch | Graph được tạo vẫn phải qua validation cùng safety gate |
| Đường dẫn job spec | Dùng job, dependency, timeout, ownership, check và expected output rõ | Runtime, model, Agent cùng control pin vẫn chưa được xác minh đến live preflight |

| `--yes` | Chỉ mang approval cho đúng destructive hoặc external scope đã mô tả | Không cấp quyền rộng hơn cho credential, file, release hay deployment |
| `--resume <run-dir>` | Dùng lại successful output và redispatch interrupted work thành attempt mới | Route, authentication, control và approval được xác minh lại |

## Dispatch session trước

Mỗi worker chạy ngoài lượt của coordinator, dưới dạng session có native handle,
context, model và lifecycle riêng, hoặc process headless được giám sát. Session
của runtime hiện tại là `runtime: internal` trong job spec. Nested in-harness
subagent không phải worker.

- **Scope mặc định là runtime hiện tại.** Candidate là session của runtime bạn
  gọi Skill và CLI được giám sát của chính runtime đó.
- **Runtime khác cần opt-in.** Truyền `--cross-runtime`, cho job một chuỗi
  `fallback_runtime` trong spec, pin `runtime:`, hoặc nêu tên runtime trong yêu
  cầu (ví dụ "as pi sessions"). Mỗi cách là một opt-in tương đương cho runtime
  đó. Runtime được nêu tên mà thiếu hoặc chưa authenticated sẽ chạy onboarding
  như một bước setup hiển thị, rồi được probe lại.
- **Không khả dụng thì hiển thị rõ.** Khi runtime hiện tại không khởi chạy được
  session đủ điều kiện và không có candidate đã opt-in nào đủ điều kiện, job
  được báo `blocked` kèm probe evidence. Skill không bao giờ âm thầm mở rộng
  scope hay ghi đè pin runtime, model hoặc role-profile rõ ràng.
- **Permission fallback là route subagent duy nhất.** Khi runtime từ chối khởi
  chạy session vì coordinator thiếu quyền (standing policy hoặc permission mode,
  không phải prompt bạn đã từ chối), job có thể chạy như nested agent. Prompt
  của nó vẫn do bạn trả lời, writer R2 (isolated high-impact) vẫn có worktree riêng, job external hoặc
  destructive vẫn bị block, và job arbiter hay review, vốn cần độc lập mà subagent
  không chứng minh được, không bao giờ dùng route này. Report
  ghi `fallback: subagent`, evidence về lần từ chối và các đảm bảo bị giảm: không
  có resume độc lập, dùng chung quota và permission, timeout chỉ là accounting.
  Lỗi quota, budget, resource, thiếu runtime và crash không bao giờ fallback sang
  subagent.

Cache của `ak orchestrate probe` nằm ở `AGENTKIT_HOME/cache/orchestrate/probe`.
Lệnh được phân loại là read-only: chỉ chạy probe version và help, không bao giờ
cài hay authenticate runtime, và chỉ cập nhật cache đó. Xem
[`ak orchestrate probe`](../../../reference/cli/orchestrate/probe).

## Mô tả job rõ ràng

Mỗi job cần:

- **Intent:** Task class như scout, architecture, implementation, review,
  audit, security, test, documentation hoặc mechanical work.
- **Workspace:** Working directory chính xác trong authorized workspace.
- **Ownership:** Tệp được phép ghi hoặc read-only scope rõ ràng.
- **Dependencies:** Job phải thành công trước khi job này bắt đầu.
- **Expected output:** Report, diff, test result hoặc artifact có thể xác minh.
- **Checks:** Command hoặc evidence arbiter phải kiểm tra.
- **Risk:** Read-only, scoped write, isolated high-impact write hoặc
  external/destructive effect.
- **Bounds:** Timeout và runtime, model, Agent, tool hoặc budget constraint rõ.

Runtime hoặc model pin là constraint, không phải bằng chứng nó hiện diện hay an
toàn. Nếu live candidate không đạt capability cùng control floor, job block
thay vì âm thầm hạ thấp yêu cầu.

## Hiểu workflow

1. **Skill chấp nhận contract.** Skill xác nhận outcome, boundary, expected
   evidence, dependency và external intent.
2. **Skill xây và validate graph.** Skill reject duplicate ID, dependency
   cycle, working directory không an toàn, bound còn thiếu và parallel write
   overlap.
3. **Skill kiểm kê live candidate.** Skill bắt đầu từ runtime hiện tại, thêm
   runtime đã opt-in, và xác minh executable hoặc session availability, authentication readiness, command shape hiện tại, selectable
   route, permission, isolation, timeout, capture, resume behavior và host
   limitation.
4. **Skill phân loại capability và risk.** Read-only extraction,
   implementation và independent judgment có minimum floor khác nhau. Safety
   control được lọc trước cost hay latency.
5. **Skill áp dụng approval gate.** Destructive, release, deployment, deletion,
   credentialed cùng external effect khác cần approval chính xác và recovery
   plan.
6. **Skill dispatch theo stage.** Independent job chỉ chạy cùng nhau trong
   `concurrency:` mà Skill cho phép dựa trên quota và host headroom (xem
   [Định cỡ parallelism và phục hồi lỗi](#định-cỡ-parallelism-và-phục-hồi-lỗi)).
   Parallel writer dùng worktree riêng và ownership không chồng lấn.
7. **Skill capture durable evidence.** State transition, bounded output,
   artifact, error, duration và usage được báo đáng tin vẫn sẵn sàng cho
   diagnosis cùng resume. Process CLI và Pi được giám sát yêu cầu Darwin; trên
   host khác, session job đủ điều kiện tiếp tục qua cùng vòng `prepare`,
   `advance` và `accept`, như mô tả trong [Kiểm tra hỗ trợ nền tảng](#kiểm-tra-hỗ-trợ-nền-tảng).
8. **Skill chạy arbiter.** Một session riêng trên model judgment mạnh nhất đã
   xác minh trực tiếp kiểm tra expected output,
   contradiction, safety gap, failed check, unsupported claim và unresolved
   question.
9. **Skill report mà không tự integration.** Worktree diff vẫn chờ review;
   merge hoặc cherry-pick là action riêng.

## Định cỡ parallelism và phục hồi lỗi

**Admission.** Skill định cỡ `concurrency:` của spec từ evidence, không dùng số
worker cố định. Skill đọc usage window do provider báo bằng `ak usage limits`,
giữ headroom dưới giới hạn đã báo (runtime chung một upstream account dùng chung
một pool), và kiểm tra CPU, memory, disk của host. Check nặng như full preflight,
browser suite và build chạy tuần tự; scout nhẹ chạy parallel. Quota hoặc cost
không rõ không có nghĩa là không giới hạn: Skill admit tuần tự hoặc hỏi policy.
Khi bị áp lực quota, cost hoặc tài nguyên host, Skill ngừng gọi `advance` cho việc mới và settle mọi job
đã được giao, không dừng process mà run không khởi chạy. Lý do giảm concurrency
được ghi trong report.

**Failure class.** Mỗi attempt lỗi hoặc kẹt được phân loại trước khi hành động.
Coordinator class nằm trong `status.json` và report, còn `error_class` đã map
của plan engine nằm trong receipt của `accept` (ví dụ `rate_limited` map thành
`rate-limit`, và lỗi transient map thành `timeout` khi hết bound):

| Class | Ví dụ | Retry |
| --- | --- | --- |
| `transient`, `rate_limited` | Mất mạng ngắn, timeout khi writer đã xác nhận dừng, giới hạn provider có thể retry | Chỉ qua policy `retry:` của job |
| `quota_exhausted`, `budget_exhausted` | Hết usage window, chạm cost ceiling | Không; chờ reset hoặc báo blocker |
| `runtime_missing`, `auth_unavailable`, `model_unavailable`, `unsupported_capability` | Runtime thiếu hoặc chưa authenticated, model không có trong live set | Không |
| `host_resource_pressure` | Thiếu memory hoặc disk | Không |
| `process_crash`, `lost_handle`, `message_unavailable` | Worker chết hoặc không resolve được session | Không, đến khi chứng minh writer cũ đã dừng |
| `verification_failure`, `merge_conflict`, `task_spec_error` | Check fail, worktree xung đột | Không |
| `permission_denied`, `security_risk`, `external_effect_requires_approval` | Action bị từ chối, input không an toàn, effect chưa approval | Không; dừng và báo approval boundary |

**Fallback ladder.** Skill chỉ leo đến bậc cần thiết, trong giới hạn thời gian và
cost của run. Run đã prepare cố định runtime, model và invocation của từng job,
nên job lỗi không bao giờ bị re-route trong cùng run.

1. Reattach vào attempt hoặc session gốc khi handle và ownership đã được chứng
   minh.
2. Retry trên cùng route qua policy `retry:` của job, sau khi writer trước đã
   settle.
3. Thích nghi trong runtime hiện tại: giảm `concurrency:` hoặc chờ usage window
   với job chưa dispatch, hoặc prepare run directory mới với model hay effort
   live khác.
4. Cross-runtime, chỉ khi đã opt-in, bằng cách prepare run directory mới route
   job tới candidate vừa probe. Model identifier và flag không bao giờ được mang
   giữa các runtime.
5. Pause, replan hoặc block kèm blocker hay yêu cầu approval có thể hành động.

Không bậc nào nâng permission, bỏ check, ignore pin hay ra ngoài authorized root.

## Hiểu model của arbiter và review

Job arbiter, advisor, review, audit và security resolve model mạnh nhất mà active
route thực sự dùng được, và arbiter chạy trong session mới, riêng biệt. Skill bắt đầu từ
các model live runtime liệt kê là selectable cho account của bạn, loại model mà
bạn, project hoặc tổ chức không cho phép, rồi áp dụng thứ tự ưu tiên: pin rõ
ràng, rồi model policy, rồi candidate mạnh nhất còn lại theo catalog rank của
runtime. Metric của các run trước không bao giờ đổi thứ hạng này. Khi route không
chọn được model, model mặc định được dùng và report nêu rõ không có override.

Report công bố runtime và model thực sự phục vụ từng judgment job, cùng lý do
chọn và lý do fallback nếu có. Reviewer khác model family được ưu tiên khi live
evidence chứng minh được; fallback cùng family được công bố. Arbiter Pi chỉ được
tính là độc lập khi model family đã resolve khác.

## So sánh shadow tùy chọn

Routing áp dụng mọi mức sàn về capability và rủi ro cùng các lựa chọn bạn đã
ghim trước. Luồng mặc định không bao giờ gọi lệnh semantic hay đọc cấu hình
provider. Chỉ với thử nghiệm do bạn yêu cầu, hoặc khi context đã có sẵn một
opt-in đáng tin cậy từ bạn, Skill mới có thể chạy [`ak eval
decision`](../../../reference/cli/eval/decision). Skill chỉ cung cấp các dữ kiện
ngắn gọn (task, tác động, mức độ quan trọng và việc có chạy song song hay không)
cùng phân loại rủi ro và capability hiện có, không bao giờ gửi prompt của job,
log hay credential.

Lệnh kiểm tra consent và chỉ tạo phép so sánh shadow. Lệnh không thể đổi runtime
hoặc model đã chọn, hạ kiểm soát rủi ro hay mức sàn capability, cấp phê duyệt,
hoặc mở khóa một route không khả dụng. Skill theo kết quả routing hiện có mỗi
khi có bất đồng hoặc provider gặp lỗi.

## Giữ quyền phê duyệt và an toàn ở bạn

<Callout type="warn" title="Worktree isolate collision, không phải sandbox">
  Worktree riêng giữ concurrent Git edit tách biệt. Chúng không chứa process,
  network access, credential hay write ngoài worktree. Job vẫn cần runtime
  control đáp ứng risk tier.
</Callout>

Mỗi CLI process có timeout do coordinator sở hữu. Session timeout chỉ là
accounting limit trừ khi live harness chứng minh cancellation; Skill không được
launch writer khác vào cùng ownership khi timed-out Agent có thể vẫn chạy.

Permission bypass mặc định tắt. Headless runtime auto-approve write bị giới hạn
ở read/report work hoặc treatment isolate mạnh hơn. Không job nào được đặt
token, cookie, private key, raw environment value hay secret argument vào
request hoặc capture.

## Xác minh kết quả

Một lần chạy hoàn tất nên cung cấp:

- Job graph đã validate với dependency, ownership, bound, expected output và
  check.
- Live runtime inventory cho candidate verified, constrained, unavailable và
  unverified mà không chứa secret value.
- Per-job status, resolved route, risk cùng capability classification,
  artifact, error, timeout và attempt.
- Failed hoặc interrupted evidence được giữ thay vì silent retry.
- Arbiter verdict kiểm tra mọi required artifact cùng contradiction.
- Final report nêu successful, failed và blocked job, check, worktree diff chờ
  integration cùng unresolved question.

Lần chạy chỉ thành công khi mọi required job thành công, check pass, claim có
evidence, contradiction được giải quyết và arbiter pass.

| Agent báo orchestrate cần macOS | Chỉ giám sát CLI bên ngoài mới cần Darwin. Skill route job qua session của runtime hiện tại; job cần CLI có giám sát được báo `blocked`. |
| Session không khởi chạy được và job `blocked` | Đọc probe evidence. Opt-in runtime khác bằng `--cross-runtime` hoặc chuỗi `fallback_runtime`, hoặc sửa session surface của runtime hiện tại. |
| Skill in cảnh báo `--internal` đã deprecated | Bỏ cờ này. Session của runtime hiện tại đã là mặc định. |
| Runtime thiếu hoặc chưa authenticated | Đánh giá fallback đã opt-in trong run directory mới qua cùng live gate, hoặc hoàn tất setup ngoài lần chạy rồi preflight lại. |
| Model hoặc flag bị reject | Quay lại live help hoặc official documentation hiện tại; không đoán hay mang identifier sang runtime khác. |
| Permission prompt xuất hiện | Dừng job và giải quyết approval boundary chính xác. Không retry với bypass. |
| Job timeout | Giữ bounded partial evidence, đánh dấu job failed và block dependent đến khi có recovery decision. |
| Parallel writer cần cùng tệp | Chạy tuần tự hoặc thiết kế lại ownership; worktree riêng không giải quyết integration conflict. |
| Lần chạy bị gián đoạn | Resume từ durable state, xác minh lại live route và chỉ chạy lại interrupted work cùng arbiter bắt buộc. |
| Arbiter fail | Xử lý missing artifact, failed check, contradiction hoặc unsupported claim trước integration. |
| Runtime không nhận diện Skill | Xác nhận target cùng scope, mở lại runtime session, rồi làm theo [Runtime không tìm thấy Skill hoặc Agent](../../../troubleshooting/runtime-cannot-find-skill-or-agent). |

So sánh `ak:team` cho live multi-session collaboration, hoặc tiếp tục với
[Engineer Kit](../../engineer) và
[Runtime adapter](../../../concepts/runtime-adapters).

## Biết các giới hạn hiện tại

- Runtime cùng model catalog, authentication, flag và safety control thay đổi;
  mỗi lần chạy phải xác minh trực tiếp.
- Session job có thể thiếu force cancellation, per-job sandboxing hoặc chọn
  model; mỗi khả năng được probe theo từng run. Subagent permission-fallback còn
  thiếu resume độc lập và dùng chung quota cùng permission của coordinator.
- Quota và resource admission là đánh giá của coordinator trên evidence quan sát
  được, không phải reservation được cưỡng chế.
- Job không chia sẻ implicit memory; dependency phải truyền explicit artifact.
- Worktree cần Git cùng disk headroom, và integration vẫn là action được review
  riêng.
- Usage cùng cost chỉ xuất hiện khi harness đã chọn báo đáng tin.
- Skill điều phối runtime hiện có; Skill không tạo daemon, dashboard, account
  pool hay provider adapter.
- Job CLI và Pi được giám sát, check `verification:` thực thi được và các lệnh
  supervisor `start`, `status`, `resume`, `stop` yêu cầu Darwin. Host khác chạy
  session job `runtime: internal` đủ điều kiện và block phần còn lại.
