Dùng `ak:predict` trước thay đổi lớn hoặc rủi ro để lộ sớm failure về
architecture, security, performance, user experience và assumption. Năm góc
nhìn chuyên gia phân tích proposal độc lập, tranh luận conflict có ý nghĩa và
tạo verdict có giới hạn cùng mitigation trước implementation.

## Chọn ak:predict khi proposal cần pre-analysis

### Dùng ak:predict khi

- Feature hoặc refactor có blast radius lớn hay thay đổi system architecture.
- Authentication, data exposure, latency, query volume hoặc accessibility có
  thể thay đổi đáng kể.
- Competing approach cần so sánh tập trung vào risk.
- Bạn muốn stress-test assumption trước khi đầu tư vào plan chi tiết.
- Proposed design cần điều kiện go, caution hoặc stop rõ ràng.

### Chọn workflow khác khi

- Thay đổi nhỏ, ít rủi ro hoặc đã được duyệt không còn design question. Dùng
  `ak:plan` hoặc `ak:cook` phù hợp.
- Bạn đang chẩn đoán bug hoặc failing test. Dùng workflow debug hay fix.
- Bạn cần khám phá relevant file trước. Dùng `ak:scout`.
- Bạn cần định nghĩa outcome hoặc explore product direction rộng. Dùng
  `ak:brainstorm`.
- Bạn cần implementation roadmap sau khi đã hiểu risk. Dùng `ak:plan`.

## Chuẩn bị project và runtime

Trước khi bắt đầu:

- Hoàn thành [Làm quen](../../../getting-started/onboarding) và xác nhận
  Engineer Kit đã được cài cho runtime cùng scope đang dùng.
- Mô tả proposed change, intended outcome cùng hệ thống hoặc người dùng bị ảnh
  hưởng.
- Nêu existing constraint, rejected alternative và assumption cần thử thách.
- Cung cấp file glob có giới hạn bằng `--files` khi current code evidence nên
  tham gia debate.
- Giữ tệp nhạy cảm hoặc không liên quan ngoài glob.

| Runtime | Cách gọi | Ranh giới khả dụng |
| --- | --- | --- |
| Claude Code | `/ak:predict ...` | Chạy như Engineer Skill đã cài trong native hoặc explicit plugin delivery. |
| Cursor | `/ak:predict ...` | Dùng slash spelling do người dùng xác minh cho Engineer Skill; parity rộng hơn chưa thiết lập. |
| Codex | `$ak:predict ...` | Dùng native Codex discovery; không suy ra parity cho mọi Engineer runtime component. |

Feature hoặc change proposal là bắt buộc. Tùy chọn refine evidence hoặc thêm
follow-on reasoning mode:

| Tùy chọn | Tác dụng | Phù hợp |
| --- | --- | --- |
| `--files <glob>` | Đọc matching relevant code trước debate | Claim architecture hoặc implementation phụ thuộc current project evidence |
| `--chain reason` | Thêm vòng generate, critique, synthesize và blind-judge refinement | Verdict CAUTION chứa subjective design hay architecture trade-off |
| `--chain probe` | Interrogate missing constraint và assumption đến khi không còn thông tin mới | CAUTION hoặc STOP do unclear requirement |

Chain mode thuộc một session `predict`; chúng không phải Skill standalone.

## Mô tả proposal rõ ràng

Input hữu ích cung cấp điều cụ thể cho cả năm góc nhìn:

- **Outcome:** proposed change cần đạt điều gì.
- **Scope:** user, data, interface, component và operation bị ảnh hưởng.
- **Constraints:** compatibility, security, latency, accessibility, budget hoặc
  deployment boundary.
- **Assumptions:** claim được tin là đúng nhưng chưa chứng minh.
- **Evidence:** relevant file, measurement, incident hoặc prototype.
- **Decision:** verdict cần unblock điều gì.

Với cross-device draft synchronization, nêu conflict behavior, offline
requirement, authentication boundary, current document compatibility, latency
target, recovery state và server component đã tồn tại chưa.

## Hiểu năm góc nhìn

| Góc nhìn | Quan tâm chính |
| --- | --- |
| Architect | Mức phù hợp design hiện tại, scalability, coupling và rework |
| Security | Abuse path, data exposure, authentication và authorization |
| Performance | Latency, memory, query, resource growth và bundle impact |
| UX | Khả năng hiểu, accessibility, mobile behavior và failure state |
| Devil's advocate | False assumption, alternative đơn giản hơn và chi phí của việc làm gì đó |

Đây là analytical perspective trong một workflow. Output là synthesis dựa trên
bằng chứng, không phải năm implementation được cấp quyền độc lập.

## Hiểu điều gì xảy ra trong một lần chạy

1. **Skill đọc proposal.** Skill ghi intended change, scope, assumption và
   expected decision.
2. **Skill đọc project evidence có giới hạn.** Khi có `--files`, Skill search
   matching area cho current behavior liên quan proposal.
3. **Mỗi góc nhìn phân tích độc lập.** Conclusion sớm được giữ tách biệt để một
   perspective không anchor các perspective khác.
4. **Skill xác định agreement.** Skill ghi concern hoặc strength được ít nhất
   bốn perspective chia sẻ.
5. **Skill đưa conflict ra rõ.** Skill so sánh view khác biệt đáng kể và xử lý
   theo impact thay vì chỉ majority.
6. **Skill tạo risk summary.** Risk nhận severity cùng mitigation cụ thể hoặc
   statement rõ chưa biết viable mitigation.
7. **Skill đưa verdict.** Skill trả GO, CAUTION hoặc STOP cùng recommendation
   theo thứ tự.
8. **Skill chạy chain tùy chọn.** `reason` refine subjective trade-off;
   `probe` thu missing constraint cùng assumption trước khi final report.

## Diễn giải verdict

| Verdict | Ý nghĩa | Phản hồi an toàn |
| --- | --- | --- |
| GO | Các góc nhìn đồng thuận và không tìm thấy critical unresolved risk trong evidence đã kiểm tra | Chuyển recommendation vào planning; vẫn verify implementation |
| CAUTION | Risk có vẻ quản lý được khi mitigation đã nêu trở thành gate rõ | Thêm mitigation cùng check vào plan trước implementation |
| STOP | Critical unresolved issue, incompatible design, unacceptable performance path hoặc false premise làm proposal không hợp lệ | Redesign, thu thêm evidence hoặc bỏ approach |

Chỉ một authentication bypass, data exposure, fundamental design
incompatibility, latency hay query explosion không thể giảm thiểu hoặc
premise-invalidating assumption cũng đủ tạo STOP.

## Giữ quyền phê duyệt và an toàn ở bạn

<Callout type="warn" title="Verdict là pre-analysis, không phải authorization">
  GO không phê duyệt code change hay chứng minh implementation sẽ secure, fast,
  accessible hoặc correct. Item CAUTION và STOP vẫn hiển thị đến khi workflow
  sau cung cấp bằng chứng giải quyết chúng.
</Callout>

Workflow theo source đọc proposal cùng project file có giới hạn tùy chọn.
Workflow không cần network access, paid provider, credential use, publication
hay deployment. Skill không nên sửa product code hoặc thực thi recommendation.

Giữ glob `--files` đủ hẹp để tránh material riêng tư không liên quan. Kết luận
security, performance và UX bị giới hạn bởi evidence được cung cấp; dùng
specialist review cùng test cho release decision. Đừng dùng chain mode để nói
vòng qua STOP trigger nếu không có evidence mới hoặc viable mitigation.

## Xác minh kết quả

Prediction report hoàn tất nên chứa:

- Verdict GO, CAUTION hoặc STOP.
- Agreement được các perspective chia sẻ.
- Conflict table hiển thị từng view cùng resolution.
- Risk summary với severity và mitigation.
- Ordered actionable recommendation.
- Evidence boundary cùng assumption vẫn chưa xác minh.
- Với `--chain reason`, refined trade-off decision.
- Với `--chain probe`, requirement mới tìm được cùng gap còn lại.

Report sẵn sàng cho planning khi mọi STOP trigger đã được giải quyết hoặc
proposal được redesign, và mọi CAUTION item trở thành constraint, acceptance
gate hoặc risk decision.

## Xử lý sự cố hoặc tiếp tục

| Triệu chứng | Bước tiếp theo an toàn |
| --- | --- |
| Report quá chung chung | Thêm affected interface, data, constraint, rejected alternative cùng glob `--files` hẹp. |
| Perspective bất đồng không có resolution | Hỏi impact cùng evidence nào quyết định resolution; high-risk conflict chưa xử lý phải còn CAUTION hoặc STOP. |
| Security hoặc performance claim thiếu evidence | Cung cấp current boundary hay measurement và chạy specialist review hoặc test trước khi coi claim đã giải quyết. |
| `--chain reason` tiếp tục refine câu chữ | Dừng khi decision không còn thay đổi và chuyển explicit trade-off vào planning. |
| `--chain probe` tìm missing requirement | Trả lời, cập nhật proposal và chạy lại verdict thay vì implementation quanh gap. |
| Runtime không nhận diện Skill | Xác nhận target cùng scope, mở runtime session mới, rồi làm theo [Runtime không tìm thấy Skill hoặc Agent](../../../troubleshooting/runtime-cannot-find-skill-or-agent). |

Đưa risk row cho `ak:scenario` để có scenario sâu hơn hoặc gắn recommendation
cùng mitigation vào `ak:plan`. Chỉ dùng `ak:cook` sau khi acceptance gate
tạo ra đã được duyệt.

## Biết các giới hạn hiện tại

- Report predict risk từ proposal cùng evidence đã kiểm tra; không forecast
  future change chưa biết hoặc bảo đảm outcome.
- `--files` không tự chứng minh runtime behavior, load limit hay exploitability.
- Năm perspective có thể lộ missing evidence nhưng không tạo ra evidence.
- Cách gọi Cursor bằng slash là bằng chứng do người dùng xác minh, không chứng
  minh runtime parity đầy đủ.
- Stable và beta package cùng persona, verdict rule và chain mode
  `ak:predict`. Thay đổi runtime ở beta không làm đổi workflow này.
